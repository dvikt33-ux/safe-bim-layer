# ArchiCAD Project Accelerator R03.1

## Запуск в Windows

Откройте PowerShell в распакованном каталоге APA или в корне интеграционной ветки. Для локальных функций достаточно 64-разрядного Python 3.11. Сборка испытана на 3.11.9.

```powershell
py -3.11 -m venv .venv-apa
$Apa = ".\.venv-apa\Scripts\python.exe"
& $Apa -m pip install -r requirements-apa.lock
& $Apa -m pip check
& $Apa -X utf8 -m apa doctor
& $Apa -X utf8 -m apa --help
```

Если `py -3.11` не находит интерпретатор, укажите полный путь к установленному `python.exe` в первой команде. `doctor` сверяет версии с `requirements-apa.lock` и показывает состояние окружения для локальных операций.

## Основные команды

```powershell
& $Apa -X utf8 -m apa catalog IFCGeometry --contracts
& $Apa -X utf8 -m apa template-check
& $Apa -X utf8 -m apa plan --intent examples/accelerator/building-shell.intent.json --output shell-plan.json
& $Apa -X utf8 -m apa exchange "C:\Models\example.ifc" --output ifc-report
& $Apa -X utf8 -m apa exchange "C:\Models\example.dxf" --output dxf-report
& $Apa -X utf8 -m apa exchange "C:\Models\example.pdf" --page 1 --output pdf-report
```

`plan` принимает существующие типизированные задания APA. Для оболочки выводит BIM Graph и маршруты `SceneWriter`. Для массового тиражирования выводит кандидатный граф, пока реальная регистрация команды не подтверждена. `exchange` сохраняет инвентаризацию и количества для IFC, предконтроль и инвентаризацию для DXF, векторную геометрию и PNG для страницы PDF. Используйте новые пути для выходных файлов и каталогов.

Для отдельного инструмента используйте `apa run-local ИМЯ_КОМАНДЫ --params параметры.json`. Контракт параметров показывает `catalog`. Для последовательности инструментов используйте `apa run-read-workflow --graph граф.json --output результат.json`. Граф принимает `after` и ссылки `$result` по JSON Pointer. Например, второй шаг может прочитать `/artifactPath` результата `AddOn.APAIFCArtifactsB2.IFCExtractElements` и экспортировать этот IFC-поднабор через `AddOn.APAIFCGeometryB3.IFCGeometryGLB`. Команды нативного API не допускаются в локальном графе.

`AddOn.APAArchitecturalSources.PDFPlanCrop` вырезает выбранную область листа. `HostedOpeningCandidates` получает из первого шага `/outputEvidence` и `/sourceSHA256` и выделяет повторяющиеся марки проёмов. Подготовленный список кандидатов сохраняет координаты PDF. Для перехода к массовому созданию проёмов нужны подтверждённые стены, типы, этажи и размеры из модели.

Действие «Сверить параметры строительного узла» читает закреплённый архив Details v2.12. `apa detail-review --detail-id <ID> --observation <диагностика.json> --output <новый JSON>` также повторно компилирует сохранённую предварительную балку через BIM Graph. Проверяются связь факта с выбранным узлом, единицы, сечение и контракт `CreateBeams`. Если диагностика содержит несколько подходящих балок, `--host-guid` задаёт конкретный хост. Отчёт сохраняет SHA диагностики и архива, уровень доказательства и открытые условия для создания, контакта, материала и сборки.

```powershell
$Dump = 'examples/model_dump_v1.sample.json'
@((Get-Content $Dump -Raw | ConvertFrom-Json).elements[0].guid) |
    ConvertTo-Json -AsArray | Set-Content -Encoding utf8 guids.json
& $Apa -X utf8 -m apa documentation --native-dump $Dump --guids guids.json --story 0 --output documents
```

Документация принимает исходный или нормализованный Model Dump V1 и явно перечисленные GUID. В `documentation.json` и CSV используется одна версия модели. Планы и разрезы, требующие чтения нативной графики, отмечают наличие соответствующих данных в исходнике.

Для здания, проверенного после повторного открытия, выберите «Выпустить ведомости по проверенной PLN» и укажите каталог задания. Команда `apa documentation --job <каталог задания> --output <новая папка>` сверяет сохранённую PLN, снимок, GUID и BREP, затем выбирает элементы по квитанции выполнения. Можно ограничить выпуск одним этажом через `--story`; по умолчанию он содержит факты по всем этажам, на которых есть элементы задания. Выход включает `documentation.json`, CSV по типам и `receipt.json` с контрольными суммами. В JSON сохранены связи требований, операций и GUID. Нативные разрезы, листы и PDF требуют отдельной проверки и выпуска.

## Проверка планировки двухэтажного дома

В действии «Проверить планировку и показать эскиз» выберите `examples/accelerator/r07-two-storey-house.json` и вариант `house-a`. Откройте `эскиз.html` из папки результатов. Два плана и разрез по лестнице строятся по тому же авторскому графу, который использует проектный предконтроль. Исходные численные требования записаны в `examples/accelerator/r07-house-brief.md`.

`ROOM_CLEAR_AREA` проверяет площадь отдельного помещения на поддержанном полу после вычета стен и плановой проекции марша. `ACCESS_PATH` с `minimumClearWidthM` строит маршрут по связанным участкам свободного пола и проверяет подходы к дверям. `entryStoryId` выбирает этаж входа снаружи. Для межэтажного перехода источником связи служит `STAIR_LINK` с двумя явно заданными помещениями площадок. В `limits` задаются проектные пределы для марша и площадок. В отчёт попадают фактические измерения и ID задействованных операций BIM.

Действие «Сравнить редакции планировки» показывает, какие маршруты, площади, операции, фасады, разрезы и документы надо перепроверить. Горизонтальная проверка свободной ширины опирается на модель круглого габарита. Высота прохода, открывание створок, отделочные слои, доступность и применимые нормы требуют собственных данных и испытаний.

```powershell
python -m apa design-review --intent examples/accelerator/r07-two-storey-house.json --variant house-a --output эскиз.html
```

## Архитектура исполнения

Для демонстрации строительной системы 1 НФ, отрицательной проверки простенка и анализа изменения используйте [сценарий R05](APA-R05-DESIGN.md).

Точка входа `apa.py` собирает существующие схемы и политики `DynamicCommands`. Локальные IFC, DXF и PDF-провайдеры регистрируются как `READ_ONLY`. `BIM Graph` проверяет зависимости и контракты. Нативные операции продолжают идти через `SceneWriter` с существующим журналом SQLite, привязкой к проекту, проверками модели и сверкой результата.

`apa project-runtime --help` показывает интерфейс предконтроля и выполнения на тестовом проекте. `apa group-runtime --help` показывает протокол работы с выделенной копией PLN, сверку прерванного запуска и проверку повторного открытия. При наличии `saved.json` выбирайте сверку сохранённого результата. `apa template-runtime --help` показывает инвентаризацию, планирование и поэтапную настройку шаблона. Для записи используют только область, прошедшую действующий предконтроль и привязку к проекту.

Опциональные `OpenBIMSegments` и `RasterFloorplan` подключаются через `apa --semantic-profile models.json catalog APASemantic`. Используется существующий локальный профиль `APA_SEMANTIC_ML_VENDOR_CONFIG_V1` с доверенными интерпретаторами, каталогами вендоров и контрольными суммами моделей. Пакет включает исходники и контракты Archicad 29. Для нативных операций нужен совместимый загруженный APX и активная рабочая копия PLN. Исторические установщики и мост GitHub остаются доступны отдельно для совместимости с установленным профилем.

## Повтор проверки

```powershell
$env:PYTHONPATH = 'scripts;tests'
$env:PYTHONUTF8 = '1'
& $Apa -m unittest -v test_apa_unified
```

Windows CI повторяет сквозные сценарии и регрессии на зафиксированных зависимостях, затем собирает ZIP тестируемого коммита и SHA-256. Сценарии CLI проверяют артефакты и содержимое исходных файлов. Для результата в Archicad действуют самостоятельные нативные испытания.
