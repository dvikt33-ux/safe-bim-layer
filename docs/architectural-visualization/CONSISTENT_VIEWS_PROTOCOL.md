# AV-01 — согласованная архитектурная генерация: план, фасады, разрезы, 3D

**Назначение:** обязательный рабочий протокол при подготовке архитектурных изображений и планшетов в чатах ChatGPT для этого проекта. Версия документа: 2026-10-12.

**Статус:** методика, а НЕ реализованный или валидированный модуль генерации изображений APA. Существующие проверки native BIM-геометрии не означают, что AI-генератор сам умеет делать взаимно точные проекции.

## 0. Непреложное правило

**ОДНО ЗДАНИЕ → ОДНА ГЕОМЕТРИЧЕСКАЯ ОСНОВА → ВСЕ ПРОЕКЦИИ → ПРОВЕРКА → ОФОРМЛЕНИЕ.**

Нельзя независимо выдумывать план, фасад, разрез и перспективу, выдавая четыре красивые, но несовместимые картинки за один проект. Текстовый промпт сам по себе не гарантирует совпадения геометрии: для технически точных видов нужны общая BIM/CAD/параметрическая модель и детерминированные проекции.

Не смешивать:
- **EXACT_GEOMETRY**: виды действительно построены из одной проверенной геометрии.
- **CONCEPT_ILLUSTRATION**: изображения получены генеративной моделью, даже если промпт требует единообразия; точность НЕ доказана.
- **UNVERIFIED**: недостаточно исходных данных или нельзя проверить результат.

Модель изображений не превращает иллюстрацию в рабочий чертёж автоматически. Не утверждать `PASS` без реального сопоставления.

## 1. Сначала найти источник геометрии и зафиксировать полномочия

Приоритет исходных данных:
1. Текущие требования пользователя (размеры, этажность, расположение помещений/окон/дверей, форма крыши, материалы, допустимые изменения).
2. Предоставленные пользователем DWG/DXF/IFC/PLN, BIM-выгрузки, плоские чертежи и референсы; проверить читаемость и авторитетность.
3. Уже зафиксированная в текущем чате согласованная `Model Card` — только если пользователь не менял исходные параметры.
4. GitHub APA — источник **методик проверки и кода**, но НЕ автоматический источник геометрии любого здания. Не переносить размеры из тестового проекта в новое здание.

Если нельзя получить фактические данные из PLN/IFC/чертежа, **не делать вид, будто файл открыт или BIM прочитан**. Для точного задания запросить только необходимое недостающее (например, габариты и планы), или явно предложить концептуальный режим. Если пользователь запретил добавлять элементы, не придумывать окна, пристройки, террасы, окружение и иные изменения без разрешения. Референс не даёт разрешения изменять его архитектуру.

Для проекта пользователя никакие удалённые операции с реальным PLN и никакое переключение открытого файла не подразумеваются автоматически.

## 2. Сформировать единый «паспорт геометрии» (Model Card)

Записать одну проверяемую спецификацию в метрах, даже если далее будет только картинка:

| Поле | Что фиксировать |
|---|---|
| `source_id`, `revision`, `source_type` | Имя/версия модели и доказанный источник: BIM / измеренный чертёж / согласованная концепция |
| `units`, `origin`, `axes` | Единицы, начало координат, ориентация осей, север |
| `footprint` | Вершины внешнего контура (X, Y), выступы и внутренние дворы |
| `stories` | Отметки чистого пола и верха перекрытий, высоты этажей |
| `walls`, `slabs`, `roofs` | Контуры, толщина, высота, уклон, отметки коньков/карнизов |
| `openings` | Уникальный ID, привязка к конкретной стене, смещение от опорной точки, ширина, высота, отметка подоконника |
| `stairs`, `shafts` | Координаты, направление, марши, проёмы перекрытий |
| `materials` | Идентификаторы поверхностей/назначения, только подтверждённые или согласованные |
| `views` | Направление каждого фасада, линия и направление каждого разреза, положение 3D-камеры |
| `change_permissions` | Что можно менять, а что запрещено |
| `status` | `EXACT_GEOMETRY` / `CONCEPT_ILLUSTRATION` / `UNVERIFIED` |

Не выдумывать измерения из перспективной картинки. Отдельно помечать допущения и получать согласие на архитектурные изменения. Для концептуального проекта можно предложить собственную единую геометрию, но не подменять согласование фактом.

## 3. Порядок изготовления изображения / архитектурного планшета

1. **Source lock.** Зафиксировать Model Card и номер ревизии. Одна ревизия — один набор связанных видов.
2. **Geometry-first.** Построить общую 2D/3D-основу в доступной геометрической/CAD/BIM-среде; при её отсутствии не заявлять техническую точность.
3. **Deterministic views.** Извлечь/проецировать план(ы), фасады и разрез(ы) из этой же основы. Для фасадов зафиксировать сторону и направление взгляда; для разреза — линию сечения и глубину; для перспективы — координаты камеры и точку цели.
4. **Cross-view audit.** Сверить матрицу согласованности ниже ДО художественной обработки. Несоответствия исправлять в источнике, затем повторно строить все зависимые виды.
5. **Rendering.** Рендерить материалы, свет, тени и окружение, не меняя геометрических исходников. AI может помогать с атмосферой и подачей, но он не должен заново придумывать фасад, кровлю или окна.
6. **Sheet composition.** Собирать лист из проверенных проекций и рендера. Размерные линии/отметки/оси/названия чертить отдельно как текст/векторные элементы, а не доверять их генерации пиксельной модели.
7. **Final audit.** Повторная визуальная/геометрическая сверка результата после AI-обработки. Любые внесённые AI изменения архитектуры — отказ в статусе точного чертежа.

### Минимальная матрица проверки

| Инвариант | План ↔ фасады | План ↔ разрез | План ↔ 3D |
|---|---|---|---|
| Габаритный контур и выступы | Совпадают проекционные длины/позиции | Совпадают пересечённые контуры | Та же форма здания |
| Проёмы | Количество, ID, осевые привязки и размеры каждой видимой стороны | Высота, подоконник, положение относительно плоскости разреза | Нет пропусков, новых или переставленных окон/дверей |
| Этажи/перекрытия | Отметки этажей и межэтажные пояса | Пол/перекрытие/потолок на тех же Z | Совпадают этажность и уровни |
| Кровля | Карнизы, коньки и фронтоны | Уклон и реальная высота в плоскости разреза | Та же конфигурация, без нового ската |
| Лестницы/внутренние шахты | Только где отражаются на виде | Лестница и проёмы в правильных местах | Не дорисовывать лишнего |
| Материалы | Поверхности на заданных стенах | Если показаны конструкции, не менять их категории | Отделка не противоречит назначению |

Каждый критичный пункт пометить `PASS`, `FAIL` или `NOT_VERIFIED`; при отсутствии измеримых геометрических данных использовать только `NOT_VERIFIED`. Не выдавать визуальную похожесть за метрическую проверку.

## 4. Что делать, когда доступен только генератор изображений

Можно сформировать одну согласованную композицию, подробно описав общий контур, число этажей, карниз/конёк, сетку проёмов и взаимное соответствие видов. Но это **CONCEPT_ILLUSTRATION**, а не гарантированно согласованный комплект чертежей. Не указывать вымышленные точные размеры и не рисовать псевдоразмерные линии.

Если задача требует действительной точности, сначала получить геометрию и вывести технические виды программно/через CAD/BIM. Художественную часть можно сгенерировать отдельно; не заменять технические виды фотореалистичной картинкой.

Нельзя «исправить» несовпадение вида, попросив генератор перерисовать только одну картинку без сверки с общей моделью.

## 5. Архитектурные запреты и разрешения

- По умолчанию **не добавлять и не изменять** не указанные пользователем архитектурные элементы. Если изменение необходимо, заранее согласовать именно это изменение.
- Если просили изменить только один материал, сохранить всё остальное, включая габариты, проёмы, ракурс и композицию, насколько это технически возможно.
- Если пользователь приложил исходное изображение и просит его редактировать — редактировать исходник, а не создавать другой проект по мотивам.
- Не подменять несущие/технические выводы визуальной убедительностью рендера.
- Не объявлять экспорт IFC, чтение из Archicad, геометрический аудит или точную привязку к BIM без фактически выполненной операции.
- Проверенный протокол APA запрещает самовольную запись реального проекта: для визуальной задачи достаточно чтения/экспорта по явному разрешению; PR/документация не даёт разрешения на запись PLN.

## 7. Формат ответа ассистента для задач с несколькими видами

Перед генерацией кратко предъявить/внутренне проверить: `SOURCE`, `MODE`, `MODEL_REV`, `VIEWS`, `PERMITTED_CHANGES`. По итогам выдать:
- комплект изображений/чертежей с названиями и ориентацией;
- короткую таблицу критичных совпадений: число/позиции проёмов, габарит, этажи и отметки, кровля;
- честный статус точности: `EXACT_GEOMETRY`, `CONCEPT_ILLUSTRATION` либо `UNVERIFIED`, перечислить недостатки.

**Критерий «ГОТОВО» для точного архитектурного комплекта:** все виды получены из одной исходной геометрии, проверены основные межвидовые инварианты, оформление не исказило архитектуру. Если этого нет, честный статус — «концептуальная иллюстрация», а не «проверенный проект».

## 8. Активация правила в новых чатах

Документ в GitHub **сам по себе не становится системной инструкцией ChatGPT**. В новом чате нужно передать [короткий промпт](CHATGPT_PROMPT.md), вставить его в инструкции ChatGPT Project или дать ассистенту прямую ссылку на этот файл. Наличие ссылки не подтверждает, что она была прочитана — ассистент должен явно открыть документ и соблюдать правила. Это не меняет модель генерации изображений и не предоставляет ей доступ к локальным PLN.
