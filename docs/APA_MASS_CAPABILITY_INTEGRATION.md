# APA mass capability integration

This package extends verified PR82, without a new controller, graph, transport server or writer. The original runtime exposes 264 Tapir contracts; the installed official AC29 SDK has 73 typed methods. All 337 are prepared by the existing router. Twelve absent candidate contracts and fourteen real DevKit example registrations are also prepared, explicitly source-only and runtime BLOCKED. The combined catalog has 363 unique provider-qualified contracts; no DLL symbols, SDK declarations or library parts are added to that command count.

The same router now accepts additional add-on namespaces and isolated common-schema definitions. Existing native_transport/tapir dispatch carries the namespace. Registration is reacquired before each selected call. Official product matching is distinguished from per-method invocation: five official methods were actually called; the remaining 68 are documented/client-compatible but not individually runtime-probed.

Effects are source-bound operator metadata, never permission inferred from a command name. A 337-entry manifest describes documented read/create/modify/delete/transaction/service effects; 51 ambiguous effects stay UNKNOWN and cannot execute without additional source review. A policy or changed catalog invalidates old tickets. Every write still needs explicit impact, project/hash, complete affected/retained inventory, one SceneWriter/SQLite ATTEMPTED-before-dispatch and independent readback. No UNKNOWN write replay.

`prepare_native_workflow()` uses the existing BIM Graph compiler. `$result` bindings reference a producer step and JSON pointer, add dependency edges, resolve typed schema placeholders and revalidate concrete consumer inputs before dispatch. The existing graph detects cycles. No independent scheduler is added. Mutating steps delegate to the same SceneWriter; failed steps stop the workflow. Native facts reuse Model Dump, IFC BREP quantities and Shapely rather than a new geometry engine.

A real 12-step read-only workflow exchanged data across official API and Tapir: 10 Walls -> details, bounding boxes and IFC IDs; attribute IDs -> 59 BuildingMaterial facts; 2779 native GDL Object resources; stories, navigator and MEP facts. All 258 accepted signatures remained unchanged. One authorized SaveProject representative then passed through the same journal with no geometry changes. Fifteen distinct commands were callable-verified in this pass, including product/registration probes and Save. Four effects have independent live evidence. Prior PR82 acceptance was not repeated or counted as a new pass.

Important geometry boundary: official boxes differed from actual resultant BREP for nine of ten Walls. These facts are retained side-by-side; the shared physical geometry uses Native Model Dump. Corner/SEO cause is not falsely certified from box differences. IFC IDs do not establish semantic export compatibility. Engineering remains NOT_VERIFIED.

Full C++ member/overload coverage and unsafe direct DLL calls are not claimed.
