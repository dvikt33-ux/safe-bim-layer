# Archicad 29: автоматический выбор групповых операций APA

**Цель:** при точном подтверждении состава повторяющегося узла выбирать одну
операцию тиражирования **целой группы**, а не копировать каждую стойку,
балку или объект отдельно. Не писать новый нативный функционал: используется
установленный Tapir/Graphisoft SDK, `DynamicCommands`, BIM Graph,
`SceneWriter` и существующий диспетчер APA.

## Что интегрировано

- `scripts/apa_ac29_group_strategy.py`: сопоставление каждой исходной
  детали с **каждым** целевым элементом по типу, подписи BIM-семейства,
  этажу, координатам и документальному источнику.
- `scripts/apa_ac29_semantic_operation_selector.py`: сперва групповые
  кандидаты, затем оставшиеся самостоятельные копирования, затем
  создание по полным нативным данным. Целевые элементы группы удаляются
  из поэлементного плана — двойное создание исключено.
- `scripts/archicad_project_accelerator.py`: вход
  `prepare_auto_optimized_native_task` принимает
  `schemaVersion: apa-native-group-auto/1`; новый режим
  `prepare_current_runtime_group_native_task` только читает текущую
  регистрацию команд на конкретном охраняемом экземпляре Archicad 29.
- Для существующей проверенной группы — одна
  `CloneNativeGroupV1`. Для набора проверенно не сгруппированных
  элементов — `CreateNativeGroupV1` → `CloneNativeGroupV1`, где GUID
  новой группы передаётся **штатной** ссылкой результата BIM Graph
  `$result: {step, pointer: /groupId}`.
- Остальные отдельные элементы — штатный `MoveElements(copy=true)`,
  пакетное `CreateColumns` / `CreateBeams` только при наличии полных
  корректных `nativeCreateData`. Неподдерживаемые элементы не создаются
  по умолчаниям.

## Какие доказательства обязательны

- В `existing` требуются `guid`, `nativeReadbackVerified: true`,
  `familySignature`, `storyIndex`, `anchor` и тип элемента.
- Для группы требуются `sourceRef`, `memberGuids`, `placements`,
  `sameStory: true`, `dependenciesVerified: true`.
- Уже сгруппированные элементы требуют существующий `existingGroupGuid`
  и `groupReadbackVerified: true`; новая группировка —
  `ungroupedReadbackVerified: true`. Без этих доказательств планировщик
  **отказывает**, а не копирует части группы по одной.
- Поддержанные в первом этапе составные группы: `Column`, `Beam`,
  `Object` (без неподтверждённых внешних зависимостей). Нельзя молча
  копировать окна/двери отдельно от несущих стен.
- Тиражирование ограничено 32 размещениями и не более 200
  элементов группы за одну нативную команду. Смещения задаются точно,
  не выводятся из случайной геометрической сетки.
- Команды проверяются по существующим схемам и политике воздействия APA,
  а **регистрация в текущем Archicad** подтверждается отдельным
  `API.IsAddOnCommandAvailable`.
- Сам факт успешного выбора не выдаёт разрешение на запись:
  `nativeWritePermission: false`. Вызов `run_auto_optimized_native_task`
  всё равно использует существующие `SceneWriter`, SQLite-журнал,
  подпись проекта, пооперационный допуск и независимую проверку результата.

## Пример структуры задания

```python
intent = {
    "schemaVersion": "apa-native-group-auto/1",
    "request": "Тиражировать один проверенный узел колонн в две позиции",
    "existing": [
        # Реальные подтверждённые BIM-записи со всеми атрибутами и GUID.
    ],
    "targets": [
        # Для каждой позиции две записи с точной BIM-подписью и координатами.
    ],
    "assemblyGroups": [{
        "sourceRef": "KR_SOURCE_VERIFIED_DOCUMENT",
        "memberGuids": ["<подтверждённый GUID 1>", "<подтверждённый GUID 2>"],
        "placements": [{"dx": 15, "dy": 0, "dz": 0},
                       {"dx": 30, "dy": 0, "dz": 0}],
        "sameStory": True,
        "dependenciesVerified": True,
        "existingGroupGuid": "<проверенный GUID существующей группы>",
        "groupReadbackVerified": True
    }]
}
preview = APA.prepare_auto_optimized_native_task(router, intent)
# Если выбранным нативным командам требуется свежая проверка в Archicad:
live = APA.prepare_current_runtime_group_native_task(router, writer, intent)
# Выполнение возможно только по отдельному решению с точными scopes:
# APA.run_auto_optimized_native_task(router, writer.api,
#                                   live["preview"], writer, scopes)
```

Пример содержит **местозаполнители**, а не реальные GUID или команду,
разрешённую к выполнению на BDD.

## Одна живая проверка планировщика на сохранённой тестовой копии (без записи)

Исходный успешный групповой тест PR №159 завершён и сохранён в файле
\`C:\LocalAI\APA_Group_Acceptance\group-ac29-assembly-20261018-04.pln\`
на порту \`19724\`. Он содержит 44 GUID. **Исходный BDD на \`19723\`
не трогать.**

Локальный сценарий \`scripts/apa_ac29_live_group_autoselect_readonly.py\`:

1. Проверяет, что открыт именно сохранённый тестовый PLN и исторические
   квитанции группы/копирования/перемещения/разгруппирования действительны.
2. Считывает настоящую нативную группу и 2 стойки, сегменты, этаж, действующие
   GUID и 3D-габариты. Геометрия не придумывается.
3. Находит свободные места для **предварительного плана**, используя
   уже существующий консервативный механизм коллизий. Создания копий нет.
4. Собирает **точные исходные подписи по конкретным GUID копируемых стоек**.
   Это подтверждённое копирование идентичного исходного элемента, **не**
   эквивалентность произвольных стоек по материалам/профилям.
5. Подключает кодовый каталог Tapir и уже существующие схемы
   \`connect_functional_modules\`. Вызывает штатный
   \`APA.prepare_current_runtime_group_native_task\` на ограниченном
   **только читающем** адаптере. Этот адаптер не содержит
   \`execute_bound_operation\`, не реализует SceneWriter и не может писать.
6. Проверяет результат: выбрана **одна** \`CloneNativeGroupV1\` на две
   позиции, а поэлементные копирования отсутствуют; команда действительно
   зарегистрирована в текущем Archicad. Сравнивает SHA сохранённого
   тестового и исходного PLN до/после.
7. Публикует однократную квитанцию в
   \`safe-bim-bridge\`, ветка
   \`feature/apa-ac29-apx-build-mailbox-20261018\`, путь
   \`safe-bim-mailbox/apa-ac29-group-acceptance/results/group-autoselect-real-model-readonly-20261018-01.json\`.

**Одно безопасное обновление и один запуск** (из PowerShell):

\`\`\`powershell

$branch = "feature/apa-ac29-automatic-group-routing-20261018"

if ($LASTEXITCODE -ne 0) { throw "Не удалось получить ветку APA" }

if ($LASTEXITCODE -eq 0) {

Не закрывать и не переключать второй экземпляр Archicad до завершения
читающего теста. Запуск **не копирует ничего**. Статус успеха:
\`LIVE_READONLY_GROUP_STRATEGY_SELECTED_PASS\`.
Не запускать повторно ради получения статуса: опубликованный результат
проверять напрямую в GitHub.

**Это не тест записи через SceneWriter и не разрешение на изменение BDD.**
Для производственной операции требуются отдельная привязка рабочего проекта,
пооперационные области изменения, журнал, точные исходные данные и
независимый полный readback, как и раньше.

## Проверки и пределы результата

В `tests/test_apa_ac29_group_strategy_integration.py` отдельно
проверяются: выбор целой группы, два варианта создания группового
узла, передача GUID между командами, оставшееся поэлементное
копирование, отсутствие дублирования, блокировка без доказательств
и отсутствие разрешения на запись без живой регистрации.

Это **интеграция исходного кода**. Она не означает новый LIVE PASS для
продукционного диспетчера, не обещает 100-кратное ускорение без замеров
и не доказывает новые операции в BDD. Ранее состоявшаяся проверка
нативной цепочки по PR №159 остаётся самостоятельным подтверждённым
результатом. До независимой проверки сквозного исполнения здесь
не следует указывать `LIVE_INTEGRATED_PASS`.

Проект остаётся на **Archicad 29**; `main`, BDD и Archicad 30 не меняются.
