# APA для Windows

## Первый запуск

1. Распакуйте Windows-комплект в обычную папку с правом записи, например в «Документы». На компьютере нужен 64-разрядный Python 3.11. На рабочем компьютере APA используется Python 3.11.9.
2. Дважды нажмите `Start-APA.cmd` внутри папки `APA-Windows`. Первый запуск создаёт `.apa-runtime` рядом с программой и ставит зависимости из комплектных колёс по SHA-256. Для установки зависимостей интернет не нужен.
3. Выберите действие, исходный файл и папку результатов. APA создаёт отдельный каталог каждого запуска. Кнопка «Открыть результаты» открывает отчёты и журнал команды.

Для локального анализа, подготовки графов и документации из снимка достаточно Python. Чтение открытого PLN требует Archicad 29, совместимого загруженного APX и профиля проверенной копии. Комплектный APX сверяется по квитанции в `native/binary-receipt.json`. Настройка рабочей установки Archicad выполняется отдельно.

## Рабочие маршруты

| Действие | Вход и результат |
| --- | --- |
| Подготовка BIM-задания | Типизированный файл APA. Сохраняет граф проекта, размещения или кандидатную операцию с условиями исполнения. |
| Предконтроль оболочки | Каталог подготовленного задания и порт открытой изолированной PLN. Использует существующие нативный предконтроль и квитанции SceneWriter. |
| Анализ IFC, DXF и PDF | Выбранный файл. Сохраняет результаты существующих провайдеров в новом каталоге. |
| Ведомости | Снимок Model Dump V1 и номер этажа. Сохраняет JSON и CSV по элементам этого снимка. |
| Библиотека проекта | Структурированное описание и кандидат из источника. Сохраняет комплект с данными происхождения и ограничениями. |
| Реестр APA | Запрос к включённому снимку канонического `PROJECT_PLAN.json`. Версия снимка указывается в результате. |
| Стена TDK | Исходное задание Wall.Ensure. Существующий адаптер нормализует его. С профилем PLN команда может сверить модель, избранное и свойства `AI_TRACE`. |
| Очередь и квитанции | Журнал SQLite бюро и файл терминального ACK Arena. Команды показывают состояние очереди и сохранённую квитанцию. |
| Профиль чтения PLN | Каталог состояния с `manifest.json`, `saved.json` и `reopened.json` и фактический порт API. Сверяет подтверждённый PLN, защищённый источник и пакет APA. |

Терминальные действия доступны через `python -m apa`. Интерфейс использует те же команды. [Команды ядра](APA-UNIFIED.md)

## Приёмник и диспетчер

Пакетный профиль позволяет существующему приёмнику обрабатывать типизированный `SOURCE_QUALIFIED_NATIVE_READ` для подтверждённой копии. Перед работой сверяются файлы выпуска, квитанция, PLN и установленный APX. Перед нативным запросом сверяется идентификатор загруженного APX. Пакетный и установленный приёмники используют общую блокировку. Журнал пакетного профиля располагается рядом с его файлом.

Действие «Проверить файлы профиля приёмника» сверяет файлы. «Подготовить настройки бюро» создаёт копию настроек с путём к новому профилю в `apaProfile`. Браузерная отправка в новой конфигурации изначально отключена. Для автономного режима служит `apa mailbox --package-profile профиль.json --loop`. Роль диспетчера и доступ к соответствующим чатам определяются его существующей конфигурацией. [Протокол бюро](research/apa-results/execution-optimizer/BUREAU_UNIFIED_SERVICE_20261020.md)

Wall.Ensure сохраняет свой контракт сверки. Для изменения стены с сопровождением свойств `AI_TRACE` нужен согласованный адаптер мутации через SceneWriter. Локальная квитанция Arena подтверждает завершение обмена и содержит SHA сигнала. Для запуска задания APA требуется отдельное типизированное задание с источником. Нативные сценарии и работа пакета проходят последующую приёмку на указанной ревизии.
