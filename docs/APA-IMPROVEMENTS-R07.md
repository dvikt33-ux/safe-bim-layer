# Улучшения APA после нативной приёмки

Ревизии ниже использованы как источники для сравнения. Работа с каждым кандидатом начинается от принятой двухэтажной PLN и доступных механизмов APA.

| Источник и решение | Что есть в APA | Следующий проверяемый блок |
| --- | --- | --- |
| **Archicad MCP Connector — DEFER.** Доступны C++-реализации лестниц и ограждений, документация и экспорт. [Лестницы и ограждения](https://github.com/davidharutyunyan/archicad-mcp-connector/blob/37ff69d380ca5e1b7576ab4262595c6cec2dc2e6/addon/Src/Commands/ComplexElementsStairRailing.cpp) · [Документация](https://github.com/davidharutyunyan/archicad-mcp-connector/blob/37ff69d380ca5e1b7576ab4262595c6cec2dc2e6/addon/Src/Commands/Documentation.cpp) · [Сборка](https://github.com/davidharutyunyan/archicad-mcp-connector/blob/37ff69d380ca5e1b7576ab4262595c6cec2dc2e6/addon/CMakeLists.txt) | Есть эскиз лестницы R07, чтение её геометрии, слой SceneWriter и проверки видов и Publisher. | Установить недостающую операцию по нативному испытанию. Если понадобится перенос C++, проверять API с DevKit соответствующего Archicad, для AC30 с DevKit 30. Сборка проекта поставщика даёт отдельный APX. Совместимость его кода с AC30 ещё требует проверки. |
| **HarnessBIM — TEST_ONLY.** Цикл проверок формирует замечания BCF с привязкой к модели. [Верификация и BCF](https://github.com/ReverseZoom2151/harnessbim/blob/3035021938cbf01128a619146f01eb2c9081d7e5/docs/08-verification-and-eval.md) · [Абстракция BIM Backend](https://github.com/ReverseZoom2151/harnessbim/blob/3035021938cbf01128a619146f01eb2c9081d7e5/docs/02-bim-backend-abstraction.md) | BIM Graph уже связывает требования, операции, GUID и затронутые виды. | На принятой модели проверить одно замечание BCF с разрешённым GUID и координатами вида. Этап проверки IFC не требует C++ или APX. Нативный исполнитель остаётся в APA. |
| **Archicad-MCP — TEST_ONLY.** YAML-правила задают область проверки и обрабатываются движком, включая свойства, классификации, зоны и коллизии. [Описание правил](https://github.com/alesdev88/Archicad-MCP/blob/af9d569efcee98b1b655c72730c1246421851de9/docs/rules.md) · [Движок](https://github.com/alesdev88/Archicad-MCP/blob/af9d569efcee98b1b655c72730c1246421851de9/src/archicad_mcp/rules/engine.py) · [Проверка свойств](https://github.com/alesdev88/Archicad-MCP/blob/af9d569efcee98b1b655c72730c1246421851de9/src/archicad_mcp/rules/builtin/property_required.py) | Есть типизированные требования, сквозное чтение свойств и проверка ограничений. | Сравнить один YAML-набор с доказательствами существующего маршрута. Перенос формата проверок не требует отдельного APX. Для проверок с нативным чтением нужны подтверждённые контракты APA. |
| **IfcTester — REUSE.** Проверяет экспортированный IFC по IDS. [Исходники IfcTester](https://github.com/IfcOpenShell/IfcOpenShell/tree/285d221089f0c818e76adea65d24b6c32fb38da1/src/ifctester) · [Руководство](https://docs.ifcopenshell.org/ifctester.html) | Команда APA уже вызывает закреплённый IfcTester 0.8.5. Положительную и отрицательную проверки IDS покрывают тесты `test_apa_ifc_reports_b1`. | Проверить IFC принятой R07 на один обязательный набор свойств и классификацию по IDS. Сохранить отчёт, SHA-256 IFC и IDS и связь с GUID. Дополнительный APX, DevKit и обновление библиотеки для этой проверки не нужны. |
