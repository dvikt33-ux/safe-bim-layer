# APA AC29: единый вход для массовых запросов

Статус: SOURCE/OFFLINE. Нативное выполнение нового входа и сохранение/reopen 32 групп **не приняты LIVE**. Родительский SAFE-01 находится в PR #178; общий блок остаётся PARTIAL до фактической приёмки.

## Рабочая цепочка в коде

`prepare_auto_optimized_native_task(router, intent)` принимает `apa-native-mass-request/1`, проверяет ограниченный текстовый intent и точные исходные BIM-данные, разворачивает явные расстановки и передаёт исходный `apa-native-group-auto/1` в существующий group-first selector. Затем используются прежние DynamicCommands, BIM Graph, `prepare_current_runtime_group_native_task`, `run_auto_optimized_native_task`, code-owned scope/verifier и SceneWriter/SQLite.

Новый модуль — адаптер запроса. Другого Router, исполнителя, очереди, APX или фонового процесса нет. Сведения о размерах, шагах, семействах, GUID, этажах, группах и осях из текста не придумываются. Текст не выдаёт разрешение на запись.

| Запрос | Явные данные | Выбор |
| --- | --- | --- |
| Копии вдоль линии | count, start, step в метрах | Один `MoveElements(copy=true)` |
| Тиражирование известной группы | Проверенные члены/группа и смещения | Один `CloneNativeGroupV1` |
| Сетка группы | columns, rows, stepX/Y, startDx/Dy | Один существующий native clone для 1–32 размещений |
| Расстановка по осям | Точные идентификаторы и координаты X/Y; исходная опорная точка | Один batch копий; реальные Grid-объекты требуют своего отдельного контракта |
| Булево объединение тел, непроверенная новая группа или иной состав группы | Отсутствует принятый code-owned verifier | Fail-closed |

## Что завершено из старых веток

Из #172/#174 перенесены существующие grid planner, переменное число размещений в независимом group verifier, исходные проверки SceneWriter, forensic SQLite reader и отдельный legacy acceptance script. Их происхождение закреплено SHA `4ef970a1cef798aafbece4649af926b9f8f4e57a`. Hotlink-specific reconciliation в текущем `apa_ac29_dynamic_write_scopes.py` сохранён. Старые acceptance scripts имеют собственные привязки веток/PLN/mailbox; их перенос не разрешает запуск в новом checkout и не означает установку.

При сквозном тесте реального DynamicCommands выявлен отсутствовавший шаг настройки: `MoveElements` имеет двойной эффект. В group workflow теперь локально регистрируется уже существующая source-reviewed CREATE-политика для ветки `copy=true` из #143. Исходный `DynamicCommands.prepare` продолжает запрещать перенос исходных объектов и смешанный copy/move batch под этой политикой. Scope, identity и readback обязательны.

Группа поддерживается действующим verifier только как две независимые Column, каждая с одним ColumnSegment, на нулевом этаже. Общие Beam/Object-группы, создание группы с последующим `$result` и произвольная композиция не объявлены принятыми. В частности, scope binder по-прежнему требует отдельного утверждённого контракта для зависимых параметров — автоматического расширения разрешений нет.

## Доказательства и оставшиеся ворота

Проверка регистрации через реальный read-only API на точной тестовой grid-копии подтвердила AC29 build 5101 / Tapir 1.5.10 и четыре команды: CloneNativeGroupV1, MoveElements, CreateHotlinkInstances, SaveProject. Квитанция содержит `nativeWrites=0`, `saveCalls=0`. Каталог этого исходного checkout содержит 296 контрактов; это не пересчёт установленного пользовательского каталога 292.

Локальные тесты проверяют настоящий исходный selector/Router/graph. Подменённые ответы в тестах проверяют маршрутизацию/учёт, а не работу Archicad. Никакие синтетические тесты не повышают статус до LIVE.

Последовательность приёмки: SAFE-01 на отдельной копии → full native BREP/группа до 32-copy → один clone → сверка каждого исходного/нового GUID и групп → один защищённый save со снимком → фактическое close/no-open/reopen → независимый readback сохранённой копии. До этого шага 32-copy сохраняет LIVE NOT RUN; новые сторонние адаптеры не вводятся.
