The model-first continuation on PR74 qualifies actual global `SetStories` rather than a Z-only substitute. A separately authorized project contains only native template references at the start. One additional real native story is inserted, preserving existing floor IDs. The existing authored generator creates the two-floor building. Changing the lower story height3.0→3.3m moves the upper home-story Walls, Slab and Roof through Archicad's story system. Five lower Wall heights then become3.1m under the0.2m intermediate Slab. Their actual geometry is synchronized with source sills1.0m through ModifyWindows, retaining hosts and GUIDs.

## Reproducible adapters

- `archicad_native_spatial_structure.prepare_story_operation` qualifies an empty or fully owned test project. Unknown/foreign constructions, occupied-story insertion/deletion, moved ground anchor, changed saved bytes or changed baseline fail before dispatch. Ground template Elevations and native built-in marker Objects are independently identified, require no available bodies and are preserved by signatures. A new project from the same template may contain their same20GUIDs; this is not proof that a previously generated building was copied.
- `prepare_height_change` uses an explicitly labelled future-story read overlay only for compilation. It is not live evidence. Actual GetStories readback checks levels and stable floor IDs. `prepare_dependency_corrections` compares actual Wall heights and hosted sills against the structured intent. `archicad_project_accelerator.apply_native_story_height_change` delegates the packet to the same SceneWriter and SQLite journal. Completed states can be reconciled with `finish_height_change` without reissuing SetStories or Create.
- `archicad_native_stair_connection.favorite_dimensions` parses the existing Favorite's main native XML as data, requires positive consistent dimensions and pins its hash. A partial Favorite export is not accepted as a complete GDL bundle. `prepare` checks current Favorite availability, real story rise and an actual free model bay, and appends the native Stair to the existing BIM Graph. Width1m/20risers/going0.35m come from the installed Favorite; rise3.3m comes from actual stories. The test riser0.165m is their explicit derived ratio, not a normative value.
- `archicad_project_accelerator.apply_native_stair_connection` uses the same writer for one CreateStairs and one ModifySlabs hole. Its persisted baseline blocks another Stair packet before creation. The hole uses measured actual Stair body bounds, preserving the Slab outer ring, GUID, material, floor and thickness. No invented clearance or headroom acceptance. Native contours can rotate, close with repeated endpoints and quantize coordinates; the existing contour comparison checks geometry within1e-6 instead of rewriting a valid result.

`examples/accelerator/native-spatial-building.json` is the initial3.0m authored test intent for the explicitly approved isolated target. It is not an instruction to write another arbitrary PLN. Use the freshly exported installed schema, exact project identity, authorization, saved-byte hash, persistent ledger, existing preflight and matching plan hash before dispatch. All JSON reads must specify UTF-8. The authored preview now pins the actual explicitly supplied schema path/hash instead of silently checking the default schema.

## Exact Grid contract boundary

Installed CreateObjects has no native tool-variation input; generic Objects, text, lines and Morph are not axes. True SDK Grid elements are API_ObjectID with APIVarId_GridElement=`GREL`. The source-only `GetNativeGridDefaultsV1` overlay uses that native default identity and returns actual source parameter names without model or tool-default writes. It compiles against SDK29 with C++20 and registers through the existing overlay builder. It is not installed, creates no axes and does not claim runtime acceptance. Full APX linking/deployment is not performed; an unrelated existing extended-pen compile mismatch in the documentation translation unit is left untouched.

The remaining minimum runtime contract must preserve Grid variation before GetDefaults/Create, expose actual native Grid instance variation on readback, bind axis geometry/labels to the real Grid default parameter schema and edit those same native instances with stable GUIDs. Source parameter names and units must be read rather than guessed. BIM Graph axes remain semantic until this contract is separately deployed and verified. Current installed APX, normative and Knowledge Graph code, documentation and main/master are retained. A11.S03 remains PARTIAL.
