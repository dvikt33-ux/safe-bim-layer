# Сопоставление апробированных возможностей APA с шаблоном AC29

**Дата:** 26.10.2026. **Статус:** обзор источников и решений, не установка расширений и не повторный LIVE-тест.
**Связанные документы:** [реестр исследований](OCTOBER_2026_RESEARCH_INTAKE.md), [поиск по 188 октябрьским PR](OCTOBER_2026_PR_INDEX.json), [снимок веток](OCTOBER_2026_GITHUB_BRANCH_SNAPSHOT.json).

## Главный результат проверки

У проекта действительно накоплено больше, чем отражено в README сборщика: несколько ранее выполненных **конкретных нативных LIVE-прототипов**; отдельные проверки групп, тиражирования, стен, проёмов, кровель, лестниц, IFC/DXF и целого здания. Но исходные ветки часто **разделены и открыты как draft PR**. Это не означает, что каждая возможность уже включена в `feature/working-archicad-mvp`, и не доказывает готовность `AC29_RU_SBIM_1.0.tpl`.

Не объединять вручную исполнители: по принятому принципу единый контур APA — `DynamicCommands → BIM Graph → SceneWriter → SQLite`; Tapir использовать как доступный установленный каталог, а не подключать поштучно. Сам builder шаблона намеренно выполняет ограниченный безопасный набор операций с атрибутами. Расширение этого набора возможно после сверки локальной версии/схемы и нативного readback.

## Обязательные решения по базовому шаблону

| Категория | Что уже подготовлено в ветке `feature/working-archicad-mvp` | Пробел до релиза |
|---|---|---|
| Библиотека/шрифты | `fonts-manifest.yaml`, `library-migration-policy-v0.1.yaml`; сценарий font-preflight | Реальная проверка на Windows, миграция библиотек на чистом рабочем месте |
| Слои/перья/линии | `layer-registry-v0.1.yaml`, `graphics-registry-v0.1.yaml`, `apply-core` | LIVE readback проекта, в том числе точное совпадение SBIM Project Info, проверка вида/видимости |
| Материалы | Реестры Surfaces, Fills, Building Materials, Composites; частичный writer | Верификация чертежных штриховок, зависимостей, узлов сопряжений и исходных толщин |
| Документация | СПДС 2026, базис Формы 3, View Map, макеты, AutoText-контракты | Калибровка координат на листе, тесты текста/AutoText, реальная печать A3/A1 и нормативная проверка |
| Обмен | DWG_IN_REFERENCE, DWG_OUT_SPDS, DWG_OUT_COMPAT, IFC_COORD/IFC_ISSUE/IFC_REFERENCE_IMPORT | Сохранение/загрузка preset'ов, единицы, round-trip; не заменять проверку шаблона автономным тестом DXF |
| Инженерия | Исследовательские контракты MEP и систем, исходные расчётные кандидаты | Геометрия маршрутов, присоединения портов, расчёт и соответствие проекту не подтверждены |
| Результат | Код builder, offline validation, launcher | `AC29_RU_SBIM_1.0.tpl` НЕ СОЗДАН; требуется Windows read-only preflight, затем санкционированные стадии в новом чистом PLN |

## Приоритетная практическая последовательность

1. Закрыть реальные блокирующие ошибки интерфейса launcher/CLI (см. [PR #195](https://github.com/dvikt33-ux/safe-bim-layer/pull/195)), доказать автономными тестами; **не сливать автоматически**.
2. Перед запуском на Windows проверить точный PID/порт/проект, так как исторически параллельно открывались несколько Archicad и порты не взаимозаменяемы; идентичность рабочего PLN нельзя угадывать по номеру порта.
3. Выполнить **только чтение**, этап `-Stage preflight`, сохранить первичные JSON и summary. Если ошибки/изменение проекта — СТОП.
4. По явному разрешению выполнить запись атрибутов **только** в отдельно сохранённом чистом кандидате, после чего повторно прочитать атрибуты, видимость, метаданные, посчитать модельные элементы.
5. Не включать массовые операции, Rhino, Hotlink или библиотечные writer'ы в обязательный путь начального TPL; использовать их отдельно при создании проверочного здания/проектного пакета.
6. Выпускать `.tpl` только после сверки Form3, PDF/DWG/IFC, библиотек, шрифтов и отсутствия лишней геометрии; фиксировать версию и манифест с доказательствами.

**Неразрешённая неопределённость:** актуальность установленного TAPIR 1.5.10 против закреплённой в сборщике JSON-схемы 1.5.8; реальная подготовка настроек в Archicad; статус лицензий/установок конкретных Rhino/GH дополнений. Это нельзя закрыть пересказом PR или успешным GitHub CI.
