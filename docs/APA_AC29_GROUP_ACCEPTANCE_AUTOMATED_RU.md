# APA 29 — один комплексный тест нативных групп вместо ручных команд

**Предпосылки подтверждены пользователем:** Archicad 29 на порту `19724`,
открыт `C:\LocalAI\APA_Functional_Test_House_01.pln`; на порту `19723`
открыт BDD и не должен изменяться. Пять групповых команд Tapir зарегистрированы.
Бинарник APX установлен с проверенной SHA-256-суммой.

## Что делает один локальный исполнитель

1. Проверяет точный порт `19724`, версию Archicad 29, путь исходного тестового
   PLN, регистрацию пяти команд и сохранённую SHA-256-сумму исходного PLN.
2. Сам читает все GUID, типы, группы и 3D-габариты, выбирает **две независимые
   стойки** одного уровня. Не просит пользователя вручную выбирать GUID.
3. Рассчитывает два свободных смещения для копирования группы и смещение для
   перемещения первой копии, отказываясь от коллизий.
4. Создаёт **побайтовую копию сохранённого тестового PLN** в
   `C:\LocalAI\APA_Group_Acceptance\<job>.pln`, открывает копию через
   готовую команду Tapir `OpenProject`. Не допускает записи до подтверждения
   точного нового пути проекта на порту `19724`.
5. Через **уже установленные** SDK-команды Tapir, без самодельных команд
   моделирования, выполняет CreateNativeGroupV1 → CloneNativeGroupV1
   (сразу две копии) → MoveNativeGroupV1 → UngroupNativeGroupV1.
6. После каждого шага независимо проверяет состав групп, количество и
   идентичность GUID, 3D-габариты и отсутствие изменений исходных элементов.
7. Сохраняет **только тестовую копию** через Tapir `SaveProject`,
   публикует итоговый отчёт в GitHub.

## Проверка настоящих 3D-препятствий (2026-10-18)

- Для элемента с отсутствующим или некорректным ответом
  `Get3DBoundingBoxes` вызывается уже существующий **нативный**
  `GetModelDumpV1` (полная проверка слотов, абсолютной системы координат,
  тождества GUID и конечности координат).
- `ColumnSegment` и `BeamSegment` восстанавливают габарит из
  собственных BREP-вершин; если у дочернего сегмента нет самостоятельных
  граней, проверяются отношение hostGuid, тип родителя, список дочерних
  GUID, BREP-вершины родителя и его изначальный ограничивающий габарит.
- В протокол заносится отдельное доказательство:
  `nativeBoundsReconstructed`. Неподтверждённая связь/геометрия
  запрещает запись, а не игнорируется.
- Система **не объявляет сегмент двумерным** и не исключает его из
  проверки объёмных препятствий.
- Два предшествовавших диагностических запуска остановились до копии
  PLN и до модельной записи:
  1) `KeyError: 'error'` — исправлен;
  2) `INCOMPLETE_MODEL_BBOX_COLLISION_PREFLIGHT` — добавлена проверка
  настоящих типов;
  3) `UNBOUNDED_SPATIAL_MEMBER_BLOCKED` для `ColumnSegment` —
  подключён нативный механизм BREP с проверкой родителя.
  Результаты будущих проходов не заявляются до реального отчёта.

## Диагноз и продолжение попытки 04

Нативное `CloneNativeGroupV1` создало две группы со стойками по смещениям
15 м и 30 м. Исходный инвентарь содержал 36 GUID, после копирования — 44.
Четыре родительские стойки и **четыре собственных ColumnSegment GUID**
подтверждены независимым чтением, состав групп и геометрия соответствуют
ожидаемым координатам. Это **не повод разрешить любые лишние GUID**:
основная функция `native_owned_children` получает дочерние сегменты из
`GetSubelementsOfHierarchicalElements`, проверяет их родительскую связь,
точный тип и непересечение с исходными GUID; затем сверяет **полное точное
множество GUID модели** и сохраняет отношения после групповых изменений.

Для уже начатой попытки 04 **новое копирование запрещено**.
Одноразовое продолжение `scripts/apa_ac29_group_resume_after_clone.py`
сначала сверяет новую независимую READ-ONLY инвентаризацию со старой
локальной квитанцией `reconciliation-readonly.json` по всем существенным
полям, существующим GUID, геометрии скопированных стоек, составу групп и
дочерним GUID. Исполнитель работает только когда открыт
`C:\LocalAI\APA_Group_Acceptance\group-ac29-assembly-20261018-04.pln`
на `19724`. После проверки он выполняет **только MoveNativeGroupV1,
UngroupNativeGroupV1**, независимое чтение и **SaveProject только копии**.

```powershell
$src = 'C:\LocalAI\APA_AC29_Build_Source'
git -C $src pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Не удалось обновить исходники' }
python "$src\scripts\apa_ac29_group_resume_after_clone.py"
```

Локальный файл `resume-started.json` записывается до первой операции,
а `resume-before-<stage>.json` — до каждой команды. **Автоматические
повторы запрещены**, в том числе при неопределённом результате команды.
Квитанция продолжения публикуется в
`safe-bim-mailbox/apa-ac29-group-acceptance/results/group-ac29-assembly-20261018-04-resume.json`.
До получения реальной квитанции успешная проверка Move/Ungroup/Save
**не заявляется**. Успех продолжения не означает, что тест в одном
непрерывном запуске прошёл полностью или что производство через
SceneWriter уже подтверждено.

## Безопасность

- Командный источник не может переопределять порт, исходный путь, количество
  операций или произвольный скрипт: допускается лишь заранее заданное действие.
- GitHub-задание содержит точный commit SHA, который должен совпасть с SHA
  локального исполнителя.
- Перед каждой записью повторяется проверка открытого **копированного** PLN
  и неизменности исходного дискового файла.
- У каждого этапа есть локальная запись намерения до native-команды. Повтор при
  неопределённом результате **запрещён**, нет автоматической повторной записи.
- BDD, `main`, операционный мост BDD и оригинальный
  `APA_Functional_Test_House_01.pln` не должны изменяться.
- При ошибке после открытия копии может остаться незавершённая/несохранённая
  тестовая сцена. Её не сохранять и не пытаться повторить автоматически.
- Если в открытом исходном тестовом проекте есть несохранённые изменения,
  Tapir OpenProject может вызвать диалог пользователя; до подтверждённого
  открытия **копии** любые операции записи заблокированы.

## Одноразовый запуск (после публикации задания)

Обновить только выделенную ветку локального исполнителя:

```powershell
$src = 'C:\LocalAI\APA_AC29_Build_Source'
git -C $src fetch origin feature/apa-ac29-group-acceptance-mailbox-20261018
git -C $src switch -C feature/apa-ac29-group-acceptance-mailbox-20261018 origin/feature/apa-ac29-group-acceptance-mailbox-20261018
powershell -NoProfile -ExecutionPolicy Bypass -File "$src\scripts\Start-APA-AC29-GroupAcceptance.ps1"
```

После запуска сценарий **сам** получает единственное задание из GitHub, выполняет
полную проверку и возвращает один результат.
Чтобы принимать новые задания в будущем без новых ручных действий, локальный
исполнитель можно позднее подключить как постоянно запущенную службу с `-Loop`
и отдельным локальным разрешением. Никакого удалённого PowerShell.

## Статусы

- `LIVE_GROUP_FULL_CHAIN_PASS` — только если все четыре операции,
  нативная геометрия/GUID и сохранение **копии** подтверждены.
- `STOPPED_REQUIRES_MANUAL_RECONCILIATION_NO_AUTORETRY` —
  этап остановился; смотреть конкретный error и локальные квитанции.

**Важно:** это отдельный изолированный приёмочный прогон нативных команд.
Он не является подтверждением сквозной производственной маршрутизации
через SceneWriter на оригинальном BDD. Эту интеграцию фиксировать отдельно,
не подменять статусами данного теста.
