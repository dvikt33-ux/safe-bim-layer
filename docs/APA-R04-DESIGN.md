# Проектирование и сверка BIM в APA R04

1. `apa design-request --source <ТЗ.txt> --output <request.json>` сохраняет исходный текст и SHA‑256. GPT уточняет неизвестные параметры, присваивает стабильные ID требованиям и готовит варианты по примеру `examples/accelerator/r04-project-design.json`. ТЗ с открытыми вопросами можно сначала проверить через `apa plan` в формате Semantic Brief.
2. `apa plan --intent <варианты.json> --output <review.json>` проверяет прямоугольники помещений, площадь с заданной методикой, опорные оси, явно заданные межэтажные связи и проходы. В проектном отчёте сохраняются источник и обязательность каждого требования. Сумма прямоугольников помещений вычисляется по исходной геометрии. Общая, полезная и жилая площадь требуют своих исходных данных. Обязательное непроверенное условие блокирует выбор варианта.
3. Для теста исполнения укажите `ADAPT_EXISTING`, точный путь будущей изолированной PLN и её фактическое имя этажа в `existingNativeLabel`. `apa design-select --intent <варианты.json> --variant <id> --output <authored.json>` готовит выбранный вариант. `apa architecture-stage` создаёт одноразовую копию проверенного донора по SHA‑256 и трассе 44 GUID. Этот маршрут поддерживает одноэтажный вариант из стен, перекрытия, дверей и окон. Существующий маршрут почты R03 использует закреплённые исходники оболочки и группы.
4. `apa architecture-runtime preflight --job <каталог> --port <порт>` связывает BIM Graph с прочитанными этажом и материалом. Сверьте `approved-preflight.json`, `plan.json` и перечень операций. `apa architecture-runtime execute --job <каталог> --confirm-preflight <SHA-256 approved-preflight.json>` выполняет подтверждённый граф один раз, перечитывает элементы и их геометрию, проверяет сохранность исходной модели и выполняет контролируемое сохранение. После закрытия `check-closed` проверяет отсутствие открытой PLN в том же процессе либо завершение PID из предконтроля. `verify-reopen --port <порт>` сверяет сохранённый PLN после открытия.
5. В `build/result.json` связь `requirementId → operationId → GUID` показывает фактическую проверку или расхождение. `apa design-diff --previous <до.json> --current <после.json> --variant <id> --output <impact.json>` показывает, какие этажи, элементы, требования и документы требуют пересмотра. Список изменений передаётся GPT для следующего варианта.

`archicad-startup` проверяет точный тестовый файл и загруженный APX после запуска или для указанного PID. Для сохранённой группы допустим отдельный каталог диагностики с новой копией тех же байтов. Существующий `group-runtime verify-reopen` сверяет GUID/BREP с квитанцией записи. Результат на новой копии имеет статус `LIVE_NATIVE_GROUP_BATCH_SAVED_COPY_READBACK_PASS`. Диагностика останавливается на диалоге, требующем действий оператора, и сохраняет наблюдения. Квитанция запуска сама по себе подтверждает готовность API для указанного PLN.

Статус `DESIGN_CHECKS_REVIEWABLE` относится к реализованным проверкам проекта. Применимость норм, несущая способность и полнота рабочей документации требуют отдельных доказательств. Лестница и проём перекрытия остаются открытым обязательным требованием, пока их нативный маршрут не подключён к варианту.
