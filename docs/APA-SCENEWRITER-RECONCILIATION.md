# Проверка записи и сохранения SceneWriter

`COMPLETE_UNSAVED` относится к сцене построения. Её шаги закончились с обратным чтением в открытой модели, сохранение на этом шаге ещё впереди. Отдельная сцена `SaveProject` фиксирует `PASS` после проверки записанных байтов и создания снимка. Оба состояния сохраняют момент выполнения своей операции.

Для полного прохождения нужны согласованные этапы.

| Этап | Доказательство |
| --- | --- |
| Создание | Сцена SQLite `COMPLETE_UNSAVED`, успешные строки шагов, GUID и результат обратного чтения. |
| Сохранение | Отдельная сцена `SaveProject` со статусом `PASS`, `saved.json`, `snapshot.json` и совпадающие SHA-256 PLN и `guarded-save.snapshot`. |
| Закрытие | `closed.json` подтверждает закрытие того же проекта или завершение точного тестового процесса. |
| Повторное открытие | `reopened.json` связывает результат с той же сохранённой моделью, GUID и BREP. Нативная проверка также сравнивает сигнатуры свойств. |

`architecture-runtime status` возвращает `LIVE_ARCHITECTURE_SAVED_REOPENED_PASS` только при наличии квитанции закрытия с тем же заданием и SHA-256. Повреждённая или отсутствующая квитанция блокирует подтверждение. Историю восстановления сохраняют, восстанавливая исходные байты квитанций из проверенной копии.

## Подготовка и продолжение

1. Подготовьте отдельную копию командой `architecture-stage` с проверенным донором и архивом начального чтения. Запускайте предконтроль на точном пути PLN и порту установленного экземпляра. Для новой попытки предконтроля сохраните предыдущие журналы.
2. Используйте `architecture-runtime preflight --job <путь> --port <порт>`. Квитанция `approved-preflight.json` фиксирует данные предконтроля. Для записи требуется явное локальное решение оператора на модель, хеш предконтроля и область операций.
3. Для проверки состояния выполните `architecture-runtime status --job <путь>`. Сверьте записи журнала и файлы по таблице.
4. При `UNKNOWN_NO_REPLAY_READONLY_RECONCILIATION_REQUIRED` сохраните `attempted.json`, журнал SQLite с сопутствующими файлами, вывод и текущий файл PLN. Прочтите фактическое состояние отдельным запросом. Следующее действие определяет оператор после сверки исходного задания и данных. [Действующий протокол фаз](APA-R03-MAILBOX.md)
