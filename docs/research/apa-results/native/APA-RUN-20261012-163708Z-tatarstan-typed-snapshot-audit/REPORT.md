## Какие реальные конструкции уже находятся в PLN

**Старый дом:** основные четыре стены на этажах 0 и 1, оси X 40–50 м / Y 40–48 м; толщина 0,30 м, высота стен каждого этажа 3 м. Две штатные Slab с верхними отметками Z=0 и Z=3 м, толщиной 0,20 м. Четыре окна (по два на этаж), одна дверь, две Column и два Beam. Одна штатная `Roof` находится над старым корпусом в X40–50/Y40–48; уклон 0,15 радиана (~8,59°), покрывает Z≈6,00–7,41 м. Это **один плоский скат**, не двускатная кровля.

**Отдельный испытательный экземпляр:** в X82–92 / Y≈40–48 имеется вторая `Roof` того же угла, и отдельная стена по оси X=87 м, доходящая до Z≈7,411 м. Отдельные Morph/Wall/Opening также размещены возле X60–72 / Y60–62. Имеющиеся шесть Morph — ранее созданные модели/образцы, не основание создавать новые Morph вместо штатных BIM-инструментов.

**Запланированный новый дом:** контур X112–122 / Y39–51 (10×12 м) **не содержит ни одной записи с валидной пересекающейся AABB**. Верхняя граница X всех 75 корректных bbox равна 92 м. Но 32 элемента без достоверных AABB препятствуют полному доказательству отсутствия геометрии; при следующем чтении требуется проверить все тела native dump и фильтры активного 3D-вида. Поэтому безопасная формулировка — `NO_VALID_AABB_OVERLAP / FULL_BREP_CLEARANCE_NOT_VERIFIED`, а не безусловное «участок свободен».

## Не повторять неудачные операции

Из приложенного консольного лога S01/S02 следует, что сценарий строения был разрушен PowerShell ParserError (`and` вместо `-and`), после чего последующие команды исполнялись как отдельные выражения. В журнале нет подтверждённого успешного native `CreateWalls`/`CreateRoofs`. Локальные `plan.json`, резервная копия и `write_started.json` **не подтверждают** создание дома. Инвентаризация 107 GUID относится к текущему старому/испытательному дому, а не к новому контуру.
