# APA — реестр кандидатов ИИ для будущих испытаний

**Создан:** 2026-10-14. **Ветка:** `research/apa-ai-candidates-registry-20261014`. **Область:** только исследования; не изменять APX/PLN, production-код, `main` или `control/PROJECT_PLAN.json`.

Этот раздел — **единый список кандидатов на проверку**, а не список подтверждённых улучшений ускорителя. Сюда добавляются локальные модели, внешние ИИ-агенты и сервисы генерации планов, полезные для разработки APA / Archicad 29. Неподтверждённые характеристики не выдаются за измеренные.

## Четыре категории (ровно)

1. **VERY_PROMISING — очень перспективные.** Максимальный ожидаемый эффект для конкретной задачи APA, совместимость или практический эксперимент выглядят реалистично. Первыми ставятся на испытания.
2. **PROMISING — перспективные.** Польза вероятна, но есть существенное ограничение: расход памяти, неизвестная скорость, качество или квоты.
3. **LOW_PRIORITY — рассмотрены; пробовать в последнюю очередь.** Польза узкая / ограниченная, либо уже есть более подходящий кандидат.
4. **DO_NOT_CONSIDER — не стоит рассматривать в текущих условиях.** Например: нет постоянно бесплатного рабочего маршрута, нужен студенческий тариф, нет пути к редактируемому BIM, или инструмент не решает нашу задачу. **Не утверждение, что продукт плох.** При изменении условий переоценить.

Категория — **предварительный приоритет**, а не вердикт о качестве. Не смешивать с независимым `test_status` (например, `NOT_TESTED`, `TESTED`, `BLOCKED`).

## Ограничения пользователя

- Ноутбук **Lenovo Legion Pro 5**: RTX 4060 Laptop 8 ГБ VRAM, **48 ГБ RAM**, Windows 11, Archicad 29; **докупать память не планируется**.
- Денежные затраты на новые модели/сервисы: **0 ₽** в постоянной эксплуатации; студенческие лицензии недоступны; trial и разовые кредиты не являются бесплатной интеграцией.
- Отдельно измерять использование VRAM, RAM и реально остающуюся RAM **с работающим Archicad**, а также скорость на **данной машине**.
- Реальные изменения BIM только через контролируемый APA Writer; модель не имеет прямого права изменять проект. Тесты сначала read-only / изолированная копия.
- Если модель/сервис работает только как ручной прототип концепции, это фиксировать; не называть интеграцией.
- Ни одна внешняя модель не объявляется независимым доказательством корректности Archicad. Нужны тесты кода и нативный read-back.

## Процесс внесения и пересмотра

1. **NEW → SHORTLISTED:** записать точный ID/версию/квантование, тип (модель / движок / облачный сервис), лицензии, официальную ссылку, пригодность к бесплатному использованию, роль, ограничение и источник. Все неизвестные значения оставлять `null`.
2. **SHORTLISTED → READY_FOR_TEST:** воспроизводимая инструкция запуска без установки на текущем компьютере пользователя; проверить источник файлов и безопасность.
3. **READY_FOR_TEST → TESTED:** сравнить на идентичных задачах (см. протокол), записать измерения и коммит/логи; отличать фактические тесты от маркетинговых цифр.
4. **TESTED → DECIDED:** категория может быть повышена/понижена **с объяснением**; решение `ADOPT`/ `RETEST` / `REJECT` принимается по данным.
5. Новые задачи для APA — **предложения**, пока независимый аудит не примет их в `PROJECT_PLAN.json`. Запись в этот реестр сама по себе не запускает разработку и не меняет статусы S-ID.

## Начальный приоритет

См. `candidates.json`: в первую очередь Gemma 4 12B / 26B A4B; затем сравнение с уже имеющейся локальной Qwen и большим MoE в Strata. Измерений APA на этом ноутбуке **пока нет**.

**Принцип:** источник ≠ тест; предположение ≠ результат; размер модели ≠ качество; параметры ≠ скорость. Категории допускают пересмотр после верификации.
