# APA AC29 — проверка выбора одиночных и массовых операций

Источник конструктивных групп: `docs/research/apa-results/bdd-house/APA_EXISTING_SCENE_WRITER_BASELINE_20261016.json` (исторический снимок состава, не снимок текущих координат 298 GUID); `APA_LIVE_6_WALL_HOST_CANDIDATES_20261016.json`; `AC29_MULTI_COPY_RECONCILED_AND_DEPLOYED.json`.

**Границы:** новые координаты взяты только в проверочных *синтетических* сценариях. Реальное расположение всех 49 свай, 48 лаг, марки осей и сегодняшняя геометрия BDD из этих источников не восстановлены. Нельзя выдавать синтетическую сетку 7×7 за настоящую координатную систему чертежа. Пользовательский PLN, существующая очередь, SQLite, APX и main не изменены. Native GridElement требует отдельно проверенного установленного SDK и соответствия параметров загруженной библиотеки.

## Проверочные ситуации в PR #157

1. Уникальная стена → одиночное создание, никаких осей.
2. Одинаковые Column, 3×4 → прямоугольный массив; но сами оси не появляются автоматически.
3. Полная сетка 7×7, с явно квалифицированными линиями X/Y → массив элементов плюс **отдельный** запрос на оси, пока не исполненный.
4. Решётка с пропуском узла → точные 11 мест, без заполнения отсутствующего.
5. Прямой равномерный ряд → линейный массив; неравномерный ряд → точные отдельные позиции в одном пакетном вызове.
6. Источник задаёт равномерное расстояние между концами → распределение только при совпадении каждого положения.
7. Источник задаёт ломаную → распределение по длине полилинии, без разворота прототипа.
8. Два типа готовых прототипов Column/Beam → один пакет много-прототипного MoveElements; свойства типов не смешиваются.
9. Два окна на стене → хозяин Wall обязателен; свободное копирование окна исключается.
10. Отдельная крыша → одиночный CreateRoofs, не ошибка unsupported copy.
11. Одинаковые элементы без готового прототипа → группировка для Create* с обязательными исходными параметрами.
12. Объект библиотеки → копировать только проверенную библиотечную деталь, не выдумывать параметры создания.
13. Уже находящийся на нужном месте элемент → без записи.
14. Неверные координаты осей или повторённая позиция → отказ.
15. Несогласованная траектория распределения → отказ.

## Важная граница приёмки

**PASS офлайн** означает только правильную классификацию типов расстановки и проверку исходных условий, опирающуюся на уже существующий `DynamicCommands.plan_reuse_existing`. Это не означает, что новые методы уже установлены в работающий APA или что они прошли реальное создание в Archicad. Исполнение должно проходить через старые архитектурные ограничения: исходные данные, реальные параметры, проверенный текущий GUID/BREP, локальное разрешение и SceneWriter. Оптимальность по времени требует сопоставимых измеренных длительностей для одинакового задания, а не догадки о скорости.
