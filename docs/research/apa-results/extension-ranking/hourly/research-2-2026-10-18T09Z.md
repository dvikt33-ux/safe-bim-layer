## Доказательные JSON/C++ контракты (статический разбор)

```json
{
  "PublishPublisherSet": {
    "publisherSetName": "required string",
    "outputPath": "optional string; otherwise publisher-set default",
    "selectedNavigatorItemIds": "optional #/NavigatorItemIds; empty means whole set"
  },
  "SaveProject": {
    "input": {},
    "effect": "ACAPI_ProjectOperation_Save() on current project",
    "output": "#/ExecutionResult"
  },
  "GetMEPPorts": {
    "input": {"elements": "#/Elements"},
    "output": {"elementPorts": "#/MEPElementPortsOrErrors"}
  },
  "CreateMEPRoutingElements_1_5_9": {
    "routingElementsData[]": {
      "required": ["domain", "nodeCoordinates"],
      "optional": ["crossSectionWidth", "crossSectionHeight", "crossSectionShape", "crossSectionReferenceId", "mepSystemId"]
    }
  },
  "CreateMEPRoutingElements_1_7_1": {
    "routingElementsData[]": {
      "required": ["domain", "nodeCoordinates"],
      "optional": ["crossSectionWidth", "crossSectionHeight", "crossSectionShape", "crossSectionReferenceId", "preferenceTableId", "mepSystemId"]
    }
  },
  "ConnectMEPElements": {
    "connectionsData[]": {"required": ["routingElementId", "connectToId"]},
    "output": {"connectionResults": "#/MEPConnectionResultsOrErrors"}
  }
}
```

Схемы выше — сокращённая **сводка реальных JSON Schema**, а не исполняемый запрос к Archicad. 12 исходных `GetInputParametersSchema` (5 MEP-команд × 2 тега + Publisher × 2 тега) успешно разобраны как JSON. `SaveProject` не имеет входной схемы; не следует изобретать для него `projectFilePath`.

## Аудит №1 — независимая сверка тегов и исходных схем

**Метод:** повторно получить файлы непосредственно по тегам, сравнить `GetInputParametersSchema` и методы `Execute`, не полагаясь на текущую документацию, релизный маркетинг или локальную память. **Результат:**
1. `PublishPublisherSet` уже в `ac-addon-0.1.1`, `selectedNavigatorItemIds` появляется не позднее `1.4.0` (нет в `1.3.1`). `SaveProject` есть в `1.3.1`, отсутствует в `1.3.0` по проверенному файлу.
2. MEP `GetMEPPorts/CreateMEPRoutingElements` есть в `1.5.6`, в `1.5.5` файл `MEPCommands.cpp` не найден; релиз [1.5.6][M56] прямо описывает MEP-команды для AC28+.
3. `GetMEPPreferenceTables` есть в `1.5.7`, нет в `1.5.6`. Поле `preferenceTableId` появляется не позднее `1.7.0`, отсутствует в `1.6.0`; **не приписывать локальной 1.5.10**.
4. `PublishPublisherSet` сохраняет входы в `1.5.9` и `1.7.1`; `SaveProject` меняет управление текущим окном в `1.7.1`, не контракт сохранения копии.
5. **OFFLINE:** 12 схем корректно разбираются как JSON; это не проверка доступности в запущенном AC29. Статусы `SOURCE_VERIFIED` и `OFFLINE_SCHEMA_PARSE`, но не `BUILD_PASS`.

## Аудит №2 — независимая функциональная контрпроверка

**Метод:** независимо сопоставить upstream C++ с официальной справкой **AC29**, лицензиями, актуальным планом и внешним расчётным решателем, специально искать контрпримеры первоначальным выводам.

1. **MEP:** [UI AC29][UI] разрешает менять профиль отдельного сегмента, но [Tapir 1.7.1][M17] при `Place` передаёт **две пустые карты** и при Modify обходит **все сегменты**. Следовательно, UI ≠ автоматический круг→прямоугольник. `GetMEPElements` умеет **распознать** `Transition`, а `CreateMEPElements` **не принимает** `Transition` и размеры двух портов. Подтверждает существующий `A11.S10 BLOCKED`, не повторяет его live-тест.
2. **SAF:** первоначальная общая гипотеза «Archicad не экспортирует нагрузки» **опровергнута**: [Graphisoft 29][LCS] включает экспорт load-related data по умолчанию, а [список типов][LOAD] различает 5 поддержанных и 6 неподдержанных видов. [Load Combinations][COMBO] только хранят данные, **не рассчитывают** их. Для PyNite нет готового мостика в проверенном дереве 155 путей, и [FEModel3D][PY] требует явного создания модели.
3. **Publisher:** исходник [Tapir][N15] не вызывает `SaveProject`, но не гарантирует, что выходные файлы не будут перезаписаны и что опубликованные документы полны. Безопасная схема — **отдельная открытая копия PLN + новый пустой outputPath + внешний манифест/хеши**, без SaveProject. Это **план**, не выполненная публикация.
4. **Нормы:** официальный [Росстандарт СП20][SP20] показывает **шесть изменений**; нельзя использовать коэффициенты из старой таблицы без привязки редакции. [Росстандарт СП50][SP50] задаёт область применимости; теплотехническая проверка по §5.4 требует тепловых мостов/узлов, не только IFC-слоёв. [IfcTester][IDS] проверяет IDS-требования к IFC, а не соответствие всем пунктам СП.
5. **Лицензии/Windows:** [Tapir MIT][LICENSE], [PyNite MIT и Python ≥3.11][PYC], [IfcOpenShell LGPL-3.0](https://github.com/IfcOpenShell/IfcOpenShell) — свободные исходники; штатный MEP Designer в справке AC29 **Available with Archicad Collaborate** и не становится бесплатным от Tapir. Релиз [Tapir 1.7.1](https://github.com/ENZYME-APD/tapir-archicad-automation/releases/tag/1.7.1) публикует Windows installer, но примечание говорит, что он **не подписан**. Ничего не скачивалось и не устанавливалось.

## Два конкретных нормативных правила — критерии для будущей проверки, не PASS

**СП 20.13330.2016, раздел 6.2, основные и особые сочетания (6.1–6.2).** Входы: тип сооружения, проектная стадия, постоянные/длительные/кратковременные/особые нагрузки, коэффициенты надёжности и сочетаний, локальная система осей, закреплённая редакция с изменениями №1–6. Проверка: классификация каждого случая, построение основных/особых сочетаний, сопоставление множителей и результатов с независимым расчётом. **Сейчас NOT_VERIFIED**: нет утверждённых проектных нагрузок и расчётного handoff. Источники: [официальная карточка][SP20], [публикация МЧС][SP20PDF].

**СП 50.13330.2024, §5.1 и §5.4, теплозащитная оболочка.** Входы: назначение/площадь и режим здания, климат, внутренние температуры, площади ограждений, реальные слои и λ с условиями эксплуатации, узлы и линейные/точечные теплопроводные включения, температуры поверхностей, закреплённая редакция. Проверка: **три требования** §5.1 (поэлементное, комплексное, санитарно-гигиеническое), расчёт **приведённого** сопротивления по §5.4/приложению Г. **Сейчас NOT_VERIFIED**: IFC/IDS не даёт мостиков холода и полного климатического набора. Источники: [официальная карточка][SP50], [опубликованный текст СП][SP50PDF].

## Следующие адресные вопросы — не предложения установить расширения

1. **R2-01 / P0:** в SDK29 есть ли публичный `TransitionDefault/Transition::Modifier` с **двумя портами разных shape/size** и допустимой ориентацией, либо только read-only Transition и сегментные setters? Получить точную сигнатуру/версию и доказать отсутствие/наличие JSON-экспозиции в локальном Tapir 1.5.10, не изменяя модель.
2. **R2-02 / P0:** можно ли read-only получить список Publisher Set и `NavigatorItemIds` через текущий APA, проверить пустой outputPath и состав выпусков PDF/IFC/SAF **до** разрешённого запуска? Разделить сохранение PLN и выпуск файлов.
3. **R2-03 / P1:** есть ли опубликованный открытый конвертер **SAF XLSX → PyNite** с таблицей Structural Members/Supports/Actions/Combinations/LCS и тестовым round-trip? Пока `NO_READY_BRIDGE` в проверенных репозиториях.
4. **R2-04 / P1:** какие конкретные редакции и значения по СП20 §6.2 и СП50 §5.4 нужны для **данного** объекта, с доказательством назначения, климата и узлов? Нормативная машина APA должна возвращать `NOT_VERIFIED` при отсутствии хотя бы одного обязательного источника.

## Ворота доказательств

- **SOURCE_VERIFIED:** C++ и JSON-схемы Tapir по тегам, Graphisoft AC29, исходник PyNite, официальные карточки СП, лицензии.
- **OFFLINE_SCHEMA_PARSE:** **12/12** JSON-схем извлечены из C++ и успешно разобраны вне Archicad; не эквивалент CI/BUILD.
- **BUILD:** `NOT_RUN`.
- **INSTALLED:** локальный Tapir 1.5.10 **REPORTED_PREVIOUSLY**, новая команда не опрошена.
- **LIVE:** `NOT_RUN`; ранее принятые live-фрагменты APA не переобъявляются результатами этого часа.
- **ACCEPTED:** `NOT_RUN`; без PLN сохранения/readback, проверки инженерных условий и манифеста выпуска приёмки нет.
- **Модель/репозиторий:** `MODEL_WRITES=0`, `MAIN_WRITES=0`, `PLAN_WRITES=0`, `APX_WRITES=0`; единственное разрешённое изменение — создание **этого** отчёта в исследовательской ветке.
