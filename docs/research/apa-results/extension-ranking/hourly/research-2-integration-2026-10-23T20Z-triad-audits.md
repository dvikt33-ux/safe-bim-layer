# APA №2 — два самостоятельных контрааудита SOURCE / 2026-10-23 20Z

## Контрааудит A — «IFCFileOperation означает, что G4 BREP уже принят»
**Оптимистическая гипотеза:** pinned Tapir1.5.10 содержит IFCFileOperation + GetIFCIdsOfElements; достаточно экспортировать IFC, G4 ACCEPTED.
**Контрдоказательства:** (1) IFCFileOperation — файловая WRITE вне DOCUMENT_COMMANDS PR74; без нового writer и отдельного допуска нельзя обойти SceneWriter. (2) Существующий guarded путь PublishPublisherSet реально есть, но его readback использует GetModelDumpV1, отсутствующий в pinned 262-command schema, и требует заранее существующий Publisher Set, 1–4 selected navigator IDs, новый пустой output directory, сохранённый PLN SHA. (3) AC29 Publisher всегда экспортирует только visible elements; BREP может не содержать скрытых стен/слоёв/этажей. (4) Collision-only и Gross Geometry фильтры искажают полноту/отверстия; BREP экспорт может потерять native parameters. (5) IFC GlobalId ≠ native GUID; необходим GetIFCIdsOfElements mapping. (6) IfcOpenShell по умолчанию tessellation, OCC BRep нужно явно подтвердить.
**Вердикт:** `G4_IFC_BREP_SOURCE_CANDIDATE`, не INSTALLED/LIVE/ACCEPTED. Безопасный следующий шаг: G0 READ GetIFCExportTranslators + GetNavigatorItemTree + actual GetModelDumpV1 presence; квалифицировать view/translator; никаких file writes. Источники: https://github.com/dvikt33-ux/safe-bim-layer/blob/f7c37b84b76c040c417ccd58a5543326e50f673a/schemas/tapir-live-1.5.10/tapir-scene-live.json; https://github.com/dvikt33-ux/safe-bim-layer/blob/5a3a9201a715a5528c93bed4a5318e2acb32eea7/scripts/archicad_bim_documentation.py ; https://help.graphisoft.com/AC/29/INT/_AC29_Help/121_IFC/121_IFC-45.htm ; https://docs.ifcopenshell.org/ifcopenshell-python/geometry_processing.html .

## Контрааудит B — «Graphisoft Live Connection даёт надёжную трёхстороннюю sync»
**Оптимистическая гипотеза:** включённый Live Connection синхронизирует AC↔GH↔Rhino, а выключенный Synchronize полностью блокирует все записи.
**Контрдоказательства:** (1) GH `Synchronize=TRUE` автоматически создаёт/обновляет элементы AC, вне APA SceneWriter/SQLite; `FALSE` возвращает Null только для Graphisoft GH компонентов, не блокирует Tapir GH/APA. (2) Deconstruct Roof не работает с MultiPlane; `Send Changes` требуется для передачи AC edits в GH. (3) GH-generated Library Part может удалиться при удалении Object Settings component, даже если другие экземпляры размещены. (4) Tapir GH ReplaceExisting может создать новый GUID и удалить старую стену с hosted openings. (5) JSON staging GH→PR74 остаётся однонаправленным, schema/unit/host mapping не является полноценным native round-trip.
**Вердикт:** `FULL_THREE_WAY_SYNC_NOT_FOUND`. Один owner: GH/Rhino calculations→frozen typed JSON→PR74→SceneWriter→AC; read-only AC→GH для сверки. При конфликте STOP+readback, не auto replay. Источники: https://help.graphisoft.com/AC/29/INT/GC.pdf ; https://github.com/ENZYME-APD/tapir-archicad-automation/pull/615 ; https://github.com/dvikt33-ux/safe-bim-layer/pull/74 .

Оба контрааудита независимы по предмету и источникам, но документарные, не native tests. MODEL_MODE_NOT_VERIFIABLE.
