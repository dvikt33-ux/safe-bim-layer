## 1. P0-дельта 11Z: жизненный цикл GH-элемента не равен GH-выходу

### P0-A. `Synchronize=False` — пауза, не доказанное удаление
[Официальный Graphisoft AC29 User Guide](https://help.graphisoft.com/AC/29/INT/GC.pdf) определяет: TRUE передаёт изменения Design/Document компонента в Archicad, FALSE не генерирует элемент и возвращает GH-выход `Null`. **Документ не устанавливает, что уже созданный AC элемент при FALSE удаляется.** [Разбор Graphisoft Community 07–24.02.2020](https://community.graphisoft.com/t5/Parametric-design/Synchronize-Bug/td-p/292443) прямо описывает сохранение уже созданных Wall/Window/Object после FALSE, пока синхронизация приостановлена. Исторический workaround с `Stream Filter → empty input` может инициировать удаление, но это отдельная **записывающая** операция, НЕ квалифицированная на AC29. Следовательно: `GH output=Null` **не доказывает** `AC inventory=empty`; никаких автоматических delete/recreate в BUILD-01.

### P0-B. Исправление неточного тезиса 10Z: AC→GH может обновляться автоматически
[Graphisoft AC29 User Guide, Grasshopper Palette](https://help.graphisoft.com/AC/29/INT/GC.pdf): включённая **Sync Changes to GH** непрерывно автоматически передаёт изменения **подключённых** Archicad-элементов в Grasshopper. Выключение оставляет ручной/несинхронный режим. Ранее сформулированное «AC→GH всегда требует ручного Send Changes» **неверно**. Автоматизм относится к AC→GH reference, НЕ к Rhino Object ID, НЕ к PR74 authored JSON, НЕ к SceneWriter и НЕ к общему AC↔GH↔Rhino commit. Если GH downstream включает Rhino Content Cache Push или GH Design `Synchronize=True`, появляется возможность обратной петли; в BUILD-01 оба пишущих выхода должны оставаться отключёнными.

### P0-C. Save/Open не удаляет автоматически GH-generated native elements
[Официальный исторический User Guide 2.3, Important Notes/File Handling](https://gsdownloads.graphisoft.com/cdn/ftp/techsupport/documentation/addons/archicad-rhino-grasshopper/AC-Grasshopper%20Connection%20User%20Guide%202.3.pdf) описывает: GH-generated native элементы остаются в сохранённом Archicad проекте даже без исходного GH кода; связь основана на ID. Это **исторический контракт**, не доказательство AC29 build5101. Он усиливает требование независимого readback inventory после Save/Close/Reopen: исчезновение GH-определения нельзя принимать за откат или удаление элементов.

### P0-D. Подключение Windows AC29/Rhino8 — воспроизводимый UI-маршрут, не runtime PASS
[Graphisoft официальный каталог](https://www.graphisoft.com/de-de/downloads/add-ons/rhino-grasshopper/) показывает **AC29 add-on build 3000**, Windows, Rhino 7/8, 01.10.2025; add-on без отдельной подписки, но Archicad и Rhino лицензируются. [Сообщение пользователя Graphisoft Community 2026](https://community.graphisoft.com/t5/Parametric-design/Archicad-29-and-Rhino-8-grasshopper-connection-issue/td-p/695667) предлагает последовательность AC29 открыть PLN → Rhino8 открыть .3dm → GH открыть .gh → AC palette `Sync Changes to GH` Start → GH `Archicad Connection Palette` Start Connection. Это **полевой пример**, не доказательство установленной среды и не основание нажимать Start без отдельного допуска. Дилерская страница с build/ID 3869 не подтверждена официальным Graphisoft каталогом как требуемая версия; для BUILD-01 pin только официальный AC29 build3000 до локальной проверки.

## 2. Точный смысл «три программы одновременно»
Разделять четыре независимых механизма: (1) Rhino geometry→GH Query/Content Cache reference; (2) AC native→GH `Sync Changes to GH` для подключённых элементов; (3) GH Design→AC native writer; (4) APA typed intent→SceneWriter/SQLite/Tapir→AC native writer. (1)+(2) не создают нативную AC запись. (3)+(4) — **два конкурирующих писателя** одного PLN; строгий inventory APA этого не допускает без согласования. Для BUILD-01 **единственный писатель AC — SceneWriter**. Rhino/GH — подготовка/проверка, AC→GH — read-only reference. Универсальный GH BREP→PR74 JSON без нового writer/router — **NOT_FOUND**.

[APA connected CLI](https://github.com/dvikt33-ux/safe-bim-layer/blob/5a3a9201a715a5528c93bed4a5318e2acb32eea7/scripts/archicad_connected_components.py#L425-L439) сверяет **всё** множество GUID, а не только APA-owned; [строки 549–575](https://github.com/dvikt33-ux/safe-bim-layer/blob/5a3a9201a715a5528c93bed4a5318e2acb32eea7/scripts/archicad_connected_components.py#L549-L575) проверяют source inventory и retained BREP/material/relations. GH-created GUID после baseline → `ACCEPTED_WHOLE_INVENTORY_DRIFT`; изменения удерживаемой геометрии → возможный `RETAINED_NATIVE_GEOMETRY_CHANGED_DURING_BATCH`. Это SOURCE-предсказание, не локальный тест.

## 3. Воспроизводимая процедура подключения — только инструкция, НЕ исполнение
1. **G0 read-only:** зафиксировать AC29 build5101, активный PLN/path/SHA, порт Tapir и `GetProjectInfo`, Tapir `GetAddOnVersion`/registered schema/APX, story index/floorId/elevation, материалы/Favorites/библиотеки. Отдельно Rhino8 exact SR/PID/.3dm/units, GH .gh hash/компоненты, Graphisoft palette port и **именно подключённый GH документ**. `Connected` без этих идентификаторов — FAIL.
2. **G1 offline:** взять отдельное утверждённое двухэтажное задание (meters, абсолютные отметки), `compile_authored_intent` → typed BIM Graph → sourcePlanHash. Нельзя считать готовым, пока фактически не исполнен компилятор; автоматический экспорт произвольного Rhino BREP в authored intent отсутствует.
3. **G2 read-only preflight:** только после принятого исходного receipt использовать существующий connected CLI `--source ... --intent ... --mode preflight --output ...` с `enabled:['beam']` для `CreateBeams`; [код](https://github.com/dvikt33-ux/safe-bim-layer/blob/5a3a9201a715a5528c93bed4a5318e2acb32eea7/scripts/archicad_connected_components.py#L528-L562) привязывает проверку к порту **19724**. Требовать `CONNECTED_NATIVE_PREFLIGHT_PASS`, `modelWriteAttempts=0`, exact inventory.
4. **G3 write:** **НЕ РАЗРЕШЕНО**. Для будущего отдельного санкционированного запуска: только новый scratch PLN, точный `--confirm-plan-hash`, единственный SceneWriter, GH-native writers OFF, без автоматического retry после неопределённой записи.
5. **G4/G5:** нативный readback + GUID/type/story/host/material/BREP, связи SEO, Save/Close/Reopen, независимый IFC BREP/parametric QA и второе исходное задание. `GH idle`, `Sync Changes to GH` или SQLite receipt сами по себе не G4/G5.
6. **Откат:** до G3 — ноль записей; после G3 — проверенная согласованная копия PLN + .3dm + .gh + receipt. **Атомарный rollback трёх приложений NOT_FOUND**.
