## P0: пять практических выводов, отличных от 11Z

**P0-12A — скрытые Archicad Defaults ломают воспроизводимость GH-generated BIM.** [Официальный AC29 GH Guide, Important Notes](https://help.graphisoft.com/AC/29/INT/GC.pdf) устанавливает: параметры, НЕ заданные в GH, наследуют **текущие Default Settings инструмента Archicad на момент создания**. Два одинаковых .gh + одинаковые координаты в разных PLN способны дать разные материалы/композиты/высоты/слои, даже если видимая GH-геометрия совпадает. GH-controlled значения при следующем исполнении GH имеют приоритет над ручной правкой AC; AC-only/uncontrolled значения могут сохраниться. Это не доказательство реального drift у пользователя, а доказанный контракт риска. **Мера:** перед G1/G2 фиксировать атрибуты, tool defaults, Favorites, этажи и библиотечный контекст; для BUILD-01 GH Design writer выключен, SceneWriter — единственный исполнитель. Для потенциального отдельного GH-owned scratch использовать `Favorite Input`/явные `Settings` и readback всех полей, но не считать это атомарной синхронизацией.

**P0-12B — только ОДИН активный GH-документ соединяется с AC одновременно.** [Официальный AC29 GH Guide, File Handling](https://help.graphisoft.com/AC/29/INT/GC.pdf) описывает несколько открытых .gh, но только один `Connect Document to Archicad` за раз; в меню File указаны активный путь (жирным) и соединённый документ (зелёным значком). **Мера G0:** записать **полный путь+SHA .gh**, путь+SHA .3dm и PLN, скрин/статус connected GH document, PID/SR Rhino, build AC, порт; `Connection Active` без identity документов = **G0_BLOCKED**. Не переключать подключённый GH-документ во время операции. Это UI-проверка по документации, не выполненный INSTALLED-тест.

**P0-12C — диалог Archicad приостанавливает Live Connection.** [Официальный AC29 GH Guide, Suspended Connection](https://help.graphisoft.com/AC/29/INT/GC.pdf) сообщает: открытый ожидающий пользовательского ввода диалог в AC приостанавливает передачу, индикатор перестаёт вращаться, downstream GH становится жёлтым; накопленное изменение вступит в силу только после закрытия диалога. **Мера:** `GH solved` или `AC connected` нельзя использовать как `OPERATION_FINISHED`. До завершения операции нужна проверка `no modal dialog` + `no pending GH component` + независимый native readback; при неизвестном состоянии запрещён повтор CREATE.

**P0-12D — Copy/Paste GH-native создаёт неуправляемую копию.** [Официальный AC29 GH Guide, Important Notes](https://help.graphisoft.com/AC/29/INT/GC.pdf): копии GH-generated элементов через AC Copy/Paste **теряют связь с GH-кодом**. У них отдельный жизненный цикл; GH `Select in GH` не является универсальным источником provenance для APA/Tapir/копий. В строгом [connected inventory](https://github.com/dvikt33-ux/safe-bim-layer/blob/5a3a9201a715a5528c93bed4a5318e2acb32eea7/scripts/archicad_connected_components.py#L425-L440) такие дополнительные GUID нарушат whole-inventory preflight. **Мера:** никаких Copy/Paste, GH Design Create, Rhino→AC Speckle Receive и ручных вставок в BUILD-01 после baseline; только read-only инвентаризация и reconciliation при обнаружении новых GUID.

**P0-12E — Rhino Content Cache имеет отдельную опасную команду Purge.** [McNeel Rhino8](https://www.rhino3d.com/features/grasshopper/content-cache/) и [McNeel developer guide](https://discourse.mcneel.com/t/content-cache-updated-guide/181883/1): `Push` отслеживает обновляемый Rhino object, `Pull` возвращает ID, `Bake` без ID может создавать новые объекты, `Purge` удаляет неиспользуемые объекты и определения (слои, материалы, блоки). **Мера:** только `Query Model Objects`/`Pull` для reference; `Push/Bake/Purge` выключены. Rhino Object ID ≠ Archicad GUID; `Push` не решает native BIM.
