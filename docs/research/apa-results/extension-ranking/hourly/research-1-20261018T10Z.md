## Source-level evidence: Tapir grouping
Source: https://github.com/ENZYME-APD/tapir-archicad-automation/blob/1.5.9/archicad-addon/Sources/ElementGroupingCommands.cpp

- CreateGroups iterates requested group definitions, building a list of GUIDs from each entry containing either `elementId` or `groupId`. This permits nested group inputs, rather than only flat element lists.
- Optional `parentGroupId` is read from the group definition.
- Calls `ACAPI_Grouping_CreateGroup(elemGuids, &newGroupGuid, parentGroupGuid == APINULLGuid ? nullptr : &parentGroupGuid)`.
- On error, emits `CreateErrorResponse(err, GetGroupCreationErrorMessage(...))` for that group.
- On success, emits an object containing `groupId`.
- Consequently, outer command completion does not prove every requested group succeeded. A safe APA adapter must correlate response array index to requested group and fail partial success explicitly.
- GetGroupsOfElementsCommand exists in same tagged source. Exact JSON readback output shape NOT_VERIFIED in this pass.

## Group-first high-level architecture implications
1. Construct stable groups from existing element GUIDs; capture groupId and individual errors.
2. Confirm membership using native readback before further transforms.
3. Treat native UI Multiply and public programmatic multiply as separate capabilities; AC29 GUI supports Drag, Rotate, Elevate, Matrix: https://help.graphisoft.com/AC/29/INT/_AC29_Help/030_Interaction/030_Interaction-96.htm .
4. Avoid implementing a duplicate group writer before comparing PR #159/#162 at function-level.
5. For hotlink modules, distinguish node ID, instance ID and child element GUID; repeated instances must not be assumed to retain child GUIDs without readback.
