**Фактически выполнено: 31 содержательная проверка исходников/геометрии, 2 независимых контраудита.** Область: группирование, нативное массовое тиражирование, Hotlink, PDF/DXF→BIM. Не изменялись `main`, PLN, APX, код или установленные дополнения.

## Главные новые результаты

1. **Нативное многокомпонентное копирование уже написано в APA.** `CloneNativeGroupV1` использует один вызов `ACAPI_Element_Edit` с массивом `GS::Array<API_Neig>` для всех элементов группы на каждое смещение. Это подтверждено в `archicad-addon/Sources/NativeGroupCommands.inc`, строки 78–105. Предложение написать второй исполнитель SDK было бы дублированием. Для N=100 элементов и K=2 размещений код предполагает K=2 вызова редактирования SDK; это не доказательство ускорения по времени в 100 раз.
2. **Выявлена логическая слабость функции проверки состава группы.** `APAGroupContainsExactly` (строки 7–10) проверяет равенство длины и принадлежность каждого фактического GUID ожидаемому набору, но не проверяет уникальность фактических GUID. Для `[A,A]` против `[A,B]` функция возвращает `true`; это независимо воспроизведено OFFLINE. Не доказано, что Archicad реально возвращает такие дубликаты.
3. **На другом листе исходного КР найдена повторяющаяся размерная закономерность.** В оригинальном PDF, страница 15 (лист КР-13, блоки 1.9–1.15), все семь цепей имеют разницу 50–51 мм между общим размером и суммой внутренних меток. Для блока 1.13 векторные линии независимо подтверждают смещения **24,994 мм слева и 25,012 мм справа**. Это особенность системы отсчёта чертежа, не доказанная ошибка сохранённого PLN.

## Независимый контраудит A — API, версии и границы безопасности

1. Исправлено предположение прошлого исследования: multi-neig clone уже реализован в APA. Не рекомендовать второй writer.
2. Сопоставлены три уровня: native sourceRef длиной ≥8; внешний PR159 guard исходного PLN и SHA; отдельный SceneWriter. Нельзя выдавать один уровень за другой.
3. Comparator `APAGroupContainsExactly` проверен на OFFLINE контрпримере с повторным GUID; логическая проблема, но нет свидетельства, что SDK создаёт такие ответы.
4. Clone и Move проверяют GUID/группы, PR159 harness проверяет bbox, PR162 новая интеграция не проходила в этом цикле LIVE.
5. Tapir 1.5.10 публичный тег отсутствует, локальный бинарник не исследован; версии upstream нельзя механически приравнивать к установленной.
6. Tapir MIT, ezdxf MIT, pdfplumber MIT, Raster2Seq code MIT; веса Raster2Seq отдельно. Graphisoft DevKit — собственное лицензионное соглашение, не MIT.

## Независимый контраудит B — физические координаты и альтернативы

1. Оригинальный PDF получен по реальному библиотечному файлу, SHA подтверждён.
2. Для нового листа 13 проведены текстовая сумма сегментов, векторная калибровка и независимое чтение PyMuPDF/pdfplumber.
3. Обнаружены семь цепей с дефицитом около 50 мм; 1.13 имеет по 25 мм на краях и 0,573 мм невязку меток/вектора. Нельзя объявлять идеальную нулевую невязку.
4. КР-2022 (Московская область) и АП-2026 (Амурская область) — разные объекты. Смешивание источников запрещено.
5. Реального DXF нет; не проверялись nested INSERT/MINSERT на пользовательском файле. Не выдумывать точность DXF→BIM.
6. Raster2Seq тестирован авторами на Linux/Python3.10.13/Torch2.3.1/CUDA11.8; Windows11/RTX4060 8GB и конкуренция с Twinmotion не подтверждены.
