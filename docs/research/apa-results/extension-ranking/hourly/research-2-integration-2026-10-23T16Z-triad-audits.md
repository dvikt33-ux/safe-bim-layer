# APA №2 — 23.10.2026 16Z — два независимых SOURCE-контрааудита

## Контрааудит A — направленность данных, владение и циклы (метод: dataflow / ownership)
Проверено: PR74 run_project вызывает SceneWriter; Graphisoft GH Live Connection создаёт/обновляет native элементы своим механизмом; Rhino .3dm Hotlink помещает GDL объекты; jSwan даёт JSON, а не native write. Три различных потока нельзя назвать одной двусторонней транзакцией. Контрпример: пользователь вручную изменил APA-owned Wall в Archicad, GH пересчитался, а SceneWriter повторил CREATE — отсутствие общего conflict resolution/ownership не гарантирует сохранение GUID. Даже при штатном GH Synchronize никакой общей APA SQLite записи нет.
Решение: для BUILD-01 native write owner=SceneWriter; GH/ Rhino только staged input/QA; GH native-generating components не запускать для тех же GUID. Удаление/конфликт/timeout → STOP, GetAllElements/readback/SQLite reconcile, новый план и отдельный допуск; никаких автоматических retry/recreate. Источники: https://github.com/dvikt33-ux/safe-bim-layer/blob/f7c37b84b76c040c417ccd58a5543326e50f673a/scripts/archicad_scene_run.py ; https://github.com/dvikt33-ux/safe-bim-layer/blob/f7c37b84b76c040c417ccd58a5543326e50f673a/scripts/archicad_project_accelerator.py ; https://www.graphisoft.com/en-aw/downloads/add-ons/rhino-grasshopper/ ; https://help.graphisoft.com/AC/29/INT/_AC29_Help/120_Interoperability/120_Interoperability-41.htm .
Вердикт: FULL_THREE_WAY_SAME_GUID_SYNC=NOT_FOUND. Нативный BUILD-01 возможен как кандидат ОДНОНАПРАВЛЕННОГО staged задания; без автоматической обратной синхронизации.

## Контрааудит B — контракты и ложноположительная геометрическая приёмка (метод: schema + negative cases)
Проверено: jSwan автоматом сериализует Point3d в X/Y/Z, тогда как PR74 polygonCoordinates/pivotLine ожидает x/y; без явных имён ключей GH→JSON невалиден. Slab Create не принимает buildingMaterialId/structureType; PR74 authored не подаёт favoriteName; один CREATE не доказывает Basic material. PR74 Roof nativeComponents требует pivotLine и не принимает documented MultiPlane без дополнительного qualified route. Native Collision Detection может пропустить скрытые/невыделенные/отключённые от проверки материалы; Model Compare не заменяет GUID/BREP. Контрпример: Rhino Roof Hotlink успешно обновился и Collision Detection показал 0, но в PLN только GDL Object вместо native Roof и материал исключён из collision detection.
Решение: fail-closed проверка JSON tree/units/schema, read-only preflight; Slab material/structureType через independent readback; native GUID/type/BREP обязательны; QA settings фиксировать; GDL provenance хранить отдельно от native GUID. Источники: https://github.com/andrewheumann/jSwan ; https://github.com/dvikt33-ux/safe-bim-layer/blob/f7c37b84b76c040c417ccd58a5543326e50f673a/examples/accelerator/model-first-building.json ; https://github.com/dvikt33-ux/safe-bim-layer/blob/f7c37b84b76c040c417ccd58a5543326e50f673a/scripts/archicad_authored_native_plan.py ; https://github.com/dvikt33-ux/safe-bim-layer/blob/f7c37b84b76c040c417ccd58a5543326e50f673a/scripts/archicad_project_accelerator.py ; https://help.graphisoft.com/AC/29/INT/_AC29_Help/080_Collaboration/080_Collaboration-64.htm .
Вердикт: GH_JSON_SOURCE_CANDIDATE, NATIVE_MATERIAL_AND_BREP_ACCEPTANCE_NOT_RUN. Отсутствие коллизий/успешный JSON сериализатор не являются BUILD-01 ACCEPTED.

Оба контрааудита основаны на SOURCE, без новых OFFLINE/INSTALLED/LIVE тестов. MODEL_MODE_NOT_VERIFIABLE.
