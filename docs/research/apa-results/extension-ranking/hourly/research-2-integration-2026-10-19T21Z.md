## Новые находки 21Z — два fail-closed контракта

**Publisher, критический сценарий:** [Tapir tag 1.5.9 NavigatorCommands.cpp, строки 7–101](https://github.com/ENZYME-APD/tapir-archicad-automation/blob/1.5.9/archicad-addon/Sources/NavigatorCommands.cpp), blob `df359f7bdf94f9004617cf616c6d38cb98be08ae`. `PublishPublisherSet` принимает **обязательный `publisherSetName`**, **необязательный `outputPath`**, **необязательный `selectedNavigatorItemIds`**. В C++ указатель `selectedLinksPtr` изначально `nullptr`; если список задан, но **пустой**, он остаётся `nullptr` и передаётся в `ACAPI_ProjectOperation_Publish`. Следовательно, пустой whitelist **не является безопасной пустой публикацией**: он может включить публикацию всего набора. Это SOURCE-вывод из пути вызова, не LIVE-воспроизведение. **Решение:** APA должен отклонять отсутствующий/пустой список GUID до команды; удостоверять GUID набора по read-only инвентарю, совпадение имени, отсутствие дубликатов имён, локальный sandbox outputPath и запрет traversal/UNC по политике. **Не запускать Publish**. Дополнительно `GetPublisherSetNameGuidTable` сопоставляет **имя→GUID** и пропускает неуспешное чтение набора; отсутствие/дублирование имени — `UNKNOWN`, не доказательство единственности.

**DXF XCLIP, критический сценарий:** [ezdxf v1.4.5 disassemble.py, строки 542–579](https://github.com/mozman/ezdxf/blob/v1.4.5/src/ezdxf/disassemble.py), blob `5f3413710f05c81193a381a69d83538ecc5b86ab`: `recursive_decompose` **не применяет XCLIP**, отдаёт геометрию вне отсечения; при MINSERT вызывает `multi_insert()`. [XClip v1.4.5](https://github.com/mozman/ezdxf/blob/v1.4.5/src/ezdxf/xclip.py), blob `3c89d5d375a4b4acff988c156f01e8105b3b3139`, предоставляет `has_clipping_path`, `is_clipping_enabled`, `is_inverted_clip`, `get_wcs_clipping_path`. [Готовые геометрические clipper-классы](https://ezdxf.readthedocs.io/en/stable/math/clipping.html): `ConvexClippingPolygon2d`, `ConcaveClippingPolygon2d`, `InvertedClippingPolygon2d`, `clip_line/clip_polyline/clip_polygon`. **Готовый единый доказанный pipeline для полного XCLIP→все типы DXF→source handle НЕ НАЙДЕН.** Минимальный недостающий адаптер: обнаружение XCLIP на исходном INSERT, захват исходного handle+MINSERT индекса, получение WCS polygon, перевод поддерживаемых примитивов в clipper и typed `UNSUPPORTED` для сложных случаев (3D/ACIS/XREF/inverted без outer bounds). Не объявлять raw разложение «видимой геометрией». Утилиты clipper не равны готовой полной обработке всех типов DXF.

## Сравнение путей и выбор

**Publisher:** A) напрямую `PublishPublisherSet` по имени — готово, но `selectedNavigatorItemIds=[]` даёт `nullptr` и может затронуть весь набор. B) existing Router → read-only enumeration `ACAPI_Navigator_GetNavigatorSet` / children → exact GUID whitelist → Tapir Publish только после отдельного разрешения. **Выбран B, пока только SOURCE**. При отсутствии доступного полного GUID read-only inventory — **NOT_FOUND/DEFER**, а не публикация по имени.

**DXF:** A) `recursive_decompose` сразу в C1 — быстро, но XCLIP игнорируется. B) source INSERT handle → `XClip.get_wcs_clipping_path` → готовые ezdxf math clippers → typed primitives; сложные случаи UNKNOWN. **Выбран B только для ограниченного 2D**, полный готовый универсальный коннектор NOT_FOUND. Альтернатива C) drawing frontend с clipping — возможный способ визуальной проверки, но не подтверждён как семантический source-handle-preserving экспорт; не считать эквивалентом.

**IFC/Hotlink:** A) существующий Router+Tapir для базового чтения, но []/"" неоднозначны. B) MultiConn/MCP — второй transport и риск auto-switch. C) существующий Router → ограниченный SDK29 read-only Bridge → штатный API → тот же BIM Graph. **A для доказанных команд; C только для недостающих ошибок/cached/proxy. B отклонён**.
