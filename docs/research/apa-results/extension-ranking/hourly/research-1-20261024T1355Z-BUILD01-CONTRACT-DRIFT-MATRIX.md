## 1. Новые факты, значимые для G1/G2
**F-R1-01 / существенный контрактный дрейф для окон и дверей.** В зафиксированном APA-каталоге `schemas/tapir-live-1.5.10/tapir-scene-live.json`, blob `e8ad53b6ea7c19dc34cbdcb723a79be995639cd7`, оба `CreateWindows` и `CreateDoors` объявляют поле `libraryPartName` (а также `favoriteName`). В upstream Tapir **immutable tag 1.5.9**, `archicad-addon/Sources/ExtendedElementCommands.cpp`, blob `bd5cd197e9ad2c0db9e40c1baff877bbdcbfae30`, схемы Windows (стр. 3865–3905) и Doors (около 4039–4080) НЕ содержат `libraryPartName`; поиск этой строки во всём файле дал 0 совпадений. Следовательно, frozen schema APA нельзя считать доказанной схемой upstream 1.5.9, а заявленную локальную 1.5.10 — тождественной upstream без `GetAddOnVersion`, зарегистрированного schema и SHA APX. **G2 BLOCKED_LOCAL_SCHEMA**. Не делать вывод о том, что поле не поддерживается пользовательским APX: он не исследован.

**F-R1-02 / поправка по оконным маркерам.** Upstream issue #551 (15.08.2026) документировал сброс marker defaults в Tapir 1.5.7/1.5.8. Но в immutable tag **1.5.9** исходник `PrepareWindowOrDoorDefaults`, строки 322–389, **уже содержит исправленную ветку**: сохранение параметров marker, полученных через `ACAPI_Element_GetDefaultsExt`, если они непусты; fallback к factory marker и pen 166 только при пустых marker defaults. Поэтому утверждение «Tapir всегда сбрасывает штамп» для 1.5.9 неверно. Для локальной 1.5.10 эффект **INSTALLED_NOT_VERIFIED**. Source: https://github.com/ENZYME-APD/tapir-archicad-automation/issues/551 и https://github.com/ENZYME-APD/tapir-archicad-automation/blob/1.5.9/archicad-addon/Sources/ExtendedElementCommands.cpp#L322-L389 .

**F-R1-03 / разрыв проверок отверстий.** Frozen schema `CreateSlabs` содержит `holes`, `polygonArcs`, но действующий `SceneWriter.verify_readback` для `CreateSlabs` (стр. 400–425) сравнивает только внешний `polygonOutline`, уровень, толщину, тип/материал; **отдельного сравнения hole loops здесь нет**. Аналогично schema `CreateRoofs` содержит `holes`, а `ConnectedComponent.verify` для Roof (стр. 184–196) сверяет outer polygon, pitch, pivot, материал, но не hole loops. Это НЕ означает, что Tapir не создаёт отверстия: это означает, что **данные два конкретных verifier не доказывают их сохранение**. Для BUILD-01 holes оставить OPTIONAL/NOT_ACCEPTED, пока не найден существующий дополнительный readback или BREP-контроль. Источники: immutable PR74 `scripts/archicad_scene_run.py` blob `ca91c1cfc41cee763c62d1f3a70337d74fbafd53`; `scripts/archicad_connected_components.py` blob `c5a99f59a90369ff622807574677cf11ca0a2225`.

**F-R1-04 / минимум для окон и дверей строже upstream schema.** В frozen schema для `CreateWindows/CreateDoors` обязательны только `ownerWallId` и `centerOffset`. Но `SceneWriter.verify_readback` (стр. 456–464) без проверки наличия обращается к `expected['width']`, `expected['height']`, `expected['sillHeight']`, `expected['centerOffset']`. Поэтому **на текущем APA-маршруте** эти четыре поля должны присутствовать явно, даже если upstream schema допускает их наследование. Это дополнительное требование verifier, не требование Tapir API. Хост только через `$createdGuid` уже созданной стены (SceneWriter, стр. 295–317), не через произвольный GH/Rhino ID.

**F-R1-05 / сохранение нативной кровли.** Upstream Tapir 1.5.9 `CreateRoofsCommand::Execute` (стр. 4720–4815): `pivotLine` задан → `API_PlaneRoofID`; отсутствует → `API_PolyRoofID`; `angle` допустим только с pivotLine; `levels/eavesOverhang` только без него. `ModifyRoofs` (стр. 5808–5850) поддерживает только `API_PolyRoofID`. Однако PR74 `compile_authored_intent` (стр. 294–303) требует `pivotLine`, Basic, `buildingMaterialId`; `ConnectedComponent.verify` (стр. 184–196) требует `SinglePlane`. В `SceneWriter.EXTENDED_WRITES` (стр. 94–98) есть `CreateRoofs` как opt-in, **нет `ModifyRoofs`**. Итог: `POLYROOF_UPSTREAM_SOURCE_FOUND / APA_NATIVE_ROUTE_NOT_FOUND`. Нельзя писать напрямую в PLN в обход SceneWriter.

## 3. Два обязательных отрицательных сценария для G1/G2 (ПРОЕКТ ТЕСТОВ, НЕ PASS)
**NEG-01 — нулевая длина Wall.** Вход `CreateWalls` с одинаковыми `begCoordinate` и `endCoordinate`, но положительными `height/thickness`. Frozen schema проверяет типы/required, не доказывает ненулевую длину. Требование: compiler/geometry guard должен отказать **до** нативной записи; если не отказывает, пометить `OFFLINE_GAP_ZERO_LENGTH_WALL`, а не отправлять Tapir. Запуск не производился.

**NEG-02 — отсутствующая библиотечная часть или Favorite.** Для Window/Door задать заведомо несуществующее `favoriteName` или библиотечную часть в изолированном mock/spec; требуется `LIBRARY_BINDING_UNRESOLVED` до native CREATE. Не считать принятую schema гарантией существования объекта. Upstream #399 отдельно демонстрирует `Failed to resolve favoriteName` и ошибку `CreateExt` на AC29 JPN; локальный build5101/язык не проверен. Запуск не производился.

## 4. Минимальный BUILD-01 без расширения writer
**Контракт G1:** один новый 2-этажный authored intent `apa-authored-project/1`, метры, явно связанные story indices/elevations; на каждом этаже наружные Wall и Slab; минимум по одной нативной Window и Door с `$createdGuid` host; одна **SinglePlane Roof** на верхнем уровне с явными `pivotLine,angle,structureType=Basic,buildingMaterialId,thickness`; Column только при наличии точного native contract. Все library parts/Favorites, building material GUID, floorId, target scratch path из реального read-only G0. Для G1 допускается только offline compile, без native dispatch.

**Не включать в минимальный G1:** PolyRoof/ModifyRoofs, slab/roof holes, произвольный NURBS→native Roof, новый GH→PR74 bridge, параллельную GH native запись, неподтверждённые лестницы/инженерные элементы. Эти возможности отдельные эксперименты, не препятствие базовой сборке.

**Контроль:** `GetStories` + `GetAttributesByType` + `GetAvailableLibraryParts`/Favorites (read-only) → typed BIM DAG `archicad_bim_graph.compile_graph` → `sourcePlanHash` → только после разрешения один `SceneWriter` → `GetDetailsOfElements`, GUID/story/host/material, отдельная геометрия/BREP → GuardedSave/Close/Open → независимый readback. Нельзя утверждать, что G1 или G4 уже выполнены.
