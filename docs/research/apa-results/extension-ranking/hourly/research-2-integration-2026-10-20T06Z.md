## Новые относительно предыдущего цикла выводы

1. **PDF-host resolver частично УЖЕ СУЩЕСТВУЕТ.** [PR #131](https://github.com/dvikt33-ux/safe-bim-layer/pull/131) содержит `_v2_host_batch`, проверку GUID host, перекрытия проёмов и `G._hosted_fit_errors`. Следовательно, NOT_FOUND относится только к автоматическому **PDF mark→выбор Wall GUID/centerOffset**, а не ко всей hosted-валидации. Переиспользовать этот валидатор; не писать второй.
2. **Tapir error 4009 — историческая регрессия с готовым upstream-исправлением.** В tag1.5.9 `CommandBase::GetResponseSchema()` намеренно пуст, `GetRawResponseSchema()` остаётся для документации. [Issue #483](https://github.com/ENZYME-APD/tapir-archicad-automation/issues/483) / [PR #544](https://github.com/ENZYME-APD/tapir-archicad-automation/pull/544) объясняют исправление. Не считать старую ошибку доказанной для tag1.5.9; отдельно проверить реальный локальный бинарник.
3. **Windows/Doors BADDATABASE — готовое исправление уже в Tapir1.5.9.** `SwitchCurrentDatabaseToFloorPlan` с `GS::OnExit` присутствует в tagged C++ для обеих команд; [upstream PR #559](https://github.com/ENZYME-APD/tapir-archicad-automation/pull/559) фиксирует происхождение. Требуется OFFLINE/разрешённый LIVE fixture с 3D/планом/другим этажом; не разрабатывать конкурирующий writer.
4. **IfcDiff0.8.5 по умолчанию проверяет ТОЛЬКО geometry:** `self.relationships=relationships or ["geometry"]`, хотя более новая онлайн-документация описывает attributes+geometry. Явно передавать `["attributes","geometry","property","container","type"]` по нужному профилю. При этом `IfcFeatureElement` исключается из множества элементов: openings проверять отдельной связью, а не объявлять полный diff.
5. **IfcOpenShell уже даёт all-peer element helpers** `get_connected_to/get_connected_from` (tag0.8.5), но они возвращают элементы, а не каждый GUID `IfcRelConnectsPorts`. Для доказательного графа отношений обходить `ConnectedTo/ConnectedFrom` и сохранять relation GUID; нового IFC-движка не требуется.
