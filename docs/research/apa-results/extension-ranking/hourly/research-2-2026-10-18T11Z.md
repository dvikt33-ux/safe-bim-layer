## Ключевой технический вывод

Нативный `RoutingElementDefault::Place` принимает `map<UInt32,RectangularCrossSectionData>` и `map<UInt32,CircularCrossSectionData>`. В Tapir 1.7.1 обе карты пусты; Modify меняет все сегменты. Нативный `RoutingSegment::Modifier` адресует один сегмент, `RoutingNode::Modifier` задаёт TransitionDefault, `Transition` выдаёт ID обоих портов, `PortBase` проверяет физическое соединение. Это реальный **GAP** существующего Tapir, а не повод писать новый SceneWriter. Двухпортовый переход круг↔прямоугольник НЕ протестирован: A11.S10 BLOCKED.

Граф: AC29+MEP license → DevKit29.3100+Graphisoft license → Place(rectMap,circMap) → RoutingNode/TransitionDefault → Transition ports → PortBase physical check. Tapir MIT JSON Place({}, {}) не использует карты. Publisher → set name/GUID → непустой выбор → изолированный каталог → manifest. SAF2.2 → C# SDK1.7.3 → отсутствующий SAF→PyNite adapter. СП20/СП50 → applicability/revision gate → инженерная приёмка.

CMake README ошибочно пишет VS2019/v143, Microsoft — VS2019/v142 и VS2022/v143. SAF schema 2.2.0 ≠ SDK package 1.7.3. EPPlus 4.5.3.3 LGPL, версии 5+ иной режим.
