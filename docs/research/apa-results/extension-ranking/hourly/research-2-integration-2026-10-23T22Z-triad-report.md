## P0 — два новых независимых риска, требующих инженерного контроля до G3/G4

### R22-01 / P0 / библиотечные детали: удаление GH-компонента может сломать BIM Objects
В **официальном руководстве Graphisoft именно Archicad 29**, обновлённом 22.01.2026, раздел *Create New Library Part* (стр.45 по индексированному тексту), подтверждено: GH Object Settings → Create New Library Part помещает новый объект в **Embedded Library**. Если удалить GH Object Settings или переключить его на *Use existing Library Part*, созданная библиотечная деталь удаляется. Уже размещённые экземпляры становятся **Missing Objects**. Изменение входной Geometry обновляет одну деталь, в которую GH объединяет несколько shapes. Источник: https://help.graphisoft.com/AC/29/INT/GC.pdf. Это реальный официальный механизм, но **не универсальный native BIM/GDL bridge** для стен, перекрытий, дверей, окон; не обеспечивает безопасный GUID-preserving edit для APA-owned элементов. В BUILD-01 GDL для Door/Window/Object должно быть из разрешённой существующей библиотеки; GH-generated Library Part — только отдельный не-Apa-owned эксперимент после отдельного допуска. **Никакой LIVE проверки.**

### R22-02 / P0 / скрытый hotlink update при IFC Publisher
В AC29 **Data Safety & Integrity** параметр *Hotlink Update* имеет три режима: Ignore, Check and ask (default), Check and update automatically. При последнем режиме во время **document output, включая Publish**, Archicad может обновить все модули с изменёнными источниками. Важнее: эта настройка хранится в **Preferences**, **не в PLN**. Следовательно, одинаковый PLN+planHash на двух рабочих местах не гарантирует одинаковый IFC, если source Hotlink/Preferences отличаются. Источник: https://help.graphisoft.com/AC/29/INT/_AC29_Help/140_UserInterfaceDialogBoxes/140_UserInterfaceDialogBoxes-15.htm; статусы Modified/Missing/OK и Update then Compare: https://help.graphisoft.com/AC/29/INT/_AC29_Help/080_Collaboration/080_Collaboration-60.htm. Требуемое условие G4: зафиксировать режим и source fingerprints, запретить несанкционированный Auto, выполнить до/после native inventory, остановиться при unexpected change. **Не менять настройки без разрешения.**

### R22-03 / исправление прежней формулировки «только ручной Send Changes»
Руководство AC29 прямо говорит: при включённом **Sync Changes to GH** связанные Parameter Components в GH обновляются **непрерывно и автоматически** после изменений Archicad. При отключении — нет. Однако это AC→GH параметрическое чтение; не Rhino document native identity, не журнал APA и не полная двусторонняя запись. *Lock/Unlock GH Elements* позволяет временно менять GH-generated объекты в AC, но при повторном Lock GH-controlled свойства возвращаются к GH; свойства, недоступные в GH (пример материал CW Panel), сохраняются. *Select in GH* находит компонент-источник. Источники: https://help.graphisoft.com/AC/29/INT/GC.pdf. Ранее формулировка «Send Changes обязательно вручную» была чрезмерной; **исправлено на условную автоматическую передачу параметров**, не на full 3-way.
