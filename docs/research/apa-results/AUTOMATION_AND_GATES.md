# APA — проект круглосуточного исследовательского конвейера

**Статус на 2026-10-10: NOT_RUNNING / НЕ РАЗВЁРНУТ.** Этот документ — архитектура и критерии включения, а не утверждение о существовании фонового агента. Сеанс ChatGPT и запуск Deep Research не гарантируют постоянное выполнение или прямую запись в GitHub.

## Уточнение способа выполнения владельцем — 2026-10-10

**Выбранный режим:** исследовательская работа в **обычных чатах ChatGPT**, а не в Deep Research; сохранение каждого результата обычным чатом через GitHub connector в canonical hub, commit + readback. Deep Research исключён из стандартного конвейера и требует отдельного прямого согласия. Существующие запланированные GPT-проходы, если доступны, должны следовать тому же контракту публикации; факт их расписания/работы надо проверить, а не предполагать.

**Предел:** обычный чат сам по себе не выполняется непрерывно между обращениями. Для 24/7 нужен подтверждённый механизм запуска обычных проходов и реальный GitHub write на каждом запуске. Не подменять его Deep Research, не обещать постоянную работу без наблюдаемых коммитов/heartbeat. Текущий статус до проверки — **NOT_RUNNING**.

## Требуемая система

Постоянно доступный **scheduler/runner** → берёт один S-ID из [RESEARCH_QUEUE](RESEARCH_QUEUE.md) → читает ранее опубликованные доказательства → исследует и валидирует → создаёт Markdown → GitHub commit → readback → обновляет реестр/очередь/статус → записывает heartbeat и ошибку при сбое → повторяет цикл.

Состояния запуска: SCHEDULED → RUNNING → EVIDENCE_READY → GITHUB_WRITING → READBACK_VERIFIED → INDEX_UPDATED → DONE_PUBLISHED. Ошибки: SOURCE_UNAVAILABLE, NOT_VERIFIED, GITHUB_PUBLISH_BLOCKED, RATE_LIMITED, RUNNER_OFFLINE. Ни одна ошибка не должна молча исчезать.

## Два разных процесса — не путать

**A. Детерминированный контроль (возможен без LLM):** периодически проверять целостность ссылок, SHA, статус очереди, stale tasks, наличие новых коммитов, рассогласование индекса и файлов, отсутствие heartbeat. Можно реализовать GitHub Actions или на отдельном сервере, но такой контроль **не выполняет интеллектуальное исследование**.

**B. Исследовательский исполнитель (требует отдельной реальной интеграции):** чтение исходников и документации, критический анализ, поиск альтернатив, верификация, формирование отчёта. Нужен постоянно доступный инструмент, которому действительно разрешены чтение источников и GitHub write. Наличие Deep Research в чате **не доказывает** его доступность по cron или способность публиковать в GitHub.

## Почему 24/7 ещё не включено

1. Нет подтверждённого постоянно работающего агента, который одновременно умеет исследовать и писать в GitHub.
2. Deep Research выводит отчёт в собственном виджете; прямой автоматический push из него не подтверждён.
3. GitHub Actions scheduled workflows обычно должны находиться в default branch для cron. Изменение main запрещено текущими ограничениями, поэтому не устанавливать расписание туда без отдельного решения.
4. Нельзя обещать бесплатную непрерывную работу модели, если отсутствует доступный разрешённый runtime. Никаких платных API и скрытых расходов.

## Минимальный путь к реальному развёртыванию

### Gate 1 — безопасная публикация
- Подтвердить минимально необходимый GitHub write scope, отдельную учётную запись/App, защиту от повторных коммитов и проверку readback.
- Выполнить один изолированный запуск без изменения main, PLN, APX и кода.
- Проверить, что один run создаёт ровно один уникальный Markdown, затем обновляет реестр и текущий статус.

### Gate 2 — периодический запуск
- Выбрать уже разрешённый всегда доступный runner; задать период, например каждые 2 часа, и max concurrency = 1 для обновления индексов.
- Добавить retry с backoff, idempotency key по S-ID/source SHA, timeout, ограничение объёма данных и затрат.
- Запустить 2 цикла подряд с подтверждёнными GitHub commit и readback.

### Gate 3 — доказанная работа 24/7
- Heartbeat: дата/время, S-ID, outcome, commit SHA, next_run.
- Watchdog: если интервал превышен, явный статус RUNNER_OFFLINE и оповещение.
- После 24 часов наблюдений зафиксировать uptime, количество проверенных источников, новых подтверждённых выводов, публикаций и ошибок. Только после этого можно писать 24H_VERIFIED.

## Варианты, требующие решения

| Вариант | Плюсы | Ограничение |
| --- | --- | --- |
| Уже работающий локальный/серверный агент + GitHub App | Может работать непрерывно, не требует main для scheduler | Нужен постоянно включённый хост, права, разрешённый исследовательский runtime |
| GitHub Actions | Доступный cron и прозрачные логи | Для schedule нужен workflow в default branch; исследовательскую модель сам не предоставляет |
| Deep Research в ChatGPT | Глубокий отдельный исследовательский проход | Нет подтверждённого 24/7 cron или автоматического GitHub push |
| PR #21 Slack coordinator | Может собирать события и уведомлять | По сохранённому реестру daemon NOT_DEPLOYED; координация ≠ исследовательский агент |
