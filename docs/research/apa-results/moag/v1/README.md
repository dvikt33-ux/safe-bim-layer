# МОАГ — реестр исходных свидетельств и топологический граф v0.1

**Статус:** IN_PROGRESS / PARTIAL CORPUS; не архитектурный чертёж, не BIM-модель и не согласованная геометрия.
**Подзадача:** [#176](https://github.com/dvikt33-ux/safe-bim-layer/issues/176). **Исходная среда APA:** feature/apa-capability-auto-discovery-20261017 (существующие `archicad_bim_graph.py`, DynamicCommands, SceneWriter).

## 1. Что сохраняется навсегда

- `evidence_graph.json` — машиночитаемые узлы пространств, инженерных систем и кольцевых маршрутов; ребра *с типом отношения*, источниками и степенью проверки.
- `../` — только проектная тема «Живые» Варвары Еналь, исходный МОАГ, а не другие станции из книг III–IV.
- Источники — URL на **главу/страницу**. Цитаты массово не копировать: хранить локаторы, переформулированный пространственный признак и короткое объяснение. В дальнейшем желательно сохранять номера книжных страниц конкретного издания.
- Форму и функции, найденные в одном фрагменте, нельзя автоматически считать совместимыми с эпизодом после перестройки/блокировки уровня. Для будущей версии ввести `story_phase`/состояние сектора и отдельный конфликтный реестр.
- Специально **НЕ ЗАДАНЫ** пространственные координаты и численные размеры: все поля `position` сейчас `null`, `geometry_gate=NOT_AUTHORIZED`. Два одинаковых кольца не означают одинаковый радиус.

## 2. Топологический граф ≠ конструктивный граф зависимостей

**G1 — пространственная сеть** допускает кольца и циклы: `contains`, `includes`, `route_to`, `access_to`, `stairs_to`, `connects_vertical`, `overlooks`, `under`, `same_ring_logic`. Каждый тип имеет конкретную семантику. Рёбра `TOPOLOGY_INFERRED` и `RECHECK_REQUIRED` нельзя превращать в геометрические ограничения без аудита. `under` — вертикальная зона, не XY совпадение центроидов; `same_ring_logic` — подобие кольцевой структуры, не равенство диаметров.

**G2 — DAG порядка строительства** (экспортируется валидатором):
- P0 — извлечение доказательств и разрешение противоречий;
- P1 — топологические узлы, относительное положение, типизированные пути;
- P2 — схематический каркас в одной общей локальной СК (на этой стадии *только* утверждённые габариты);
- P3 — численные/параметрические геометрические ограничения;
- P4 — единая несущая структура и узлы ядра;
- P5 — ограждения, перекрытия, стены/перегородки;
- P6 — отверстия, двери/окна, проходки;
- P7 — отделка и облицовки;
- P8 — инженерные сети и навесное оборудование.

**Важно:** пользовательский порядок «сначала каркас, потом стены» реализуется как P4 до P5. Инженерные магистрали как *резервы и зоны* нужно предусмотреть уже в P2–P4, хотя детальное оборудование появляется в P8.

## 3. Доказательный контракт

У каждого узла и ребра:
- `id` — постоянный ключ, не меняется после появления версии;
- `source_ids` — ссылки на тексты, обязательны;
- `text_basis` / `claim` — точный смысл авторского описания без выдуманной геометрии;
- `state`: `TEXT_DIRECT`, `TOPOLOGY_INFERRED`, `RECHECK_REQUIRED`, `HYPOTHESIS`;
- никакие координаты не разрешены, пока `geometry_gate != APPROVED` и не появится *отдельный протокол геометрической приёмки* с базой, масштабом, источниками и версиями.
- `APPROVED` — не право писать PLN; требуется отдельный native SceneWriter gate и пользовательское подтверждение.

Критические неразрешённые вопросы записаны в `questions`. Статус `books_exhaustively_checked=0` — буквально означает, что **ни одна книга не прошла полноценную постраничную разметку**. Источниковые данные *seed*, а не полный текстологический корпус.

## 4. Реальная интеграция с APA

**Сделано в v0.1:** автономный, воспроизводимый **офлайн вход для APA**, который валидирует доказательную сеть, выдаёт `APA-MOAG-TOPOLOGY-SNAPSHOT/0.1` и G2. Никаких новых Tapir/Archicad транспортов, собственных writer или side-effect pipeline. Никаких native mutation.

**Следующий адаптер (НЕ сделан):** `topology snapshot -> resolved geometry constraint model -> archicad_bim_graph.py operation plan -> existing archicad_dynamic_commands.py -> existing SceneWriter/SQLite -> native readback`. Нельзя передавать узлы помещений сразу в `CreateWalls` по произвольным координатам; сначала `APPROVED_GEOMETRY_V1`, তারপর подготовка нативных операций в существующем API и повторная проверка перед *каждой* записью.

При массовой геометрии пользоваться существующими нативными batch/group/hotlink возможностями, но только после geospatial checks и на изолированном тестовом PLN. Не проводить проверки на BDD доме или пользовательских активных PLN.

Команды (на полном checkout APA):
```bash
python tools/moag_topology/validate.py docs/research/apa-results/moag/v1/evidence_graph.json --mode verify
python tools/moag_topology/validate.py docs/research/apa-results/moag/v1/evidence_graph.json --mode snapshot --out /tmp/moag-topology-snapshot.json
python tools/moag_topology/validate.py docs/research/apa-results/moag/v1/evidence_graph.json --mode dot --out /tmp/moag.dot
python -m unittest discover -s tests -p 'test_moag_evidence_topology.py' -v
```
`dot` показывает отношения и **НЕ** задаёт метрические расстояния, углы, истинную ориентацию или радиусы. `--out` отказывается перезаписывать существующий файл.

## 5. Первый исследовательский проход и находки

1. Книга I, «Таис. Дорога на Третий уровень»: главные коридоры и вентиляционные шахты трёх уровней повторяют схему. Базы Нижнего расположены ниже кают Второго, замыкаются в малом внутреннем круге; внешний круг тоже существует, значительная часть Нижнего тогда не исследована. [Глава](https://knigalit.ru/avtori/varvara-enal/book2364884/chitat/?page=6).
2. Книга I, «Таис. Закон»: Оранжевая магистраль внешняя, Зелёная внутренняя; между ними есть переход; через Главную площадь можно выйти к шестым туннелям, от которых есть короткий проход к магазинчикам. [Глава](https://knigalit.ru/avtori/varvara-enal/book2364884/chitat/?page=4).
3. Книга I, «Эмма. Экзамен»: жилая галерея второго этажа расположена над Главной площадью с садом и фонтаном. [Глава](https://knigalit.ru/avtori/varvara-enal/book2364884/chitat/?page=3).
4. Книга I, «Эмма. Я не хочу умирать»: внутри Третьего уровня детский блок с высоким залом и кувезами, коридоры с улучшенной отделкой; после него описывается круглый зал отдыха. [Глава](https://knigalit.ru/avtori/varvara-enal/book2364884/chitat/?page=15).
5. Книга II, ангарный обход: отдельный сектор Нижнего уровня, коридор с полукруглым сводом; высокие операторские кабины, раздвижная дверь с биометрическим замком, одноместные катера, отдельный шлюз. [Эпизод](https://loveread.ec/read_book.php?id=53370&p=14).
6. Поздние состояния не перепутать: после установления управления станцией Нижний уровень может быть повторно заблокирован. Не заменять этим первоначальную планировку. [Книга II](https://loveread.ec/read_book.php?id=53370&p=1).

## 6. Задачи следующей редакции (принимаются при аудите)

- Отметить **каждое** пространственно значимое высказывание во всех четырёх книгах: `book / chapter / scene / speaker / precise locator / room / observed state`.
- Связать маршруты героев как последовательность точек и относительных поворотов; не преобразовывать «справа» без направления взгляда и начала координат.
- Найти сцену взломанного лона и карты первого уровня; сохранить конфликт со словами о недоступных планах как разные стадии/права доступа.
- Установить ангарный маршрут, группировку кают бывшего спецназа, связи между базами и проходами через служебные зоны.
- Ввести ревизионную геометрию: исходная ось, кольца, ярусные высоты, касания, запрет пересечений, единые планы/разрезы/3D.
- После внешнего аудита (не только тестов автора) оформить `APPROVED_GEOMETRY_V1` с владельцем решения.

## 7. Приёмка v0.1

Граф без неизвестных идентификаторов и без циклов **в отношении содержания** (`contains/includes`). В маршрутах циклы допустимы. Все источники по HTTPS, домены и главы проверяются вручную. Любые несогласованные метрики блокируются. Вердикт `geometry_ready=false`, `native_write_allowed=false`. Это машинная проверка целостности, а не независимое литературоведческое подтверждение каждого отношения.

**Галерея и комнаты в верхней части закрытого круглого зала:** книга I, стр. сайта 17: железный мостик под самым потолком, идущий полукругом по половине зала, частично разрушенная лестница, дверь с мостика → комната ручного управления шлюзами → следующая дверь → жилая комната с раковиной и лучевой печью. Это не один зал, а связанная двухъярусная пространственная группа. [Эпизод](https://knigalit.ru/avtori/varvara-enal/book2364884/chitat/?page=17).

**Операторские ангаров** на другом участке расположены почти под потолком; связь через лестницы. Отличать частичные верхние площадки от полноценного второго этажа. Глобальных уровней названо три; локальных отметок в Нижнем блоке больше. Точное количество сплошных палуб, отметки z, площадь и «самый нижний — самый большой» текстом пока не доказаны.

Дополнительный машинный контракт: [vertical_strata.json](vertical_strata.json) — вложенные локальные ярусы с **относительными Z-связями** и неопределённой протяжённостью. В реестре известные связи помечены TEXT_DIRECT, геометрия не утверждена. Нельзя генерировать 4 диска или плиты только из предположения о двух этажах.
