## ONE-PASS: одно чтение страницы, классификация и доказательства вместе

Для каждой ещё не обработанной веб-страницы выполняется один последовательный проход:

1. Открыть страницу первоисточника один раз; прочитать весь литературный текст, исключая футер сайта. Учитывать контекст уже обработанных страниц.
2. В этом же чтении определить локацию и рассказчика, отметить смены сцен и временных линий, сны, воспоминания, гипотезы персонажей, иллюстрации и голограммы. Границы глав фиксировать по заголовку и оглавлению по мере их появления; если заголовок делит страницу, разметить оба фрагмента.
3. Если фрагмент на МОАГе — сразу извлечь все пространственные, архитектурные, конструктивные, инженерные и маршрутные сведения. Для внешнего фрагмента проверить диалоги, воспоминания, карты и дистанционные сведения о станции; нерелевантный фрагмент отметить как внешний. Смешанные страницы классифицировать по фрагментам.
4. Для неопределённого места не исключать страницу: сохранить классификацию `UNCERTAIN` и полноценно записать доступные доказательства с явной оговоркой.
5. В рамках того же чтения обновить `pages/*.json`, `page_observations.json`, `chapter_screening.json`, маршруты и ссылки на существующие узлы. Не выдумывать отсутствующие размеры, координаты, этажи или идентичность помещений.
6. После сохранения перейти к следующей странице. Не читать главу сначала для фильтрации и повторно для извлечения. Не создавать отдельный пересказ сюжета и не повторять полный анализ при каждом обновлении графа.
7. Инкрементально использовать накопленные записи и ускоритель APA для кэширования/пакетной обработки и графового синтеза. Структурные проверки выполнять по данным и ссылкам, не подавая полный литературный текст модели повторно.
8. Повторно открыть уже обработанную страницу только с записанной причиной: противоречие, недостающая доказательная деталь, сомнительное исключение или конкретный пробел. Выборочные текстологические аудиты допустимы; полный повторный проход — нет.
9. Отдельно вести метрики: контекстно проверенные страницы, страницы с полной доказательной разметкой, внешние страницы, исключённые после проверки, неразрешённые классификации и повторно открытые страницы/число повторных открытий.

Ключевой цикл: **ОДНА СТРАНИЦА → ОДНО ЧТЕНИЕ → КЛАССИФИКАЦИЯ + ДОКАЗАТЕЛЬСТВА → СОХРАНЕНИЕ И ОБНОВЛЕНИЕ СВЯЗЕЙ → СЛЕДУЮЩАЯ СТРАНИЦА.**

## Система статусов источника

- `DIRECT_TEXT` — реальное наблюдение/конкретная реплика о помещении.
- `CONTEXT_INFERENCE` — логический вывод, не изображать как прямую цитату автора.
- `MEDIATED_IMAGE_UNVERIFIED` — фильм, экран, голограмма, модель; могут подсказывать вопросы, но требуют подтверждения реальной сцены.
- `DREAM_NONFACT` — сон, не использовать как физическую геометрию.
- `MEMORY_NOT_SPATIAL` — воспоминание без новых геометрических данных.
- `EXCLUSION_EVIDENCE` — описание иной станции, полезно для **запрета** ошибочной атрибуции.

**Схема уровней — не сумма отдельных независимых планов.** Нужны взаимосвязанные `G1` (сеть помещений, включая циклы), `G2` (DAG порядка строительства, без циклов), `G3` (геометрические и вертикальные неравенства), `G4` (инженерные сети); только после проверки — общая геометрическая модель Archicad 29 и APA DynamicCommands → BIM Graph → SceneWriter. Пока все нативные записи запрещены.

## Визуальные гипотезы

Присланные пользователем иллюстрации и найденные в интернете изображения допустимы как **гипотезы для ускорения поиска**. Каждая получает ID `VH`, предполагаемое пространственное утверждение, исходное изображение, требуемые подтверждения по конкретным страницам и вердикт. `TEXT_SUPPORTED_LOCAL_ONLY` означает ограниченное подтверждение отдельной детали, не целого этажа. Нельзя выдавать эскиз планировки за геометрию без первоисточника.
