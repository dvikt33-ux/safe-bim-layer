## Жёсткий цикл аудита КАЖДОЙ страницы

1. Прочитать **весь литературный текст веб-страницы**, включая диалоги, мысли, воспоминания, переходы между частями, предложения с предлогами положения, пояснения роботов. Системный футер сайта не считать литературным текстом.
2. Отметить границы **реальное событие / сон / иллюстрация или голограмма / обман героя / воспоминание / гипотеза персонажа**.
3. Установить `station_id`: МОАГ, другая станция, Земля или неизвестно. Не переносить архитектуру станции Питера из книги IV на МОАГ.
4. Выписать **каждое** описание: объём и форма помещения, вход/выход, отделка, мебель, свет, вертикаль, шахта, вентиляция, силовые кабели, тепло, вода, шлюзы, автоматика, сцепление коридоров, маршрут от точки А к точке Б.
5. Отдельно выписать **относительные признаки**: выше/ниже, рядом, напротив, за, до, вторая половина кольца, через стену, поворот, число ступеней, разница размеров. Право/лево записывать только с направлением движения конкретного персонажа — НЕ как мировой азимут.
6. Отметить функциональное и сюжетно-временное состояние: закрыто после аварии, двери открыты в главе, датчики недоступны конкретному лону. Не объявлять один момент постоянным устройством станции.
7. Создать запись `page_observations.json` и привязать к уже известным узлам реестра v1. Если узла нет — записать будущую задачу создания узла; не подменять неподтверждённую комнату.
8. Страница без значимой архитектуры всё равно маркируется `REVIEWED_FULL_PAGE` **и отдельно** фиксируется `recorded_spatial_hints:0` — отсутствие сведений тоже аудируется.
9. Из изображения можно сформулировать гипотезу для поиска, но изображение без масштабного подтверждения не позволяет создавать стены, размеры, этажи или радиусы.
10. После блока сделать независимые сверки: источники, пропуски, конфликты, неверно перенесённые станции, необоснованные выводы и совпадение `page`→`observation`→`node`.

## Система статусов источника

- `DIRECT_TEXT` — реальное наблюдение/конкретная реплика о помещении.
- `CONTEXT_INFERENCE` — логический вывод, не изображать как прямую цитату автора.
- `MEDIATED_IMAGE_UNVERIFIED` — фильм, экран, голограмма, модель; могут подсказывать вопросы, но требуют подтверждения реальной сцены.
- `DREAM_NONFACT` — сон, не использовать как физическую геометрию.
- `MEMORY_NOT_SPATIAL` — воспоминание без новых геометрических данных.
- `EXCLUSION_EVIDENCE` — описание иной станции, полезно для **запрета** ошибочной атрибуции.

**Схема уровней — не сумма отдельных независимых планов.** Нужны взаимосвязанные `G1` (сеть помещений, включая циклы), `G2` (DAG порядка строительства, без циклов), `G3` (геометрические и вертикальные неравенства), `G4` (инженерные сети); только после проверки — общая геометрическая модель Archicad 29 и APA DynamicCommands → BIM Graph → SceneWriter. Пока все нативные записи запрещены.

## Визуальные гипотезы

Присланные пользователем иллюстрации и найденные в интернете изображения допустимы как **гипотезы для ускорения поиска**. Каждая получает ID `VH`, предполагаемое пространственное утверждение, исходное изображение, требуемые подтверждения по конкретным страницам и вердикт. `TEXT_SUPPORTED_LOCAL_ONLY` означает ограниченное подтверждение отдельной детали, не целого этажа. Нельзя выдавать эскиз планировки за геометрию без первоисточника.
