# МОАГ R21 — ревизия перегруженных маршрутных индексов и контекстный кросс-реестр

**Состояние:** `SOURCE_QUALIFIED_EPISODE_IDENTITIES_NOT_XYZ`. База — [R20 PR #207](https://github.com/dvikt33-ux/safe-bim-layer/pull/207), коммит `6906e1668e239084741ddfd6d009c5f2b358e252`. Полный Windows/Linux CI R11–R20 предварительно перепроверен и имеет статус SUCCESS.

## 1. Что обнаружено

Маршрутный словарь R14 присваивает нескольким **разным физическим типам объектов** одну исторически использованную широкую метку `existing_graph_node`. При сохранении общей R09-структуры это приемлемо для сюжетной навигации, но **неприемлемо для физического объединения объектов**.

R21 программно проверяет каждое употребление пяти высокорисковых меток по оригинальному `v2/character_routes.json` и старому R04 кросс-индексу:

| Старая метка | Эпизодов | Почему нельзя автоматически сливать |
|---|---:|---|
| `L1-ANGAR-HALL` → `MOAG-G-0017` | **4** | Один широкий проход, один ангар спящих, один старый высокий ангар, один вход во вновь используемый военный ангар |
| `L1-CIRCULAR-CONTROL` → `MOAG-G-0060` | **3** | Пультовая ручного управления шлюзами круглого зала и верхняя диспетчерская ангара B1-110 могут не совпадать |
| `L1-CIRCULAR-STAIRS` → `MOAG-G-0059` | **4** | Круглый зал, старые служебные помещения и подвесная лестница ангара — не все одна доказанная лестница |
| `L1-OLD-FREIGHT-HANGAR` → `MOAG-G-0053` | **8** | Несколько коридоров, историческая грузовая область, отдельные ангары |
| `L1-SEALED` → `MOAG-G-0021` | **11** | Весь закрытый сектор и неодинаковые в разных эпизодах ворота/переходы |

**Итого: 30 маршрутных употреблений**, все остаются доступными в аудиторском реестре, с исходными индексами, страницами, типом и причиной неопределённости. Не утверждается, что все 30 употреблений ошибочны: проблема — автоматическое физическое тождество по совпадению метки.

## 2. Новые источниковые контекстные уточнения

R20 уже установил **`RT015-G` → `MOAG-G-0057`** по [B1-075/P-216](https://loveread.ec/read_book.php?id=48197&p=75) — ангар со спящими взрослыми, а не магистраль G0017.

R21 дополняет:

| Эпизод | Подтверждённый физический референт | Источник |
|---|---|---|
| `RT024-F`, широкий ангар B1-110 | `M-L1-AH-OLD-001` (исторический высокий ангар) | [B1-110/P-313](https://loveread.ec/read_book.php?id=48197&p=110) |
| `RT024-H`, поднятые комнаты ангара | `M-L1-AH-OLD-CTRL-001`, не G0060 по одному названию | [B1-110/P-313](https://loveread.ec/read_book.php?id=48197&p=110) |
| `RT024-I`, скрытое обзорное остекление | Та же поднятая пультовая `RT024-H` | [B1-113/P-316](https://loveread.ec/read_book.php?id=48197&p=113) |
| `RT015-L`, ручное управление шлюзами | `MOAG-G-0060` — помещение за полукруглым мостиком | [B1-076/P-221](https://loveread.ec/read_book.php?id=48197&p=76) |
| `RT031-G`, возвращение к катерам и лестнице | Тот же посещённый рабочий военный ангар, в который вошли на `RT031-F` | [B2-018/P-376](https://loveread.ec/read_book.php?id=53370&p=18) |

Первые четыре строки **не меняют** R14, R09 и геометрический R15; связь `RT031-F`/G — только тождество посещаемого пространства в одном эпизоде, не новый индекс конкретного ангара.

Для `RT030-D` сохранена корректная исходная идентификация **G0017 = ангарная магистраль**, с точной ссылкой B2-014/**P-362** (не P-363: тот источник описывает биометрические створки ангара).

Для `RT023-A` R18 сохраняет вопросы о лестнице; для `RT022-E/F`, `RT024-B/C/E`, `RT031-E` старый `MOAG-G-0053` остаётся **контекстом старой грузовой зоны**, но не физической идентичностью единственного помещения.

## 3. Что принципиально не установлено

Пока без доказательной идентичности остаются три межэпизодные пары:

1. Пультовая ручного управления шлюзами `MOAG-G-0060` и поднятая диспетчерская старого ангара `M-L1-AH-OLD-CTRL-001`.
2. Военный ангар с катерами `RT031-F` и первый катерный ангар `M-L1-FH-001` — совпадение возможно, но не доказано одними общими названиями.
3. Высокий старый ангар `RT024-F` и ангар со спящими `MOAG-G-0057` — R18 уже сохранил оба варианта.

В **каждой паре** MiniZinc и Python OR-Tools должны допускать и `SAME`, и `DIFFERENT`, а затем независимо воспроизводить найденные Python-свидетели в MiniZinc. Это предотвращает случайное «утверждение» первого попавшегося 3D-сценария как книжной геометрии.

## 4. Модель и расчёты

R21 добавляет **5 доказательных равенств физических референтов эпизодов** в уже работающую общую модель R11–R20. Идентификаторы физического объекта сохраняются отдельно от координатных переменных R13.

```powershell
python tools/moag_topology/bootstrap_r11.py
python tools/moag_topology/contextual_crosswalk_r21.py --out moag-r21-run
python -m unittest discover -s tests -p test_moag_crosswalk_r21.py -v
```

Для источниковых равенств требуются **5 отрицательных UNSAT**: синтетически объявить названные эпизоды разными физическими референтами; при отключении источниковой семьи противоречие должно исчезнуть (SAT). Конфликтные ядра с P-313/P-316/P-221/P-376 перепроверяются **обоими** backend.

Дополнительно проверить **6 независимых SAT-альтернатив** для трёх нерешённых пар и повторный приём Python-свидетеля в MiniZinc.

## 5. Пределы результата

- Источниковый слой не является утверждённой геометрией или готовой моделью для Archicad.
- R09 сохраняет **593 узла / 845 связей**. Нет новых физических узлов, удалений, подмены R04 или перезаписи первичного R14.
- Сохраняются **52 маршрута / 378 этапов** и исходные подтверждённые объёмные привязки **25**, незавершённые — **353**.
- Точные XY/Z, расстояния, габариты, виды и количество новых дверей **не выводятся** из совпадения книжных референтов.
- Первичные страницы B1-110/113, B2-018 используются из ранее зарегистрированного постраничного реестра; утверждение о новом полном постраничном чтении в R21 не делается.
- Пять приоритетных перегруженных меток не охватывают **все** возможные ошибки реестра. Это адресный проверяемый проход, а не окончательный тотальный аудит четырёх книг.

**Следующий шаг:** в отдельном разрешённом редакционном слое предложить исправление канонической маршрутной индексации `RT015-G` и `RT024-F/H/I`, предварительно согласовав все исходящие связи с графом и пройдя обратную совместимость. До этого хранить исходные индексы и R21 доказательное перекрёстное соответствие одновременно.
