# МОАГ R13 — первая вычислительная проверка объёмной компоновки (только сценарий)

**Статус:** `NONCANONICAL_BOX_FEASIBILITY / SOURCE_RELATIONS_PROTECTED / NOT_ARCHITECTURAL_3D`

База: R12, [draft PR #198](https://github.com/dvikt33-ux/safe-bim-layer/pull/198). Три глобальных блока, но каждая главная часть станции имеет внутренние локальные ярусы. Граф R09, R11/R12, книги и обе присланные пользователем авторские иллюстрации не изменяются.

## Важная разница между R12 и R13

R12 проверяет символический порядок пола и верхнего яруса. R13 впервые проверяет **пример допустимого размещения ограниченного множества условных 3D-оболочек** внутри трёх *раздельных* демонстрационных областей и обнаруживает случаи, когда поднятая операторская оказалась **вне** ограничивающего объёма ангара.

**Никакая коробка в R13 не означает, что помещение в книге прямоугольное.** Все `(x,y,z,w,d,h)` — вспомогательные искусственные целочисленные размеры и размещения. Конкретные числа не извлечены из текста, не являются метрами и **не подтверждают** внешние стены или план здания.

Верхние галереи неправильной/круглой формы из R12 **не заменяются** прямоугольными комнатами. У Нижнего круглого зала — *частичная дуга*, у Третьего круглого зала — *периметральная галерея*. Их форма сохранена в R12; R13 проверяет лишь возможную общую объемную область зала.

## Три полностью различимые глобальные области

Область | Условный размер решателя | Что это значит
---|---|---
Нижний блок | 80 × 80 × 36 | Один расчётный ограничивающий бокс для сценария
Второй блок | 64 × 64 × 26 | Другой ограничивающий бокс, по сценарию меньше
Третий блок | 48 × 48 × 22 | Третий ограничивающий бокс, по сценарию ещё меньше

Принцип убывания блоков поддержан авторским видом станции. **Сами численные отношения, прямоугольность, центровка и абсолютные Z — проектные гипотезы R13.** Не принимать это за точный внешний облик и не экспортировать как геометрию корпуса.

Все объёмы хранят локальные координаты *внутри собственного блока*, для будущей полной сцены есть отдельный сценарный `origin`. Отсюда нельзя автоматически заключить, что вертикальные шахты совпадают по XY между блоками или что сквозные объемы имеют вход на каждом уровне.

## Демонстрационная выборка: 12 объектов

Нижний: три названные базы (Тёмная, Овальная, диких), первый и соседний ангары малых катеров, старый ангар, высокий круглый зал, а также **три доказанные верхние операторские** внутри соответствующих ангаров. Второй: Главная площадь. Третий: круглый зал отдыха.

Три пары `parent -> raised room` читаются **из R12** и сверяются по точным индексам и источникам. Прочие галереи R12 не потеряны, но на этом шаге ещё не получают полноразмерных пространственных коробок. 12 объектов — **испытательная выборка**, а не все помещения МОАГа.

Непересечение проверяется только для явно разных самостоятельных помещений: три пары названных баз и пара двух разных ангаров катеров. Это не повсеместный запрет на пересечение всех 197 индексов, поскольку один индекс может представлять составную область, галерею, оборудование или уточняющее название.

Четыре положения названий баз на авторской схеме Нижнего используются **как порядковые условия в плоскости рисунка**. Они проверяют общий сценарный порядок центров соответствующих контейнеров, а не направления сторон света, радиусы или настоящие координаты стен.

**Пути P-024 и P-305** между Тёмной и Овальной базами сохранены в R12 как два разных косвенных маршрута. R13 **не** утверждает, что 3D-бокс базы соединяется дверью с другим боксом, и **не** рисует прямой коридор.

## Тест, который должен отличать новое качество

- **SAT:** подобрать относительные координаты внутри условных областей так, чтобы выделенные пространства не пересекались запрещённым образом, поднятые комнаты находились внутри ангаров и были выше их полов.
- **Cross-backend:** повторно передать все найденные целочисленные координаты MiniZinc + CP-SAT, чтобы независимый пользователь модели признал размещение допустимым.
- **UNSAT:** подменить одно доказанное отношение условием `x_child >= x_parent + width_parent` и показать противоречие с `child_inside_parent` при положительной ширине дочернего помещения. Поднять из CP-SAT достаточное конфликтное ядро с точным источником поднятой операторской.
- **Защита:** деформация, потеря источника, выход за ограничивающий бокс и неправомерное утверждение точной формы вызывают ошибку.

Реальный запуск в CI при публикации:

```powershell
python tools/moag_topology/bootstrap_r11.py
python tools/moag_topology/scenario_volumes_r13.py --out moag-r13-run
python -m unittest discover -s tests -p test_moag_volumes_r13.py -v
```

Используется **реальный** MiniZinc CP-SAT и Python OR-Tools из R11. Формируются `scenario.json`, `sat.mzn`, `cp-witness.mzn`, `synthetic-unsat.mzn`, исходные stdout/stderr и `results.json`.

## Границы доказательности

Найденное положение **не будет** называться планом станции. Пока запрещены: изображение прямоугольных границ вместо книжной дуги, точная соосность шахт, помещение всех баз в один отсек, перенос технических ярусов между глобальными блоками, построение сплошных дополнительных палуб, присвоение числовых размеров из R13 тексту книги, вывод реальной дальности баз только из расчётного зазора.

Следующий содержательный этап — расширение контролируемой выборки на другие помещения с реальными индексами, типизированная проверка маршрутов и, если будут достаточные текстовые данные, калибровка формы и размеров с **авторским силуэтом** без автоматического превращения ограничивающего бокса в корпус.

Только после этого логично собирать полные планы всех трёх глобальных блоков и аксонометрию, на которых неизвестная геометрия останется отдельным слоем.
