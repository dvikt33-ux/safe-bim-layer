# МОАГ R16 — первичный аудит 353 этапов, источниковые ссылки и развилка к базам

**Статус:** `REVIEW_353_STAGES / REUSE_EXISTING_PAGE_LEDGER / QUALITATIVE_FORK_COMPARISON`

Основа: [R15 / draft PR #201](https://github.com/dvikt33-ux/safe-bim-layer/pull/201), commit `2f965d12992073b8837d08b2d3e2a06d42994c4f`. Структура R09 593/845, объёмы R13, локальные высоты R12 и 52 маршрута R14 не редактируются. Два авторских изображения остаются обязательными исходными схемами, не публикуются повторно.

## 1. Почему 353 непривязанных этапа — не 353 недостающие комнаты

Из опубликованного `r15/calculation/missing_evidence.json` автоматически читаются **все 353** записи и сравниваются с полученной заново моделью R15. Неполное совпадение идентификаторов блокирует выполнение.

- **189 этапов имеют существующий объектный индекс**, но тот ещё не имеет подходящего сценарного объёма из ограниченной выборки R13 или однозначной доказанной связи с таким объёмом.
- **164 этапа не имеют подтверждённого объектного индекса**. Большинство — эпизоды передвижения, прохождение дверей, использование лестниц/лифтов, неясные промежутки; **это не позволяет объявлять их новыми физическими помещениями**.
- **112 этапов ограничены Нижним глобальным блоком**. Именно они составляют первоочередной набор ручной и источниковой проверки.
- Прочие ограничения глобальных блоков остаются без произвольного «уточнения».

Для **189** существующих индексов формируются очереди:
1. Отдельный описанный `space`: **проверить источники и возможный объём**, но не присваивать прямоугольный бокс автоматически.
2. `circulation`, `vertical_route`, `portal`, `local_gallery`, `corridor`: **искать трассовый/портальный домен**, не добавлять комнату.
3. `level`, `zone`, `space_group`, `system`, `utility`, `logical_access`: **сохранять агрегат/систему** и искать доказательные вложения, не делать один новый объём без оснований.

Для **164** отсутствующих индексов категории являются **только заявкой на проверку**, по зарегистрированному способу движения. `NARRATIVE_GAP` означает неописанный переход (новая шахта запрещена). Прохождение двери — не самостоятельная комната. Лестница/лифт могут означать конструктив или общую шахту, но не дают разрешения отождествлять разные конструкции. `WALK/RUN` не означает «один прямой коридор».

Выход: `review-queue.json`, все 353 этапа с источником, блоком, индексом, типом требуемой проверки и явными запретами на новые помещения/метры. Порядок приоритета `P1_LOWER`, `P2_OTHER`, `P3_UNRESOLVED_GLOBAL_BLOCK`. Никакие статусы уверенности графа не повышены.

## 3. Новое прямое качественное отношение R16: развилка маршрута

Индекс `MOAG-G-0100` уже существует и подтверждён как развилка возвращения к Нижним базам. У `RT014-D` стоит его точный индекс; `RT014-E` фиксирует выбранную длинную ветвь, `RT014-F` — прибытие к двери района баз.

Книга I, страница **B1-065** в ранее проверенном реестре: правый путь **короче**, левый **длиннее**. Короткий блокирован/опасен, поэтому выбран длинный обход.

R16 добавляет в **ту же общую задачу CP-SAT R15** единственное новое качественное отношение:

```
порядковая_длина(левый_длинный) > порядковая_длина(правый_короткий)
```

Это **абстрактные ранги [0..8], НЕ метры**. Два маршрутных варианта не превращаются в две новые комнаты; проход справа не объявляется пройденным в этой сцене. Нет дополнительных XY, дверей, сплошных коридоров или неизвестных физических индексов. Нельзя распространять относительную длину этого эпизода на другие маршруты.

Результат считается полезным именно потому, что теперь развилка не может исчезнуть при упрощении модели до одной линии.

## 4. Проверяемый эксперимент

R16 запускает не отдельную игрушечную модель, а **совместную систему ограничений R15 плюс новый источник B1-065**:

- **SAT:** реальный Python OR-Tools и MiniZinc CP-SAT принимают всю совместную модель, включая ветви развилки.
- **Cross-backend:** полное решение Python с закреплёнными значениями принимается MiniZinc.
- **UNSAT:** искусственное обратное требование `короткий >= длинный` даёт несовместимость. В ядре должны присутствовать книжная запись B1-065 и синтетический тест; ядро повторно подтверждается обоими решателями.
- **Значимость:** при выключении нового источникового ограничения минимальный ранг длинного пути равен 0; при включении — 1, оба оптимума подтверждены. **Это сокращение только условного пространства вариантов длины данной развилки**, не повышение пространственной определённости XY всей станции.

Команды:

```powershell
python -m pip install -r tools/moag_topology/requirements-r11.txt
python tools/moag_topology/bootstrap_r11.py
python tools/moag_topology/evidence_triage_r16.py --out moag-r16-run
python -m unittest discover -s tests -p test_moag_evidence_r16.py -v
```

Результаты: `results.json`, `review-queue.json`, формальные входы MiniZinc и сохранённые stdout/stderr.

## 5. Ограничения и следующий переход

**В R16 сознательно не увеличивается число 25 из 378 этапов с привязкой к существующим 12 сценарным объёмам.** Увеличить эту цифру добавлением искусственных прямоугольников было бы методической ошибкой.

В B1 ранее проверены все 114 страниц, B2 — 118 из 148, B3 — 27 из 71, B4 — 1 из 79. Страницы B3/B4 часто описывают другие объекты и ретроспективные события: необходимо сначала установить, относится ли конкретный эпизод к физической станции МОАГ, а не автоматически переносить всё в модель.

R17 должен расширять не число искусственных помещений, а **число реальных пространственных ограничений**, особенно для 112 нижних этапов и существующих ангаров, шахт и технических маршрутов. Новый объект/проход/геометрия допускаются лишь после адресного доказательства по книге и сверки с авторскими иллюстрациями. Условные размеры R13 не являются размерами станции.
