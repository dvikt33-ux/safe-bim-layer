# МОАГ R14 — все маршруты и источник-объяснимый вертикальный порядок

**Статус:** `RECORDED_ROUTE_ORDER_AND_RELATIVE_Z / NONMETRIC / NOT_PHYSICAL_DOOR_GRAPH`

База: [R13, черновой PR #199](https://github.com/dvikt33-ux/safe-bim-layer/pull/199). Не заменяем R09 (593/845), R11–R13, авторские планы, книжные тексты и исходные реестры.

## Что подключено к MiniZinc + OR-Tools

Впервые решателю передаётся **полный существующий реестр 52 наблюдавшихся маршрутов (378 шагов)**, а не только выбранная демонстрационная зона. Из уже заполненных полей `constraints` перенесены **32** явно записанных качественных отношения `RELATIVE_Z`; ещё **1** особое указание `ROUTE_WITH_ALTERNATE_VERT_PATH` сохранено **отдельно**, а не превращено в линейный порядок Z.

**326** последовательностей шагов — связи только типа `RECORDED_NARRATIVE_ORDER_NOT_PHYSICAL_DIRECT_ACCESS`. Это **не 326 доказанных дверей или прямых коридоров** и не 326 новых комнат. Шаг без физического индекса остаётся наблюдением с `UNPLACED_NARRATIVE_STAGE_NOT_PHYSICAL_ROOM`, а не произвольно нарисованным техническим отсеком.

Для решения используются символические `t` (порядок наблюдений в данном маршруте) и `z` (относительный высотный ранг). Для известных глобальных блоков 1/2/3 применяется только порядковая иерархия; численная величина условных рангов не является физическим расстоянием в метрах или отметкой перекрытий. Неизвестные уровни остаются широкими областями. Нельзя объединять высоты одинаково названных маршрутных эпизодов, если их тождество не установлено.

## Важнейшие маршруты для пространственной компоновки

| Запись | Что известно | Что пока не доказано |
|---|---|---|
| **P-024**, B1-003 | После двойных дверей большая круглая труба ведёт в сторону Овальной, противоположная сторона — к Тёмной | Единственный прямой коридор между границами двух баз, координаты развилки |
| **P-305**, B1-106 | Между Овальной и Тёмной существует сокращённый путь через технические проходы, трубы и кабельные ниши | Порядок каждой ниши, точное расстояние, дверное примыкание |
| **RT-006**, B1-042–043 | От Тёмной к базе диких описаны семь последовательных стадий: большой обход, узкий коридор, высокий порог, две ступени вниз, трубы и заключительный подход | Прямая дверь Тёмная–Дикие, геометрическая кратчайшая дистанция |
| **RT-007**, B1-044–045 | Из спальной зоны Тёмной к прямому грузовому коридору зафиксированы **два раздельных спуска**, дверь и технические ниши; затем путь обратно | Все базы выше всех ангаров, непрерывное понижение на всём пути без подъёмов |
| **RT-008**, B1-046 | Переход Нижний → Второй через вентиляцию | Точная шахта/XY и локальная высота входов |
| **RT-009**, B1-047–048 | Обычный лифт Второй → Нижний | Тождество этой шахты с иными лифтами |

**Особенно важно:** RT-007 впервые позволяет напрямую проверить уже записанные в маршрутах **две высотные зависимости, ведущие от спальни Тёмной к грузовой системе**. Но это ещё не доказывает общий тезис «каждая база выше каждого ангара». Требуется учитывать возможные промежуточные подъёмы и различия между локальными полами.

Два пути P-024 и P-305 сохраняются как разные **описания маршрутов** с закреплёнными индексами конечных баз `MOAG-G-0008` и `MOAG-G-0009`. Графический редактор не должен рисовать «коридор между базами» где-то в стороне, не привязав его оба конца к этим двум индексам. При этом разрешено оставить неизвестные промежуточные участки неопределёнными. Нельзя утверждать, что два пути полностью независимы по физическим шахтам.

Шаг `RT007-H` о прямом грузовом коридоре сопоставлен с возможным индексом `MOAG-G-0080` только как **`CANDIDATE_CONTEXTUAL_MATCH_NOT_APPROVED_PHYSICAL_IDENTITY`**. Он не сливается с этим индексом, а тем более с другим полукруглым ангарным проходом. Сохранён источник P-169.

## Проверка ошибок графа и пробелов в ссылках

Установлены четыре номера страниц, для которых маршрутный реестр имеет ссылочный код, но **в реестре постраничных наблюдений пока нет совпадающего `citation_url`**: `B1-061`, `B1-063`, `B1-064`, `B1-065`. Их локальные маршрутные наблюдения не удалены и не заменены выдуманными веб-ссылками. Необходима адресная верификация.

R14 никогда не повышает последовательность наблюдений до физической смежности и не объявляет шаг новой комнатой. Отношение `ROUTE_WITH_ALTERNATE_VERT_PATH` RТ-001 сохраняется отдельно, чтобы разные лифты одной сцены не сливались без доказательства.

## Реальный эксперимент и критерии

```powershell
python tools/moag_topology/bootstrap_r11.py
python tools/moag_topology/route_constraints_r14.py --out moag-r14-run
python -m unittest discover -s tests -p test_moag_routes_r14.py -v
```

Запускаются настоящие Python OR-Tools CP-SAT и MiniZinc → CP-SAT для всех 52 маршрутов. Проводится воспроизведение найденного CP-SAT свидетеля в MiniZinc, затем два отрицательных опыта:

1. **UNSAT: локальная высота.** Искуственно обратное отношение к явной записи RT-006 `порог выше двух ступеней вниз`. Конфликтное ядро должно включать исходную маршрутную запись и тестовую инверсию.
2. **UNSAT: пропуск стадий.** Искусственное сжатие семишагового RT-006 в одну позицию повествовательного порядка. Решатель должен сохранить 5 промежуточных описанных стадий. Этот тест **не доказывает пяти дверей или физически пяти помещений**.

Результаты: `route-evidence.json`, `all-routes-sat.mzn`, `python-witness.mzn`, два входа для конфликтных опытов, stdout/stderr и `results.json`. Проверки выполняются в GitHub Actions на Windows и Linux вместе с R11–R13.

## Что требуется далее

У R13 пока только 12 демонстрационных 3D-боксов. **R14 не должен принудительно сажать все 378 шагов на один из этих боксов.** Правильное следующее действие — соединить подтверждённые маршруты с уже размещёнными в сценариях индексами и определить **множества допустимых областей**, а не точки неизвестных коридоров; сравнить варианты с авторской схемой, расширить типизированные физические объёмы без потери дуг/галерей и проверить, насколько новая сеть горизонтальных и вертикальных ограничений уменьшает неопределённость.

**Запрещено утверждать готовность BIM/3D, метры, местоположения неизвестных комнат и прямые проходы без первоисточника.** Обе книжные иллюстрации, исходный граф, `main` и Archicad неизменны.
