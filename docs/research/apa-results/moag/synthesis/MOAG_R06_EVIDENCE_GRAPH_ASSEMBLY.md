# МОАГ — R06 | Сборка разрозненных доказательных графов

**Статус:** `PARTIAL_EVIDENCE_ASSEMBLY / REVIEW_REQUIRED / NOT_METRIC_GEOMETRY`.

R06 является **надстройкой** над R04/R05, а не заменой источников. Входы: 197 индексированных сущностей, графы R04/R05, 52 маршрута с отдельными наблюдениями шагов и редактируемые интервалы площадей/объёмов R05. Фактические счётчики при запуске вычисляются из файлов; численные размеры книги не подменяются проектными оценками.

## Алгоритм

1. **Сохранить идентичности.** Индексированное помещение и шаг маршрута — разные виды сущностей. Наблюдение `ROUTE::RT-XXX::STEP` не создаёт новый физический отсек. Старый текстовый псевдоним связывается с индексированным понятием, но не сливается физически с другими понятиями без отдельного доказательства.
2. **Собрать локальные группы.** Из R04 берутся только допустимые физико-пространственные свидетельства, из R05 — подтверждённые топологические связи. Исторические названия, проектные сравнения размеров и неразрешённые идентичности не превращаются в доказанную смежность.
3. **Подключить маршруты.** Последовательные явно зарегистрированные шаги дают связь `OBSERVED_ROUTE_ORDER_NOT_DIRECT_DOOR` (порядок прохождения, не соседство дверей). Шаг `NARRATIVE_GAP` разрывает обе стороны соединения. Возле шагов сохраняются конкретные исходные страницы.
4. **Различить соединения.** Регистрируются все технические операции присоединения узлов и отдельно — случаи `PHYSICAL_EVIDENCE_COMPONENTS_CONNECTED_NOT_METRIC`, когда через маршрут соединены два ранее разрозненных компонента, каждый из которых уже содержит индексированный физический объект.
5. **Уровни и вертикаль.** Глобальные уровни 1, 2 и 3 проверяются отдельно от локальных антресолей и шахт. Отношение «выше/ниже» задаёт ориентированное ограничение порядка без численного Z; циклы фиксируются как противоречия. Совпадение старого «нижнего» ярлыка инженерной сети с наблюдением её входа на Втором — не автоматическая ошибка и не доказательство одного этажа: `MULTILEVEL_ALIAS_REVIEW`.
6. **Площади / объёмы.** R06 повторно вызывает R05 для проверки площади пятна, полезных площадей, вместимости судов, дискретных зон и свободных высоких объёмов. Условные ангарные галереи не создают сплошных палуб. Диапазоны по тексту и проектным расчётам не смешиваются.
7. **Остаточная неопределённость.** Несоединённые группы и одинокие узлы сохраняются. Ни связность, ни нахождение на одном уровне не устанавливают координаты XY, одинаковую отметку Z, толщины стен, взаимную ориентацию или геометрическую единственность.

## Специальный контроль RT-011

Маршрут RT-011 описывает выход к вентиляции на Втором и спуск на Нижний. Старая концептуальная запись `L1-VENT → MOAG-G-0016` приписана Нижнему, однако по функции это система лазов и вертикальных участков. Система выводит `MULTILEVEL_ALIAS_REVIEW`, сохраняет весь путь и **не изменяет исходный индекс и этаж**. Для утверждения геометрии вентиляционной сети нужен отдельный источник или принятая пользователем гипотеза.

## Использование

```bash
python tools/moag_topology/assemble_evidence_graph_r06.py --out moag-r06-evidence-result.json
```

С пользовательскими входами, не меняющими книгу:

```bash
python tools/moag_topology/assemble_evidence_graph_r06.py \
  --r04-parameters docs/research/apa-results/moag/synthesis/demo_override_r04_NONCANON.json \
  --area-overrides docs/research/apa-results/moag/synthesis/demo_area_overrides_r05_NONCANON.json \
  --variants docs/research/apa-results/moag/synthesis/demo_layout_candidates_r05_NONCANON.json \
  --out moag-r06-demo-NONCANON.json
```

Дополнительно рассчитываются число компонентов только по физическим индексам **до и после** включения маршрутов, количество реально объединённых физических островов, не привязанные индексы и компоненты только из маршрутных наблюдений. Число технически добавленных шагов не подменяет число соединённых помещений.\n\nДля просмотра доказательной цепочки между двумя индексами:\n\n```bash\npython tools/moag_topology/assemble_evidence_graph_r06.py \\\n  --between M-L2-EMMA-SUITE-001 M-L2-EMMA-KITCHEN-001 \\\n  --out moag-r06-trace.json\n```\n\n`requested_evidence_trace.edge_chain` перечисляет использованные связи и страницы. Это **цепочка свидетельств**, не маршрут человека и не доказанная геометрия.\n\nФормат результата: `nodes`, `typed_evidence_edges`, `connected_evidence_components`, `bridge_events`, `physical_fragment_bridge_events`, `route_location_review`, `narrative_gaps`, `vertical_partial_order`, `new_level_candidates`, `area_volume` и `gates`. Поля `metric_xy_known`, `metric_z_known`, `geometry_approved` и `archicad_write` должны оставаться `false`.

## Критерии готовности следующей фазы

- Пополнить маршрутами новый корпус постраничных свидетельств: каждый узел, связь и переход с конкретной ссылкой на страницу, без искусственных промежуточных проходов.
- Адресно разобрать каждый `MULTILEVEL_ALIAS_REVIEW`, `ROUTE_LOCATION_LEVEL_CONFLICT` и `VERTICAL_ORDER_CYCLE`; исправлять **источник связи**, а не подгонять координаты.
- Добавить геометрические *интервалы* для локальных помещений только после достаточно конкретных свидетельств и проверки суммарных вместимостей.
- Перед любым 2D/3D чертежом выполнить независимый аудит единой геометрической модели: планы, фасады и разрезы обязаны иметь одну топологию и размерный набор.

**Важно:** CI проверяет структуру и математическую непротиворечивость кода. Оно не доказывает точность интерпретации книги. Изменения относятся только к новой ветке, без записи в PLN и без объединения в main.
