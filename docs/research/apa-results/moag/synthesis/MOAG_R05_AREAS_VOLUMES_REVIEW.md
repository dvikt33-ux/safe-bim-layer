# МОАГ — R05 | Диапазоны площади, высоты и объёма

**Статус:** `PROJECT_HYPOTHESIS / INTERVAL_CONSTRAINTS / NOT_BIM_GEOMETRY`. Эта редакция строит архитектурные ограничения для последующей компоновки из уже собранных свидетельств. Исходные литературные записи и `main` не менялись. Новые страницы книг не читались.

## Основа

- [Новые локальные фрагменты R05](progressive_fragments_r05.json): 43 новых индексированных кандидата и 33 типизированных отношения.

## Классы площадей — НЕ смешивать

| Величина | Применение | Что **не** означает |
|---|---|---|
| Пятно горизонтальной проекции | сколько места занимает конкретное пространство или блок | не сумму всех помещений и не площадь застройки диска без пустот |
| Полезная площадь полов | этажи комнаты, антресоль, отдельные каюты | не свободное вертикальное пространство высокого ангара |
| Пространственный объём | площадь условной оболочки × чистая высота; предварительная оценка | не фактический кубический объём неправильной формы |
| Сквозной технический объём | площадь поперечного сечения шахты + её вертикальный диапазон | не дополнительный жилой этаж |
| Глобальная оболочка уровня | условная круглая проекция при авторском диаметре | не подтверждённый полный круглый внешний корпус станции |

Большой ангар с операторской не превращается в две непрерывные палубы; площадь операторской учитывается как локальная часть, а не как новая площадь всего этажа. Вложенные группы и их дочерние комнаты **нельзя суммировать повторно**.

## Минимум и максимум

Каждая из 157 площадных записей содержит:
- `min_module2 / max_module2` — стартовый широкий диапазон площади, рассчитанный через человеческий модуль (h=1.60	ext{ м}), если нет индивидуального интервала.
- `min_height_in_human_modules / max_height_in_human_modules` — предварительный диапазон чистой высоты.
- `editable_area_min_m2 / editable_area_max_m2` и `editable_height_min_m / editable_height_max_m` — индивидуальные переопределяемые границы, где уже выделен особый масштаб объекта.
- `source_ids` — ссылки на книжные наблюдения; они обосновывают **наличие и функцию**, но не являются доказательством выданных проектных чисел.
- `area_role` — категория учёта.

У трёх глобальных блоков есть отдельные широкие проектные интервалы пятна. Если пользователь задаёт условный диаметр, круглая площадь считается в проектном сценарии (pi D^2/4). Для Высоких ангаров и цехов хранится независимая высота; меньший по пятну Верхний блок **может** иметь большие локальные высоты.

## Сужение диапазонов

1. Исходный широкий интервал сохраняет несколько вариантов компоновки.
2. Корабельная вместимость сужает допустимую **минимальную** площадь ангара в зависимости от класса аппарата, их числа и проектных зазоров.
3. Минимумы раздельных жилых помещений суммируются для проверки площади каюты — без повторного суммирования самой каюты как дополнительной комнаты.
4. Нельзя размещать отдельный крупный сектор с площадью большей, чем доступный проектный блок.
5. **Три проверяемых предположения о непересечении крупных зон** задают бюджет пятна и пространственного объёма на Нижнем, Детском и Верхнем уровнях. Они явно обозначены как проектные гипотезы; если обнаружено перекрытие или вложенность, списки меняются по доказательствам.
6. Компоновки с противоречием по уровню или необходимой площади отбрасываются. Площадь служит ограничителем и вторичным критерием, но сама по себе **не** доказывает положение, левую/правую сторону или единственность всей геометрии.

## Демонстрация изменений

Все числа в файлах `NONCANON` **специально вымышленные проверочные сценарии, не габариты станции по книге**.

```bash
python tools/moag_topology/assemble_spatial_constraints_r05.py \
  --r04-parameters docs/research/apa-results/moag/synthesis/demo_override_r04_NONCANON.json \
  --area-overrides docs/research/apa-results/moag/synthesis/demo_area_overrides_r05_NONCANON.json \
  --variants docs/research/apa-results/moag/synthesis/demo_layout_candidates_r05_NONCANON.json \
  --out moag_r05_offline_review.json
```

Пример редактирования одной физической комнаты по индексу:

```json
{
  "M-L2-DINING-001": {"min_area_m2": 24, "max_area_m2": 600, "chosen_area_m2": 80}
}
```

После обновления сценария пересчитываются ограничения, выбор возможных блоков и площади/объёмы. Изменение корабля в исходных параметрах R04 меняет необходимый минимум его ангара — **не** требуется переписывать книжное наблюдение.

## Структурные испытания

Проверки Python 3.11/3.12 включают позитивные и отрицательные сценарии:
- Два/три катера и два разных класса грузовых крейсеров, без подмены классов.
- Слишком маленький ангар отклоняется.
- Сумма минимумов кухни, спален, гостиной и ванной не может превышать максимум каюты.
- Несколько индивидуально допустимых промышленных площадей могут **в сумме** перегрузить площадь Нижнего блока.
- В Верхнем блоке допустимая площадь может скрывать невозможный суммарный пространственный объём.
- Из трёх предложенных альтернатив остаётся одна по уровню и площади, **не** объявляется единственной архитектурной компоновкой станции.
- Отдельные связки R05 соединяются с R04 и регистрируются с доказательствами; координаты после такого объединения по-прежнему неизвестны.

## Границы готовности

- **Нет** доказанных координат XY, азимута кольцевых коридоров, габаритов конкретного крейсера по точному книжному чертежу и проверенных динамических траекторий разворота.
- **Нет** утверждённых стен, полной BIM-модели, выполнения SceneWriter и живого вызова Archicad.
- Минимумы и максимумы широко заданы для **настройки** и не являются исходными обмерами.
- Техническое прохождение CI не заменяет независимую архитектурную приёмку.
- R04 остаётся первичной учётной базой, R05 — уточняющим пространственным слоем; физические тождества, которым пока не хватает источников, не объединяются автоматически.
