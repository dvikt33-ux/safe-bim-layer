# МОАГ R08 — реконструкция с гипотетическими связями, без потери неизвестных элементов

**Рабочая редакция:** R08 от 20.10.2026. **Статус:** `HYPOTHETICAL_OVERLAY / NO_METRIC_GEOMETRY / NO_BIM_RELEASE`.

## Основное правило

Если книга подтверждает существование помещения, дверного рубежа, лифта,
галереи, инженерной сети или прохода, но не даёт точного места в общей
компоновке, **объект сохраняется в едином реестре**. Неизвестное расположение
не означает отсутствие объекта.

Если книга не описывает часть пути, этот участок сохраняется как **неизвестная
часть маршрута**. Это **не доказательство нового построенного коридора**:
персонажи могли проходить по уже известной сети, менять направление или
повествование могло пропустить промежуточное событие.

Если компоновка выглядит закономерной — кольцевой, радиальной, симметричной,
модульной или функционально повторяющейся — мы храним её как **вариант
расположения**, имеющий собственное основание и условия опровержения.
Симметрия может быть локальной, неполной либо вообще отсутствовать.

## Реализованная структура данных

[Сборщик R08](../../../../../tools/moag_topology/hypothesis_overlay_r08.py)
использует неизменённый доказательный каркас R07 и создаёт составной граф
`composed_graph`, в котором каждый гипотетический узел/ребро типизированы,
имеют ссылки на первичный реестр, домен допустимых глобальных уровней,
состояние проверки и явно запрещённое автоматическое подтверждение.

| Величина | Значение |
|---|---:|
| Доказательные и маршрутные узлы R07 | 575 |
| Доказательные и отрицательные связи R07 | 761 |
| Условные узлы неизвестных частей маршрутов | 18 |
| Условные связи с концами этих участков | 36 |
| Условные связи для локализации 12 известных стационарных индексов по уровням | 12 |
| Альтернативные гипотезы компоновки | 16, в восьми парах |
| **Узлы составного графа R08** | **593** |
| **Рёбра составного графа R08** | **825** |
| Доказанные качественные компоненты | 39, без изменения |
| Прямые доступы | 25, без изменения |

Регистр `entire_unplaced_index_register` сохраняет **все 197
индексированных объектов, систем и концептов** с областью допустимого уровня,
источником и отсутствием доказанных XY/метрических Z. Имеется один объект
`V-IMINUYA-001`, для которого не найден надёжный `source_ids` в исходных
R04/R05/R03 реестрах; его источник требует проверки, а не выдумывания.
Три сомнительных люка другой станции сохраняются как карантинные кандидаты.

Из 197 индексов 12 неподключённых стационарных элементов дополнительно
получили слабую связь `HYPOTHETICAL_LOCATION_SCOPE_NOT_ACCESS` с
контейнером *допустимого глобального уровня*. Этот контейнер — область
поиска, **не точка в плане, не вход, не вертикальная проекция и не новое
перекрытие**.

## Восемь групп альтернатив

Каждая группа содержит **два невыбранных варианта**, которые надо
сопоставлять с новыми страницами, маршрутами, площадями и высотными
ограничениями.

1. **Нижние малые ангары:** продольный ряд модулей вдоль общей служебной
   магистрали **или** радиальные ответвления к общему распределителю.
2. **Кольца Третьего:** примерно радиальный грузовой подход **или**
   непрямой коридор с несколькими поворотами.
3. **Жилое кольцо и Главная площадь Второго:** повторяющиеся частичные
   секции галереи **или** асимметричные фрагменты с ограниченным числом
   лестниц.
4. **Лифты Д/Е и приёмная платформа:** удалённость через длинный кольцевой
   маршрут **или** удалённость через ветвистую сервисную сеть.
5. **Старая изоляционная зона Третьего:** путь к площадке грузовых
   подъёмников через промежуточные помещения **или** отдельная
   промышленно-служебная ветвь.
6. **Оружейная Третьего:** возможное ответвление от внутреннего круга
   **или** от грузовой зоны.
7. **Библиотека с овальным окном:** общественная секция около площади
   **или** секция жилого кольца. Ни одна из этих моделей не отождествляет
   её с другой библиотекой без окна.
8. **Полукруговые кладовки Третьего:** возможная привязка к пути
   погрузчиков **или** к внутренней служебной дуге возле производства.

Первичные опоры и проверки вариантов зафиксированы в
[реестре R08](hypothetical_placement_options_r08.json): P-365/368/369,
P-200, P-193/484/486, P-138, P-571/573, P-498/200, P-488/484,
P-570/200. Эти наблюдения подтверждают упоминаемые элементы, **но
сами гипотетические взаимные расположения не доказаны**. У каждого
варианта есть `falsifier` — какое новое наблюдение исключит его.

## Как гипотеза может стать доказательной связью

1. Устанавливается правильная физическая станция и исторический период.
2. Подтверждается точный референт обоих объектов; повторное старое
   название не считается доказательством тождества.
3. Исключаются конфликт глобальных уровней и запреты R04/R05/R07.
4. Источник должен прямо подтверждать **именно отношение**, а не просто
   содержать оба названия на странице.
5. Отдельно проверяются тип связи, возможность прохода, промежуточные
   помещения и временное состояние ворот.
6. Перед утверждением размеров проверяются диапазоны площади,
   вертикальные объёмы, локальные антресоли и транспортные зазоры.

Только после этих проверок создаётся **новое доказательное ребро**,
которое отдельно проходит тесты. Выбирать более красивую симметричную
гипотезу для автоматического объединения компонентов запрещено.

## Инварианты и запуск

```bash
python tools/moag_topology/hypothesis_overlay_r08.py \
  --out moag-r08-hypotheses.json
python -m unittest discover -s tests -p 'test_moag_*.py' -v
```

Тесты проверяют сохранение R07 без переписывания, 18 маршрутных границ,
12 известных, но нелокализованных стационарных элементов, 16 взаимно
альтернативных вариантов, исключение чужой станции, запреты тождества
объектов, невозможность подмены пересекающимися уровнями и отсутствие
мнимых дверей/площадей/численных координат.

R08 имеет **единый формат визуализации**, но **не выдаёт 39 доказательных
компонентов за один уже связанный физический план**. Запись Archicad,
изменение `main` и публикация подтверждённого BIM не выполняются.
