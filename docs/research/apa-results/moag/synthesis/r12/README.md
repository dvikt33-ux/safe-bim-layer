# МОАГ R12 — локальные высокие объёмы и доказательные маршруты между базами

**Статус:** `PARTIAL_SOURCE_CONSTRAINED_VOLUMETRIC_ORDER / NONMETRIC / NOT_3D_GEOMETRY`.

База: draft PR #196, R11 MiniZinc + OR-Tools; неизменяемый мастер R09 — 593 узла, 845 типизированных отношений. R12 не заменяет R09/R11, не добавляет виртуальные комнаты и не пишет в Archicad.

## Исправленный дефект постановки

R11 проверял `отметка пола верхней комнаты > отметка пола зала`, но не фиксировал, что часть поднятых помещений находится **внутри высокого объёма**. Выводом R11 могла стать картинка, где операторская парит над ангаром вне его оболочки. R12 добавляет для **точечно доказанных** книжных пар `parent_floor < upper_floor < parent_top`. Все переменные — **целочисленные порядковые свидетельства**, не метры, не отметки строительной модели и не высоты полного перекрытия.

Привязываются не любые отношения `contains`, а только явно описанные **верхние комнаты и частичные галереи**. Для Нижнего блока — **7** подтверждённых источником записей (четыре точных R03 и три отдельные концептуальные R04; они **не семь независимых помещений и не семь независимых книжных фактов**). Для жилого Второго — **1** запись R03. Сохраняются остальные **13 R11 ограничений Нижнего и 3 Второго**, включая четыре утверждения **только о порядке на авторском листе**.

| Связь | Книжный источник | Статус |
|---|---|---|
| Поднятая диспетчерская внутри высокого старого ангара | P-313 / B1-110 | Прямое описание, R03 |
| Частичный верхний мостик внутри круглого зала | P-220 / B1-076 | Прямое описание, R03; не весь верхний этаж |
| Верхняя операторская внутри первого ангара катеров | P-365 / B2-014 | Прямое описание, R03 |
| Верхняя операторская внутри соседнего ангара | P-369 / B2-015 | Прямое описание, R03 |
| Верхняя группа операторских в ангарном объёме старого индекса | B2-014 / R04 E21 | Отдельный концептуальный индекс, НЕ сливать с R03 |
| Локальный полукруглый мостик в круглом зале старого индекса | B1-017 / R04 E66 | Отдельный концептуальный индекс, НЕ сливать с R03 |
| Верхняя периметральная галерея в общей комнате Темной базы | LR-B1-049 / R04 E91 | Прямое описание, R04 |
| Галерея над жилым блоком Второго | P-484 / B2-066 | R03, отдельная локальная отметка |

**Уточнение:** `parent_top` — только символическая верхняя граница исходного высокого пространства. Не является измеренным потолком, доказанным цилиндром/кругом в XY, площадью надстройки или отсутствием коллизий.

## Два доказательных пути между Темной и Овальной базами

Не приравнивать эти пути к одной прямой двери:

1. **P-024 / B1-003:** после двойных дверей ветка большой круглой трубы ведёт в сторону Овальной, в противоположную сторону движение к Темной. Точные точки входа в обе базы и геометрическая длина не известны.
2. **P-305 / B1-106:** сокращённый путь из Овальной к Темной через технические проходы, ниши, трубы и кабельные зоны. Прямой дверной проём между базами **не доказан**.

Они экспортируются в `source_backed_routes_not_solver_constraints`, имеют точные ссылки на страничные записи и не становятся жёстким метрическим расстоянием либо дверным ребром.

Авторские рисунки из R11 остаются обязательным источником общей ориентации и внешней оболочки. Сохранённые R11 плановые координаты — **только порядок подписей на рисунке**, не оси станции, не метры и не готовое размещение.

## Проверка на настоящем решателе

```powershell
python tools/moag_topology/bootstrap_r11.py
python tools/moag_topology/spatial_constraints_r12.py --scope 1 --out moag-r12-lower
python tools/moag_topology/spatial_constraints_r12.py --scope 2 --out moag-r12-second
python -m unittest discover -s tests -p test_moag_spatial_r12.py -v
```

Требуются зависимости из `tools/moag_topology/requirements-r11.txt`; используется тот же официальный MiniZinc CP-SAT. Результат каждого опыта — `qualitative-model.json`, машинный вывод SAT, повторный запуск SAT с фиксированным свидетелем, преднамеренный UNSAT с источниковым конфликтным ядром, `results.json`.

Противоречие: одновременно `parent_top > upper_floor` и искусственное `parent_top <= upper_floor`. Его нельзя ошибочно выдать за конфликт книги: обратная запись имеет статус `SYNTHETIC_CEILING_BELOW_UPPER`. Настоящее содержание подтверждённого источника хранится в самом ядре.

## Что R12 пока НЕ решает

- Метры и точные XY/Z, число сплошных полов, контур корпуса и его совместимость с объёмами.
- Длины и ширины переходов, непересечение объёмов в XY, реальные размеры ангаров и расстояния между базами.
- Какой из геометрически допустимых вариантов реально нарисовал автор вне помеченных на рисунке отношений.
- Общее отношение высот **всех** баз и **всех** ангаров — R11 специально доказал, что из нынешней модели оно не следует.
- Размещение остальных изолированных объектов, которым не хватает пространственных свидетельств.

Оставшиеся неизвестные сохранять, а не рисовать. Следующий полноценный геометрический этап — ограниченные *объёмные* домены с привязкой к внешней оболочке, различением реального проёма, длинного маршрута и неизвестной траектории. Нельзя выдавать R12 за окончательную 3D-модель.

## Техническая приёмка

R12 должен пройти два независимых реальных backend-испытания Python CP-SAT / MiniZinc CP-SAT для Нижнего и Второго, источник-объяснимый искусственный UNSAT и повторную независимую проверку SAT-свидетеля, а также отсутствие изменений хеша мастера R09. Факт выполнения подтверждать конкретным GitHub Actions, не только наличием кода.
