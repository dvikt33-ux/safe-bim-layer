Один пакет может объединять совместимые компоненты. Подключение, offline-проверка, native-работоспособность и инженерная пригодность — отдельные статусы. Проблемные необязательные модули отключаются независимо; обязательный неподдерживаемый функционал блокирует соответствующий сценарий. Единственный управляемый writer сохраняется. Точный изолированный PLN, identity/Tapir/журнал и отсутствие слепого повтора обязательны для native-операций. Main/APX/защищённые проекты требуют отдельного согласования.

Каталог component_catalog содержит источник/код, готовность, подготовительные и эксплуатационные зависимости, точку подключения, функции, взаимодействие, адаптер и критерий проверки. Конкретные функции уточняются при чтении доноров, без фиктивного PASS. Публикация — feature PR и штатный publisher с GitHub readback; локальные пути и посторонние сырые метаданные не экспортируются. По ходу работы только короткие тезисы; отчёт в конце.
