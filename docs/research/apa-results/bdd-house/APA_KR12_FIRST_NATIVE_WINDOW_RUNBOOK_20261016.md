# BDD дом — первая реальная нативная створка окна через APA SceneWriter

Дата 2026-10-16. Статус **CODE_AND_OFFLINE_CI_PASS / LIVE_WRITES_NOT_RUN**.

## Почему именно окно 1.8, а не все 23 сразу

Относительное положение западного оконного проёма полностью восстанавливается по двум чертежам исходного **того же** дома 2022 года:
- КР-10 (PDF стр. 12), план каркаса: западная наружная линия 1.8 и окно у середины пролёта;
- КР-12 (PDF стр. 14), развёртка блока **1.8**, длина обвязки 9 280 мм, окно чистым размером 1 500 × 900 мм, отметки подоконника +1 100 и верха +2 000.

Сумма на размерной цепи до левой обрамляющей стойки (от юга): 600+600+443+442+417+418+600+50 = **3 570 мм**; правая обрамляющая сторона — 5 170 мм (полная ширина с 50-мм стойками = 1 600 мм). Геометрический центр — **4 370 мм от южного конца** (по плану КР-10 подтверждён южный старт измерения). Исходная нативная стена: GUID `323703e9-2bf2-4488-a24d-0ba20760400d`, от (0,9.38) до (0,0), 9 380 мм, то есть ориентирована от северного конца к южному. Нативный `centerOffset=9 380−4 370=5 010 мм`.

**Тип:** `CreateWindows`; `width=1.5`, `height=0.9`, `sillHeight=1.1`, `centerOffset=5.01`, `ownerWallId` = сохранённый GUID. Дом не содержит уже созданных окон/дверей в базовом состоянии 261 GUID.

## Нативная реализация

`scripts/apa_bdd_native_first_window_scene_writer.py`: **не дополнительный writer** и **не прямой Tapir**. Использует `archicad_project_accelerator.native_command_router()`, `prepare_native_task()`, действующий `archicad_dynamic_commands.DynamicCommands.execute()` и **`archicad_scene_run.SceneWriter.execute_bound_operation()`** с одним штатным SQLite журналом `intent-before-write`.

- До записи: точные пути исходного/рабочего PLN, хеш источника, версия/сборка/порт Archicad 29 build 5101 / 19727, 261 GUID, GUID хозяина, нативные параметры стены.
- Проверка графа: `GetDetailsOfElements` существующего хозяина → `CreateWindows`, источник утверждает явный смещённый размер.
- Резервная копия рабочего PLN с побайтовой проверкой хэша.
- Перед созданием: полный набор 260 `retained_signatures` через штатный дамп APA и проверка неизменности модели. Если полный дамп недоступен — **отказ без записи**, а не отключение проверки.
- Сама команда записывается заранее в штатный durable SQLite журнал; единственный native CreateWindows без повторной отправки.
- После native ответа: тип Window, родитель Wall GUID, этаж 0, ширина/высота/подоконник/offset, ровно 1 добавленный GUID, реальное изменение BREP стены и сохранность геометрических сигнатур оставшихся элементов.
- `SceneWriter` по умолчанию **не изменился в поведении**. Лишь явный `allow_3d_view_for_write=True` для уникально разрешённой текущей сохранённой копии допускает активное 3D (`actStory=-1`), когда штатный `GetModelDumpV1` активировал 3D. При этом путь, SHA, реальная карта этажей и истинный floor0 индекс обязательно подтверждаются. Если этаж 1/2 активен — отказ.

### Сохранение

Нативный `CreateWindows` изменяет активный рабочий PLN **в памяти Archicad**. При `NATIVE WINDOW LIVE PASS` оператор должен нажать **Ctrl+S**, чтобы зафиксировать результат в *уже открытой рабочей копии*. Это намеренно не отправляется другим нескоупированным SaveProject. Не сохранять, если есть ошибки `PARTIAL_OR_UNKNOWN_OUTCOME` — нужен разбор конкретного GUID/модели.

## Локальная команда

```powershell
$ErrorActionPreference = "Stop"
$dir = Join-Path $env:TEMP ("APA_BDD_Window1p8_" + [DateTime]::UtcNow.ToString("yyyyMMdd_HHmmss"))
gh repo clone dvikt33-ux/safe-bim-layer $dir -- --depth 1 --branch feature/apa-bdd-native-window-1p8-20261016
if ($LASTEXITCODE -ne 0) { throw "GitHub clone failed" }
$py = "$env:APPDATA\uv\tools\archicad-mcp-server\Scripts\python.exe"
& $py (Join-Path $dir "scripts\apa_bdd_native_first_window_scene_writer.py") --apply --publish
Write-Host "APA_WINDOW_EXIT_CODE=$LASTEXITCODE"
```

Первое выполнение **не повторять** даже при ошибке: журнал и частичный результат нужно сверять с текущим PLN и новой квитанцией.

Вся успешная/неуспешная информация автоматически публикуется в `safe-bim-bridge/safe-bim-mailbox/gpt-live/results/apa-bdd-scene-writer-window-1p8-*.json`, не нужна пересылка логов. Финальная отделка и библиотечная створка требуют отдельной визуальной/детальной сверки с PDF.
