# BDD дом — 16 колонн, 16 нативных сегментов: расследование остановки (16.10.2026)

## Подтверждённые доказательства

- Исходный PLN: `C:\LocalAI\SafeBIM_Global_Library_Test_Projects\BDD дом .pln`. Его исходные 21 GUID не потеряны.
- Активная рабочая копия Archicad 29.2.1 (build 5101): `C:\LocalAI\SafeBIM_Global_Library_Test_Projects\BDD дом - по чертежам 2022.pln`, порт 19727.
- Первичный аварийный лог строительного исполнителя: `Unexpected element count or foreign write during 49 bored piles`, стадия создания первой партии из 16 свай.
- Read-only диагностика: https://github.com/dvikt33-ux/safe-bim-bridge/blob/main/safe-bim-mailbox/gpt-live/results/apa-bdd-first-batch-diagnostic-20261016T140357Z-28aa6dc0.json
- В модели 53 GUID: исходных 21 + `Column` 16 + `ColumnSegment` 16; `missingOriginalCount=0`, `readErrors=[]`.
- Все 16 физических колонн имеют диаметр 300 мм, высоту 2400 мм, вертикальные отметки от -3.000 до -0.600 м, координаты совпадают с первыми 16 точками `PILES[:16]` извлечёнными из PDF.
- `ColumnSegment` — вложенный нативный элемент Archicad, возвращённый GetAllElements отдельно, с невалидным sentinel bounding box (xMin ~ 1e35, xMax ~ -1e35). Нельзя считать сегмент ещё одной физической сваей.

## Корневая причина

Старый `record_stage()` ожидал `len(after - prior) == len(batch)` (16), хотя Archicad вернул 32 GUID (16 родительских колонн и 16 дочерних сегментов). Проверка завершила процесс после фактического создания, но ДО записи успешной партии в `house_native_manifest.json` (`stagesRecorded=0`). Никаких доказательств создания следующих партий свай нет.

## Исправление

- Новая безопасная одноразовая процедура восстановления `scripts/apa_bdd_house_safe_resume.py`.
- Перед записью требует точный путь рабочей копии, правильную версию/сборку Archicad, исходный SHA256 и все 21 исходных GUID, а также ТОЧНО известные 16 GUID Column и 16 ColumnSegment из отчёта.
- Сверяет координаты и параметры каждой из 16 свай с геометрией первой партии, а не просто считает элементы.
- Отдельно учитывает возвращаемые командой физические GUID и дополнительные внутренние элементы Archicad; перед каждым вызовом записывает `inFlight`, затем полученный набор новых GUID до последующей геометрической проверки.
- Сохраняет только рабочий PLN, исходный не перезаписывает, при несовпадениях останавливается без повторного создания.
- Проверка на GitHub Actions: компиляция и моделирование восстановления на данных той же формы, что у Archicad: **OFFLINE PASS**. Реального продолжения строительства через эту процедуру ещё не выполнялось: **NOT_LIVE_TESTED**.

## Дальнейшие действия

Не запускать `apa_bdd_house_native_builder.py` повторно: он требует исходный активный PLN, новая копия уже существует и первая партия физических свай создана. Для продолжения в локальном Archicad нужно выполнить один раз подготовленную процедуру восстановления. После выполнения проверить GitHub отчёт `apa-bdd-native-build-*.json` и новые нативные GUID, а не только статистику. Не утверждать, что весь дом построен, пока не восстановлены все конструктивные компоненты, окна, двери и истинная геометрия кровли.
