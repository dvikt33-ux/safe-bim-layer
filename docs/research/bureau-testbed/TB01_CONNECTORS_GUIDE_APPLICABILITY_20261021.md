## 1. Действительно полезное открытие
Инструменты доступны через **существующие официальные MCP-серверы** — не нужно писать собственные адаптеры для каждой платформы. Вместе с тем установка MCP даёт агенту инструменты, а не делает бюро автономным и не обеспечивает надёжной маршрутизации, памяти, проверки источников, подтверждений или работы без хоста.

На 21.10.2026 удалось фактически получить полный Markdown предложенного гайда с публичного URL через Firecrawl scrape (HTTP 200). Это проверка *одного публичного чтения*, не установленного Firecrawl на Windows, не рабочего коннектора Codex и не LIVE тестов T01—T26.

## 2. Сопоставление с текущей системой
| Коннектор | Что даёт ТБ-01 | Уже имеющееся / дополнительный смысл | Порядок |
|---|---|---|---|
| Firecrawl | Scrape/crawl/search источников, страницы Markdown/JSON, мониторинг изменений | Работает как альтернативный слой чтения веб-источников; одно публичное чтение гайда подтверждено | G1, sandbox read-only |
| Playwright MCP | Управление web-страницами по DOM и изолированное тестирование интерфейсов | Конкурент Opera/Automa на отдельном test browser; избегать доступа к рабочим чатам | G1, самое важное испытание |
| Composio | OAuth + поиск и запуск готовых действий внешних сервисов | GitHub и Google Drive **уже доступны прямыми интеграциями**; Composio имеет смысл только если реально закрывает недостающие действия или улучшает управление полномочиями | G2, только scoped sandbox |
| Perplexity MCP | Search/Ask/Research/Reason и ссылки | Поиск уже возможен через имеющиеся средства; API платный и отдельно от подписок; запускать при обоснованном тестовом бюджете | G2, ограниченный запрос |
| PostHog MCP | Чтение реальной телеметрии о выполнении агента/интеграциях | Пока нет инструментированных LIVE циклов, подключать нечего; PostHog без event instrumentation не узнаёт про PR #187 | G3, после метрик |

## 3. Поправки к гайду для нашего конкретного окружения
1. Гайд предлагает общий промпт на установку всех пяти серверов. **Для ТБ-01 это неправильный порядок**: сначала инвентаризация и тестирование одного сервера, потом постепенное подключение. Не менять глобальные настройки без необходимости, не дублировать названия существующих MCP.
2. OpenAI описывает конфигурацию Codex не только на пользовательском уровне `~/.codex/config.toml`, но и в **доверенном проекте** `.codex/config.toml` (документация https://developers.openai.com/docs/config-file/config-basic). Предпочтителен изолированный временный рабочий каталог ТБ-01; не публиковать реальные локальные пути/ключи и не менять основной конфиг APA. Перед применением — читать точную документацию текущей версии Codex.
3. Документация подтверждает общую конфигурацию **Codex CLI и IDE** (https://developers.openai.com/learn/docs-mcp), но не даёт достаточного основания утверждать, что любой сервер после `codex mcp add` автоматически появляется в любой беседе **обычного ChatGPT desktop/web**. Для ChatGPT использовать прямое подключение через Plugins с отдельным OAuth/политикой; https://developers.openai.com/api/docs/guides/custom-mcp-server .
4. Не считать Playwright security boundary. Изолированный профиль `--isolated` не сохраняет состояние и не даёт доступа к уже авторизованной Opera; механизм Chrome/Edge extension или CDP с Opera потребует отдельного подтверждения. Тестировать на фиктивном приложении, затем на отдельных тестовых чатах — не на живых адресатах PR #187. Источник: https://github.com/microsoft/playwright-mcp .
5. PostHog MCP доступен только если действительно создан проект, поступают события/логирование/ошибки и настроены права. Чтение `?readonly=true` и ограниченные scopes предпочтительны до приёмки. https://posthog.com/docs/model-context-protocol/faq .
6. Composio Connect имеет мета-инструменты открытия и запуска *других* инструментов; это расширяет поверхность полномочий, не автоматически снижая риск. Связать только **изолированные тестовые** учётные записи, сравнить с прямыми подключениями: https://docs.composio.dev/docs/composio-connect .
7. Автор гайда не проводил установку/авторизацию — предложенные форматы команд и тарифы должны повторно подтверждаться по официальным источникам, актуальной версии клиента, бюджету и реальному выводу `codex mcp list`.
8. Не писать API-ключи в промпт/PR, не выполнять `curl | sh` без отдельного аудита сценария, не менять `AGENTS.md` текущего APA, не выдавать доказательство вызова MCP за достоверность исследования.

## 4. Контрольная последовательность (операции, ещё не выполненные на Windows)
- ПРЕДВАРИТЕЛЬНО: в копии ТБ-01 проверить `node --version`, `codex --version`, `codex mcp list`, существующие конфигурации, резервирование; определить конфликтные имена и права.
- A: в проектный sandbox Codex **только** Firecrawl MCP на чтение; OAuth подтверждается пользователем в браузере. Проба: получить эту страницу, сохранить URL/время/хеш/высказывания, отличить доступный оригинал от вывода агрегатора.
- B: отдельно настроить Playwright MCP с `--isolated` и `--caps=testing` после фиксации совместимой версии. Проба: тестовая страница → элемент → подтверждение → закрытие → повтор, без записи в действующие чаты. Сопоставить с Automa.
- C: Composio — **только если** прямые Google Drive/GitHub соединения не выполняют ограниченную test-функцию; точная OAuth-область и отзыв права после теста.
- D: Perplexity — после утверждённого предельного бюджета; проверять 10 одинаковых запросов, ссылочность/давность/стоимость против доступного поиска.
- E: PostHog — после появления событий завершения/ошибки/аудита: собрать только jobId, stage, duration, error category и расход (без контента, PII, URL чатов, cookie, токенов); сравнить с SQLite/GitHub receipts.

## 5. Надёжность и отсутствие зависимости от руководителя
Каждый инструмент подключается *как исполнитель/наблюдатель* к ГАП, а не становится вторым ГАП. Нужны один owner изменяемого статуса, дедупликация и подтверждение записи, durable queue, независимая приёмка документов, источник истины и сохранение решений вне чата. Связь MCP сама по себе не гарантирует выполнение без работы компьютера.

## 6. Критерий «готово»
**Не достаточно:** сервер появился в `codex mcp list`, OAuth пройден, команда отвечает.
**Требуется:** для каждой интеграции фиксация версии, прав, стоимости, двух успешных повторяемых реальных вызовов с получением фактов и недопустимого/ошибочного вызова, проверяемое закрытие доступа, логирование, возврат при сбое, отсутствие дублей и независимая ревизия. Для UI-взаимодействия — отдельно корректное различение состояния отправки сообщения и статуса окончательной приёмки.
