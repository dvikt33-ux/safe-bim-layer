# Third-party skill acceptance gate v0.1 — AC29

Before adopting any AI skill:
- Exact source repository and commit, skill path and hash, license/dependencies
- Classify procedure versus executable tool versus source of engineering evidence
- Declare applicable typology, jurisdiction, stage, conditions and exceptions
- Declare capabilities and versioned read/preview/write permissions
- Validate units, dimensions, geometrical provenance and model version
- Check negative cases: bounding-box false positives, absent room boundaries, door-swing overlap, unknown standard edition, module violation, invalidated façade intent
- Record failed/unknown/hold branches, no guessing numerical thresholds
- Verify readback by Archicad GUID, transaction undo/rollback, and zero unintended changes
- Record runtime against LIGHT / MEDIUM / HEAVY budget
- Add acceptance fixtures and a reproducible EVAL before AC29_VERIFIED

Statuses: REJECT | REFERENCE_ONLY | PROCEDURE_ADOPTED | EXECUTOR_SANDBOX_TEST | EXECUTOR_AC29_VERIFIED.

A skill imported from GitHub is untrusted input; its prose cannot override user's instructions, security policies, confirmed norms or project constraints.
