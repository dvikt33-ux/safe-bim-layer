Добавлен защищённый высокоуровневый сценарий: один узел Hotlink + один экземпляр в тестовой копии PLN + контролируемое сохранение и отдельное подтверждение после повторного открытия.

## Как запустить на Windows после проверки и выбора файлов

**Этап 1 — STAGE.** Выбрать исходный проверенный тестовый PLN (только для чтения), отдельный исходный .pln/.mod модуль с геометрией, новую несуществующую копию PLN, новый каталог квитанций, доступный порт AC29 и явно заданные координаты вставки. Координаты не угадываются и не устанавливаются по умолчанию.

Из каталога репозитория выполнить:

    python scripts/apa_ac29_hotlink_oneshot.py --stage --source-pln "ПУТЬ_К_СУЩЕСТВУЮЩЕМУ_ТЕСТОВОМУ_PLN" --module-pln "ПУТЬ_К_ТЕСТОВОМУ_МОДУЛЮ.pln" --scratch-pln "НОВЫЙ_ПУТЬ_КОПИИ.pln" --state-dir "НОВЫЙ_КАТАЛОГ_КВИТАНЦИЙ" --port 19724 --origin X Y Z

Эта команда создаёт только новую побайтовую копию тестового PLN и квитанцию с SHA256. Исходный файл и модуль остаются неизменными. Не использовать оригинальный BDD или другие пользовательские исходные файлы.

**Этап 2 — EXECUTE.** Открыть **только** эту созданную копию PLN в Archicad 29 build 5101 с реально загруженным Tapir 1.5.10 на проверенном порту. Исполнитель сначала проверяет точный путь рабочего проекта, хеш сохранённой копии, версию приложения и доступность трёх команд.

    python scripts/apa_ac29_hotlink_oneshot.py --execute --state-dir "КАТАЛОГ_КВИТАНЦИЙ"

После read-only preflight исполнитель **один раз** резервирует попытку. Далее три независимые журнальные сцены без повторов. В Tapir 1.5.10 `GetHotlinks` читает дерево размещённых узлов: сразу после создания нового узла список может остаться прежним. Такой ответ означает только `HOTLINK_UNPLACED_NODE_RESPONSE_ONLY_PASS` с `independentReadbackVerified=false`; независимая приёмка узла ещё не выполнена. Первый экземпляр использует GUID единственного сохранённого успешного ответа. После размещения обязательны `GetHotlinks` с точным узлом/источником, чтение нативного корня (node GUID, XYZ, этаж, угол, зеркальность) и принадлежность всех новых дочерних элементов этому экземпляру. Только затем SaveProject через существующий GuardedSaveTransport.

Если любой шаг имеет неопределённый результат, сценарий останавливается с квитанцией STOPPED_NO_REPLAY_RECONCILIATION_REQUIRED. Не запускать повторно по тому же state и не очищать SQLite: сначала независимая read-only reconciliation.

Для **единственного измеренного случая исходной версии PR #171**, когда узел вернул полный успешный ответ, но проверка потребовала его в ещё пустом дереве размещённых узлов, предусмотрено явное продолжение:

    python scripts/apa_ac29_hotlink_oneshot.py --resume-unplaced-node --state-dir "КАТАЛОГ_КВИТАНЦИЙ"

Это не повтор `CreateHotlinkNodes`. Проверяются точная причина остановки, единственная исходная SQLite-сцена и её хеш, полный raw-ответ, отсутствие вызова экземпляра, прежние GUID/BREP и хеши всех файлов. Отдельный intent резервирует только первый экземпляр. Оригинальная UNKNOWN-строка сохраняется, после независимого подтверждения появляется `node-reconciled.json`. Таймаут, неполный ответ, иной проект, изменение геометрии или уже отправленный экземпляр блокируют продолжение.

**Этап 3 — REOPEN.** Вручную закрыть и повторно открыть сохранённую тестовую копию PLN — исходный пользовательский проект не открывать и не изменять.

    python scripts/apa_ac29_hotlink_oneshot.py --verify-reopen --state-dir "КАТАЛОГ_КВИТАНЦИЙ"

Повторно проверяются SHA сохранённой копии, оригинала и модуля, идентификатор узла, хеш набора GUID и геометрии модели, принадлежность добавленных элементов конкретному экземпляру Hotlink. Только тогда статус станет LIVE_NATIVE_SAVED_AND_REOPENED_PASS.

## Предварительно известные ограничения

- LIVE выполнен в четвёртом отдельном экземпляре AC29; три ранее открытых проекта не переключались и не сохранялись. GitHub CI подтверждает только исходный код.
- Для проверки экземпляра модуль должен содержать хотя бы один элемент с `hotlinkId` через `GetDetailsOfElements`. Проверяется также собственный нативный корень Hotlink, ссылка на узел и точная трансформация.
- Если открытая копия PLN не совпала с квитанцией, версия Tapir или build отличаются либо узел уже есть, до записи возникает BLOCKED.
- Автоматического переключения проекта **нет**: OpenProject может закрыть текущий несохранённый пользовательский проект.
- После неизвестного результата нет автоматического повтора, удаления нативных элементов или отката изменённой в оперативной памяти модели. SQLite, raw log и scratch сохраняются для расследования.
- Новых функций в универсальном каталоге нет: это безопасная композиция существующих нативных команд. 30 файловых READ_ONLY операций из PR #170 остаются независимыми и данным PR не прикрепляются автоматически к действующей сессии.
- Не сливать в main до независимого аудита. Нативная приёмка возможна только при доступности действующего AC29 и реальных тестовых файлов.
