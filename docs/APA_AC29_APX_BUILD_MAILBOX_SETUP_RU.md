# APA 29 — локальная сборка APX по заданию из GitHub

Статус: **исходники интегрированы; локальный исполнитель ещё должен быть запущен пользователем**.
Этот канал выполняет **только сборку**, не устанавливает APX, не открывает Archicad,
не изменяет PLN и не вызывает команды записи в модель.

## Что переиспользовано

- Действующий репозиторий обмена: dvikt33-ux/safe-bim-bridge.
- GitHub CLI \`gh\` и локальный Git; никакого проброса локальных портов или публичного сервера.
- \`archicad-addon/Examples/build_model_dump.py\`: имеющийся сборщик на Graphisoft DevKit 29 + MSVC/CMake.
- Публичные SDK-модули из текущей исходной ветки APA 29, включая команды работы с группами.

Новый скрипт \`scripts/apa_ac29_apx_build_mailbox.py\` — минимальная связка,
а не новая система моделирования. Приёмник действующего BDD-моста не меняется.

## Первый запуск (Windows PowerShell)

Установленные программы: Archicad 29 DevKit, Visual Studio C++ (MSVC),
Windows SDK, CMake, Python 3, Git и GitHub CLI \`gh\`. Для GitHub CLI
нужна авторизация \`gh auth login\` с доступом к обоим репозиториям.

1. Если исходников \`safe-bim-layer\` нет локально, выполнить **один раз**:

   \`\`\`powershell
   gh repo clone dvikt33-ux/safe-bim-layer C:\LocalAI\APA_AC29_Build_Source -- --branch feature/apa-ac29-mailbox-apx-build-20261018
   \`\`\`

   Если уже есть Git-копия, можно использовать её. Но запускать нужно именно
   \`Start-APA-AC29-BuildMailbox.ps1\` из рабочей ветки интеграции.

2. Выполнить проверку подключения (вместо \`<APPROVED_COMMIT_SHA>\` вставить
   40-символьный SHA коммита, переданный в сообщении о готовности):

   \`\`\`powershell
   & "C:\LocalAI\APA_AC29_Build_Source\scripts\Start-APA-AC29-BuildMailbox.ps1" -ApprovedSha "<APPROVED_COMMIT_SHA>" -Healthcheck
   \`\`\`

   При первом запуске будут запрошены **два локальных пути**:
   - папка уже существующего Git-репозитория Tapir 1.5.10 (с каталогом \`.git\`);
   - каталог \`Support\` комплекта Graphisoft Archicad 29 DevKit.

   Пути сохраняются в \`%LOCALAPPDATA%\APA_AC29_APX_BuildMailbox\paths.json\`.
   Эти пути не передаются в GitHub как часть задания.

3. Для одного прохода по входящим заданиям:

   \`\`\`powershell
   & "C:\LocalAI\APA_AC29_Build_Source\scripts\Start-APA-AC29-BuildMailbox.ps1" -ApprovedSha "<APPROVED_COMMIT_SHA>"
   \`\`\`

   После подтверждения одноразового цикла можно добавить \`-Loop\`
   для периодического опроса (30 секунд). Во время первой сборки не требуется
   запускать Archicad или переключать проекты.

## Протокол

Репозиторий: \`dvikt33-ux/safe-bim-bridge\`.
Отдельная ветка: \`feature/apa-ac29-apx-build-mailbox-20261018\`.
Входящие: \`safe-bim-mailbox/apa-ac29-apx-build/jobs/apx-*.json\`.
Результаты: \`safe-bim-mailbox/apa-ac29-apx-build/results/apx-*.json\`.

Поля входящего задания: \`schema\`, \`jobId\`, \`action\`,
\`repo\`, \`commit\`, \`createdAt\`, \`expiresAt\`.
Разрешено только \`action = BUILD_APX_ONLY\`. \`commit\` должен строго
совпадать с \`-ApprovedSha\`, заданным **на компьютере**. Срок жизни
задания — не более двух суток.

Приёмник делает \`git fetch\` только для одобренного коммита, создаёт
временное рабочее дерево Git и запускает **единственный фиксированный**
сборочный сценарий. Команда, сценарий, рабочий каталог, файлы модели,
конфигурация сборщика и исполняемые программы не могут подменяться полями задания.

Приёмник фиксирует попытку на диске до сборки и **не повторяет её автоматически**
при неопределённом исходе. Результат GitHub неизменяем: повторная
публикация допускается только при побайтово эквивалентных данных.
Сборочный журнал и APX остаются **на локальном компьютере**;
в GitHub попадает сводка, хеш лога, последние строки и хеш бинарника.

## Состояния

- \`APA_AC29_BUILD_MAILBOX_HEALTHCHECK_PASS_NO_MODEL_CALLS\` — локальные пути,
  GitHub CLI и исходная Git-копия доступны. **Это ещё не сборка APX.**
- \`BUILD_PASS_BINARY_NOT_INSTALLED\` — компилятор завершил работу,
  получена штатная квитанция сборщика о совпадении бинарника и идентификатора.
  **Не означает, что API-команды успешно зарегистрированы или проверены в Archicad.**
- \`BUILD_FAILED\` — компилятор вернул ошибку; смотреть \`logTail\`.
- \`BUILD_BLOCKED\` — не прошли защита/предусловия или не удалось завершить процесс.
- \`PREVIOUS_ATTEMPT_REQUIRES_MANUAL_RECONCILIATION\` — прерванная попытка,
  автоматический повтор заблокирован.

## Границы и следующий шаг

Данный этап не даёт ChatGPT произвольный доступ к Windows. Он даёт
одну разрешённую операцию **собрать APX на фиксированном коммите** и вернуть результат.
Установка APX, контроль версии загруженного аддона, проверка групповых операций
и запись в BDD потребуют отдельных явно разрешённых действий и квитанций.

Не изменять \`main\`, основной \`arena/local-agent-v0\`, исходные PLN и действующий
\`AI Dispatcher\` ради настройки этой сборки.
