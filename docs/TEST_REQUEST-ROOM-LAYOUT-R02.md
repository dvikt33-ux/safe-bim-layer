# Нативная приёмка планировщика APA R02

Начните с чтения атрибутов и предконтроля в Archicad 30 на новой отдельной копии PLN. Нативное построение проводится отдельно после проверки квитанции предконтроля и явного допуска. Расчёт и сверка используют существующие Semantic Brief, BIM Graph, Tapir, SceneWriter и SQLite. [Требования R02](https://docs.google.com/document/d/1WBZewlSBqe3d0auFcznmRgWoiuPhhV58n3KrgEAST38/edit?usp=drivesdk) · [План разработки](https://docs.google.com/document/d/18-NOWxSewm0uaN9T0onYXjMOeJRW5PuX8tCGYH34QDw/edit?usp=drivesdk)

## 2. Предконтроль и последующая нативная приёмка

1. Используйте профиль `room-layout-profile.json` подготовленного комплекта на действующем частном маршруте MCP. Команда локального запуска профиля приведена ниже. В `apa_read(kind="status")` должны быть видны цель `layout-mcp-r02-zone-auto-01` и ревизия скачанного выпуска. При недоступном туннеле выполните два локальных чтения из раздела 3 и отдельно отметьте, что частное подключение ещё ожидает проверки.
2. Передайте содержимое примера в `apa_execute(operation="plan", job_id="r02-plan", intent=<JSON>)`. Через `apa_read(kind="job", job_id="r02-plan")` получите `LAYOUT_PLAN_VALIDATED_OFFLINE`, 9 операций и план двух областей. В отдельном вызове `r02-missing` передайте только поле `schemaVersion`. Ожидайте `LAYOUT_INPUT_REQUIRED` с конкретными вопросами.
3. Откройте указанную выше тестовую PLN. Для `layout-mcp-r02-zone-auto-01` вызовите `native-read` с ID `r02-attributes`. Ожидайте `LAYOUT_NATIVE_ATTRIBUTES_READ`, `modelWrites = 0` и `zoneCategorySelection.status = RESOLVED`. Сверьте `zoneCategorySelection.rooms.hall` и `zoneCategorySelection.rooms.living` с таблицей, включая разные GUID. Дополнительно сверяются материал «Кирпич», библиотека Door и точный путь PLN. Если категория отсутствует или неоднозначна, квитанция показывает причину. Для неизвестного назначения уточните, для чего служит помещение. Техническое имя атрибута в новом задании не требуется.
4. Вызовите `preflight` с ID `r02-preflight`, прочитайте `READY_FOR_EXPLICIT_TEST_RUN` по тому же ID. Сверьте точный путь, Archicad 30, PID/порт, этаж, APX, обе пространственные области, `facts.zoneCategories`, `facts.retainedDetailsSha256` и `modelWrites = 0`. Сохраните вывод и квитанции. При отказе передайте точную причину и папку журнала. **На этом заканчивается проверка исправленного предконтроля. Пункты 5–8 выполняются после отдельного допуска.**
5. Утвердите состав и размеры и локально выпустите допуск под новый ID `r02-write` по команде ниже. В обычном ChatGPT вызовите `write` с этим ID и целью `layout-mcp-r02-zone-auto-01`. Дождитесь `SAVED_PENDING_REAL_REOPEN`. Проверьте 9 различных GUID в поле `operationReadback.addedGuids` файла `saved.json`. В принимаемой области новых элементов на этом шаге быть не должно. Повтор запроса с тем же ID должен вернуть тот же результат. Журнал и число элементов должны совпасть.
6. Закройте испытательную PLN штатно. Вызовите `check-closed` с ID `r02-closed`. Снова откройте тот же файл и вызовите `verify-reopen` с ID `r02-reopen`. Ожидайте `SAVE_REOPEN_VERIFIED`, совпадение SHA, GUID, 3D-сигнатур, параметров и площадей. Выделите каждый предусмотренный тип и откройте его настройки, чтобы увидеть редактируемые параметры. Отмените открытые диалоги настроек.
7. В той же открытой PLN выделите весь фрагмент экспериментальной области. Штатной командой Archicad «Переместить копию» перенесите фрагмент по глобальной X на +13 000 мм и Y на 0. Включите обе Zone в выделение. Двери должны перейти вместе с их стенами. Перед сохранением вызовите `verify-inclusion` с ID `r02-inclusion`. Ожидайте `LAYOUT_USER_COPY_VERIFIED`, 9 новых GUID, сохранённые исходные GUID и `verificationNativeWrites = 0`. Проверьте конструкцию, слои, библиотечную деталь Door, категорию Zone, связи и площади. Если проверка не прошла, сохраните сообщение, отмените непроверенный перенос средствами Archicad и оставьте сохранённый испытательный снимок доступным.
8. После успешной проверки можно сохранить испытательный файл с участком включения. Для возврата результатов подготовьте квитанции, перечисленные ниже, и снимки обеих областей и параметров Wall, Door и Zone. Для продуктовой приёмки повторите сценарий с изменёнными согласованными размерами, неизменной исходной резервной копией и отдельным ID задания.

В пунктах 3–7 аргумент `target` равен `layout-mcp-r02-zone-auto-01`. После каждого `apa_execute` прочитайте `apa_read(kind="job", job_id=<тот же ID>)`. Для полного плана доступны страницы `apa_read(kind="receipt", job_id="r02-plan", artifact="plan", offset=0)`.

## 3. Команды оператора

В отдельном окне PowerShell запустите тестовый профиль на локальном порту, который указан в действующем частном подключении. Для отдельного тестового подключения можно использовать выделенный порт 18788. Первая команда использует штатный Windows-запуск APA.

```powershell
$Release = 'C:\Users\Admin\Documents\ChatGPT\настройка адитор\APA-R02-Layout-20261118'
$App = Join-Path $Release 'APA-Windows'
$Job = Join-Path $Release 'layout-mcp-r02-zone-auto-01'
$Profile = Join-Path $Release 'room-layout-profile.json'
& (Join-Path $App 'Start-APA.cmd') --mcp-profile $Profile --mcp-port 18788
```

Для отдельного допуска на этапе построения откройте PowerShell с теми же переменными и проверьте файл `$Job\preflight.json`.

```powershell
$Py = Join-Path $App '.apa-runtime\Scripts\python.exe'
$Apa = Join-Path $App 'apa.py'
$Approval = (Get-FileHash -LiteralPath (Join-Path $Job 'preflight.json') -Algorithm SHA256).Hash.ToLowerInvariant()
& $Py -I -B -X utf8 $Apa mcp-control --profile $Profile --grant r02-write layout-mcp-r02-zone-auto-01 $Approval
```

Если обычный ChatGPT ещё не видит тестовый профиль, для этапа A достаточно штатных локальных команд чтения. Используйте переменные из начала раздела. Чатовый маршрут проверяется отдельно.

```powershell
$Py = Join-Path $App '.apa-runtime\Scripts\python.exe'
$Apa = Join-Path $App 'apa.py'
& $Py -I -B -X utf8 $Apa ac30-native layout-attributes --job $Job
& $Py -I -B -X utf8 $Apa ac30-native preflight --job $Job
```

Для отдельно допущенного этапа B используйте штатный MCP или локальную последовательность после проверки текущего SHA.

```powershell
# После локального утверждения 64-значного хеша использовать только этот запуск или MCP write.
& $Py -I -B -X utf8 $Apa ac30-native execute --job $Job --confirm-preflight $Approval
# Выполнять пункты 6 и 7 между этими проверками.
& $Py -I -B -X utf8 $Apa ac30-native verify-closed --job $Job
& $Py -I -B -X utf8 $Apa ac30-native verify-reopen --job $Job
& $Py -I -B -X utf8 $Apa ac30-native verify-inclusion --job $Job
```

Для другого задания создайте новые копии по `apa.py ac30-native stage-layout --help`, затем `apa.py mcp-control --profile <новый профиль> --prepare-layout <новый каталог layout-mcp-*>`. Поддерживаемый вход включает от двух до пяти прямоугольных помещений общей глубины в ряд, одну входную дверь и двери в соседних перегородках. Окна и произвольные контуры отклоняются с диагностикой. Инструмент сохраняет граф зависимостей расчёта и проверяет собственную копию готового фрагмента.

Обычных названий «Холл» и «Гостиная» достаточно. Если название условное, например «Помещение А», укажите его назначение обычными словами, например `"purpose": "транзитное помещение"`. Поле `zoneCategoryName` сохранено для воспроизводимости прежних изолированных геометрических испытаний. В новых пользовательских заданиях подбор выполняется по назначению каждой комнаты.

## 4. Доказательства

Верните `job.json`, `preflight.json`, `attempted.json`, `saved.json`, `closed.json`, `reopened.json`, `inclusion.json`, хеш финальной PLN и квитанции MCP по ID вызовов. Сохраните SQLite-журнал и снимок проекта локально. При аварии передайте существующие файлы, точный этап и состояние модели. Повтор изменяющей команды при неизвестном результате требует сверки. Оригинальный донор и ранее принятые данные остаются средствами восстановления.

Контрольный отрицательный сценарий перед нативной записью: увеличьте `minPierMM` до 1000 только в копии входного JSON. Ожидайте `LAYOUT_MINIMUM_PIER` до построения графа при прежних положениях дверей. В основном проходе проверьте отказ `write` без локального допуска на отдельном ID. Оба отказа должны оставить геометрию и исходный файл без изменений.
