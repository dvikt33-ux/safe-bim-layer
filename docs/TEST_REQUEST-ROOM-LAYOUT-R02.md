# Нативная приёмка планировщика APA R02

Начните с чтения атрибутов и предконтроля в Archicad 30 на новой отдельной копии PLN. Нативное построение проводится отдельно после проверки квитанции предконтроля и явного допуска. Расчёт и сверка используют существующие Semantic Brief, BIM Graph, Tapir, SceneWriter и SQLite. ## 2. Предконтроль и последующая нативная приёмка

1. Используйте подготовленный профиль на действующем частном маршруте MCP. Команда запуска приведена ниже. В `apa_read(kind="status")` должны быть видны цель `layout-mcp-r02-wall-system-01` и ревизия из `apa-release.json` этого выпуска. При недоступном туннеле выполните два локальных чтения из раздела 3 и отдельно зафиксируйте состояние частного подключения.
2. Передайте содержимое примера в `apa_execute(operation="plan", job_id="r02-plan", intent=<JSON>)`. Через `apa_read(kind="job", job_id="r02-plan")` получите `LAYOUT_PLAN_VALIDATED_OFFLINE`, 9 операций и план двух областей. В отдельном вызове `r02-missing` передайте только поле `schemaVersion`. Ожидайте `LAYOUT_INPUT_REQUIRED` с конкретными вопросами.
3. Откройте указанную выше испытательную PLN `APA-AC30-layout-test.pln`. Для `layout-mcp-r02-wall-system-01` вызовите `native-read` с ID `r02-attributes`. Ожидайте `LAYOUT_NATIVE_ATTRIBUTES_READ`, `modelWrites = 0` и `zoneCategorySelection.status = RESOLVED`. Сверьте две категории, их GUID и наличие материала «Кирпич». При неоднозначности назначения помещения прочитайте причину в квитанции.
4. Вызовите `preflight` с ID `r02-preflight` и прочитайте `READY_FOR_EXPLICIT_TEST_RUN`. Сверьте путь, Archicad 30, PID/порт, этаж, APX, обе области, `facts.zoneCategories`, `facts.retainedDetailsSha256` и `modelWrites = 0`. Проверьте `facts.wallJunctionAttributes` с GUID слоя, ненулевой группой пересечений и приоритетом материала. В `facts.wallStrategy` ожидаются регистрация `CreateWalls`, `native_create_walls_batch`, 5 → 1 вызов стен и `OPTIMUM_NOT_PROVEN`. При расхождении сохраните точную причину отказа и папку журнала. **Пункты 5–8 выполняются после отдельного допуска на этот предконтроль.**
5. Утвердите состав и размеры. Локально выпустите допуск под новый ID `r02-write` по команде ниже. В обычном ChatGPT вызовите `write` с этим ID и подготовленной целью. Ожидайте `SAVED_PENDING_REAL_REOPEN`, 9 различных GUID, 1 вызов `CreateWalls` с 5 строками `wallsData` и 1 `SaveProject`. В `saved.json` проверьте `operationReadback.wallSystem` и `executionTrace`. В принимаемой области новых элементов на этом шаге быть не должно. Повтор того же ID должен прочитать прежнюю квитанцию с теми же GUID без нового нативного вызова.
6. Закройте испытательную PLN штатно. Вызовите `check-closed` с ID `r02-closed`. Снова откройте тот же файл и вызовите `verify-reopen` с ID `r02-reopen`. Ожидайте `SAVE_REOPEN_VERIFIED`, совпадение SHA, GUID, 3D-сигнатур, параметров, площадей и квитанции стыков. На плане и в 3D осмотрите все шесть узлов. Измерьте стены, чистые размеры помещений и положение дверей. Откройте настройки Wall, Door и Zone, чтобы увидеть родные редактируемые параметры. По каждому узлу отметьте просвет, выступ либо непрерывное сопряжение. Проверьте обе привязки дверей к хостам.
7. В той же открытой PLN выделите весь фрагмент экспериментальной области. Штатной командой Archicad «Переместить копию» перенесите фрагмент по глобальной X на +13 000 мм и Y на 0. Включите обе Zone в выделение. Двери должны перейти вместе с их стенами. Перед сохранением вызовите `verify-inclusion` с ID `r02-inclusion`. Ожидайте `LAYOUT_USER_COPY_VERIFIED`, 9 новых GUID, сохранённые исходные GUID и `verificationNativeWrites = 0`. Проверьте конструкцию, слои, библиотечную деталь Door, категорию Zone, связи и площади. Если проверка не прошла, сохраните сообщение, отмените непроверенный перенос средствами Archicad и оставьте сохранённый испытательный снимок доступным.
8. После успешной проверки можно сохранить испытательный файл с участком включения. Для возврата результатов подготовьте квитанции, перечисленные ниже, и снимки обеих областей и параметров Wall, Door и Zone. Для продуктовой приёмки повторите сценарий с изменёнными согласованными размерами, неизменной исходной резервной копией и отдельным ID задания.

В пунктах 3–7 аргумент `target` равен `layout-mcp-r02-wall-system-01`. После каждого `apa_execute` прочитайте `apa_read(kind="job", job_id=<тот же ID>)`. Для полного плана доступны страницы `apa_read(kind="receipt", job_id="r02-plan", artifact="plan", offset=0)`.

Верните скриншоты плана и 3D, GUID двух Wall и машинный дамп до закрытия и после открытия. Сценарий проверяет нативную очистку X. Расчёт углового X и разных толщин покрыт программным тестом, а нативное подтверждение других углов и многослойных стен ведётся отдельно. ## 3. Команды оператора

В отдельном окне PowerShell запустите тестовый профиль на локальном порту, который указан в действующем частном подключении. Для отдельного тестового подключения можно использовать выделенный порт 18788. Первая команда использует штатный Windows-запуск APA.

```powershell
$Release = 'C:\Users\Admin\Documents\ChatGPT\настройка адитор\APA-R02-Walls-20261118'
$App = Join-Path $Release 'APA-Windows'
$Job = Join-Path $Release 'layout-mcp-r02-wall-system-01'
$Profile = Join-Path $Release 'room-layout-profile.json'
& (Join-Path $App 'Start-APA.cmd') --mcp-profile $Profile --mcp-port 18788
```

Для отдельного допуска на этапе построения откройте PowerShell с теми же переменными и проверьте файл `$Job\preflight.json`.

```powershell
$Py = Join-Path $App '.apa-runtime\Scripts\python.exe'
$Apa = Join-Path $App 'apa.py'
$Approval = (Get-FileHash -LiteralPath (Join-Path $Job 'preflight.json') -Algorithm SHA256).Hash.ToLowerInvariant()
& $Py -I -B -X utf8 $Apa mcp-control --profile $Profile --grant r02-write layout-mcp-r02-wall-system-01 $Approval
```

Если обычный ChatGPT ещё не видит тестовый профиль, для этапа A достаточно штатных локальных команд чтения. Используйте переменные из начала раздела. Чатовый маршрут проверяется отдельно.

```powershell
$Py = Join-Path $App '.apa-runtime\Scripts\python.exe'
$Apa = Join-Path $App 'apa.py'
& $Py -I -B -X utf8 $Apa ac30-native layout-attributes --job $Job
& $Py -I -B -X utf8 $Apa ac30-native preflight --job $Job
```

Для отдельно допущенного этапа B используйте штатный MCP или локальную последовательность после проверки текущего SHA.

```powershell
# После локального утверждения 64-значного хеша использовать только этот запуск или MCP write.
& $Py -I -B -X utf8 $Apa ac30-native execute --job $Job --confirm-preflight $Approval
# Выполнять пункты 6 и 7 между этими проверками.
& $Py -I -B -X utf8 $Apa ac30-native verify-closed --job $Job
& $Py -I -B -X utf8 $Apa ac30-native verify-reopen --job $Job
& $Py -I -B -X utf8 $Apa ac30-native verify-inclusion --job $Job
```

Для другого задания создайте новые копии по `apa.py ac30-native stage-layout --help`, затем `apa.py mcp-control --profile <новый профиль> --prepare-layout <новый каталог layout-mcp-*>`. Поддерживаемый вход включает от двух до пяти прямоугольных помещений общей глубины в ряд, одну входную дверь и двери в соседних перегородках. Окна и произвольные контуры отклоняются с диагностикой. Инструмент сохраняет граф зависимостей расчёта и проверяет собственную копию готового фрагмента.

Обычных названий «Холл» и «Гостиная» достаточно. Если название условное, например «Помещение А», укажите его назначение обычными словами, например `"purpose": "транзитное помещение"`. Поле `zoneCategoryName` сохранено для воспроизводимости прежних изолированных геометрических испытаний. В новых пользовательских заданиях подбор выполняется по назначению каждой комнаты.

## 4. Доказательства

Верните из каталога задания `job.json`, `preflight.json`, `attempted.json`, `saved.json`, `closed.json`, `reopened.json`, `inclusion.json`, хеш финальной PLN, исходный `execute-*\raw.jsonl` и квитанции MCP по ID вызовов. Сохраните SQLite-журнал и снимок проекта локально. При частичном результате пакета, ошибке BREP или неизвестном исходе сохраните журналы и зафиксируйте видимое состояние. Для новой попытки после сверки используйте новую копию и новый допуск. При отказе на стыке значения `LAYOUT_WALL_JUNCTION_*` указывают, какую проверку остановило фактическое тело.

Для X снимите BREP локальной командой чтения. Укажите порт именно экземпляра с `APA-R02-X-test.pln` и передайте снимок окна с именем проекта. Повторите после открытия с новым именем выходного файла.

```powershell
$Dump = Join-Path $App 'archicad-addon\Examples\model_dump_v1.py'
$XPort = [int](Read-Host 'Порт API экземпляра с APA-R02-X-test.pln')
& $Py -I -B -X utf8 $Dump --port $XPort --out (Join-Path $Release 'junction-witness\before-close.json')
```

Контрольный отрицательный сценарий перед нативной записью: увеличьте `minPierMM` до 1000 только в копии входного JSON. Ожидайте `LAYOUT_MINIMUM_PIER` до построения графа при прежних положениях дверей. В основном проходе проверьте отказ `write` без локального допуска на отдельном ID. Оба отказа должны оставить геометрию и исходный файл без изменений.
