# Нативная приёмка планировщика APA R02

Выполните испытание в Archicad 30 из обычного ChatGPT через действующее частное подключение APA. В комплекте подготовлена отдельная копия PLN. Расчёт, предконтроль и сверка используют существующие Semantic Brief, BIM Graph, Tapir, SceneWriter и SQLite.

## 1. Подготовленная копия и ожидаемый результат

Пути на компьютере с подготовленным испытанием:

```text
C:\Users\Admin\Documents\ChatGPT\настройка адитор\APA-R02-Layout-20261117\APA-Windows
C:\Users\Admin\Documents\ChatGPT\настройка адитор\APA-R02-Layout-20261117\room-layout-profile.json
C:\Users\Admin\Documents\ChatGPT\настройка адитор\APA-R02-Layout-20261117\layout-mcp-r02-demo\model\APA-AC30-layout-test.pln
```

Входные параметры хранятся в `APA-Windows\examples\accelerator\two-room-layout.json`. На отметке 0 мм ожидаются:

| Что проверить | Ожидание |
| --- | --- |
| Состав в каждой области | 5 прямых Wall, 2 Door на своих стенах, 2 ручные Zone |
| Связи | Вход → холл → гостиная, у комнат общая перегородка с дверью |
| Чистые размеры | Холл 2590 × 3240 мм, гостиная 2630 × 3240 мм |
| Площади | 8,3916 и 8,5212 м², требуется не менее 8 м² на комнату |
| Стены | Кладочный профиль 1 НФ, модуль 130 мм в плане и 77 мм по высоте, толщина 120 мм и высота 2772 мм |
| Двери | Номинальные 1050 × 2079 мм, край проёма в 900 мм от начала стены, минимальный простенок 380 мм |
| Перенос | Копия вдоль мировой оси X на +13 000 мм, без разворота и с сохранением этажности |

Ожидаемая точность измеряемых линейных размеров и положений до 1 мм. Номинальный размер двери проверяется в параметрах Door. Чистый проход, строительная применимость конкретного материала и нормативная применимость проверяются по отдельным данным объекта.

## 2. Пройти один сценарий из обычного ChatGPT

1. Используйте профиль `room-layout-profile.json` подготовленного комплекта на действующем частном маршруте MCP. Команда локального запуска профиля приведена ниже. Проверьте `apa_read(kind="status")`: должен быть виден целевой тест `layout-mcp-r02-demo` и ревизия скачанного выпуска.
2. Передайте содержимое примера в `apa_execute(operation="plan", job_id="r02-plan", intent=<JSON>)`. Через `apa_read(kind="job", job_id="r02-plan")` получите `LAYOUT_PLAN_VALIDATED_OFFLINE`, 9 операций и план двух областей. В отдельном вызове `r02-missing` передайте только поле `schemaVersion`. Ожидайте `LAYOUT_INPUT_REQUIRED` с конкретными вопросами.
3. Откройте указанную выше тестовую PLN. Для `layout-mcp-r02-demo` вызовите `native-read` с ID `r02-attributes`. Прочитайте `LAYOUT_NATIVE_ATTRIBUTES_READ`. Проверьте единственность точных имён материала «Кирпич» и категории «Жилые помещения», наличие подходящей библиотеки Door и правильный PLN. Если имена отличаются, сформируйте новый тест из своего уточнённого JSON и нового уникального каталога. Существующий профиль привязан к SHA подготовленного задания.
4. Вызовите `preflight` с ID `r02-preflight`, прочитайте `READY_FOR_EXPLICIT_TEST_RUN` по тому же ID. Сверьте точный путь, Archicad 30, PID/порт, этаж, APX, обе пространственные области и `modelWrites = 0`. У приёмной области должен быть пространственный PASS. Если получен отказ, сохраните причину в квитанции. Для следующего пункта требуется точное подтверждение из текущего `preflight.json`.
5. Утвердите состав и размеры и локально выпустите допуск под новый ID `r02-write` по команде ниже. В обычном ChatGPT вызовите `write` с этим ID и целью `layout-mcp-r02-demo`. Дождитесь `SAVED_PENDING_REAL_REOPEN`. Проверьте 9 различных GUID в поле `operationReadback.addedGuids` файла `saved.json`. В принимаемой области новых элементов на этом шаге быть не должно. Повтор запроса с тем же ID должен вернуть тот же результат. Журнал и число элементов должны совпасть.
6. Закройте испытательную PLN штатно. Вызовите `check-closed` с ID `r02-closed`. Снова откройте тот же файл и вызовите `verify-reopen` с ID `r02-reopen`. Ожидайте `SAVE_REOPEN_VERIFIED`, совпадение SHA, GUID, 3D-сигнатур, параметров и площадей. Выделите каждый предусмотренный тип и откройте его настройки, чтобы увидеть редактируемые параметры. Отмените открытые диалоги настроек.
7. В той же открытой PLN выделите весь фрагмент экспериментальной области. Штатной командой Archicad «Переместить копию» перенесите фрагмент по глобальной X на +13 000 мм и Y на 0. Включите обе Zone в выделение. Двери должны перейти вместе с их стенами. Перед сохранением вызовите `verify-inclusion` с ID `r02-inclusion`. Ожидайте `LAYOUT_USER_COPY_VERIFIED`, 9 новых GUID, сохранённые исходные GUID и `verificationNativeWrites = 0`. Проверьте конструкцию, слои, библиотечную деталь Door, категорию Zone, связи и площади. Если проверка не прошла, сохраните сообщение, отмените непроверенный перенос средствами Archicad и оставьте сохранённый испытательный снимок доступным.
8. После успешной проверки можно сохранить испытательный файл с участком включения. Для возврата результатов подготовьте квитанции, перечисленные ниже, и снимки обеих областей и параметров Wall, Door и Zone. Для продуктовой приёмки повторите сценарий с изменёнными согласованными размерами, неизменной исходной резервной копией и отдельным ID задания.

В пунктах 3–7 аргумент `target` равен `layout-mcp-r02-demo`. После каждого `apa_execute` прочитайте `apa_read(kind="job", job_id=<тот же ID>)`. Для полного плана доступны страницы `apa_read(kind="receipt", job_id="r02-plan", artifact="plan", offset=0)`.

## 3. Команды оператора

В отдельном окне PowerShell запустите тестовый профиль на локальном порту, который указан в действующем частном подключении. Для отдельного тестового подключения можно использовать выделенный порт 18788. Первая команда использует штатный Windows-запуск APA.

```powershell
$Release = 'C:\Users\Admin\Documents\ChatGPT\настройка адитор\APA-R02-Layout-20261117'
$App = Join-Path $Release 'APA-Windows'
$Job = Join-Path $Release 'layout-mcp-r02-demo'
$Profile = Join-Path $Release 'room-layout-profile.json'
& (Join-Path $App 'Start-APA.cmd') --mcp-profile $Profile --mcp-port 18788
```

В том же PowerShell после запуска отдельного процесса профиля либо в другом окне с теми же переменными проверьте файл `$Job\preflight.json` и выполните допуск:

```powershell
$Py = Join-Path $App '.apa-runtime\Scripts\python.exe'
$Apa = Join-Path $App 'apa.py'
$Approval = (Get-FileHash -LiteralPath (Join-Path $Job 'preflight.json') -Algorithm SHA256).Hash.ToLowerInvariant()
& $Py -I -B -X utf8 $Apa mcp-control --profile $Profile --grant r02-write layout-mcp-r02-demo $Approval
```

Если обычный ChatGPT ещё не видит тестовый профиль, локальные проверки можно выполнить тем же исполнительным контуром. Для продуктовой приёмки необходимо отдельно подтвердить чатовый маршрут.

```powershell
& $Py -I -B -X utf8 $Apa ac30-native layout-attributes --job $Job
& $Py -I -B -X utf8 $Apa ac30-native preflight --job $Job
# После локального утверждения 64-значного хеша использовать только этот запуск или MCP write.
& $Py -I -B -X utf8 $Apa ac30-native execute --job $Job --confirm-preflight $Approval
# Выполнять пункты 6 и 7 между этими проверками.
& $Py -I -B -X utf8 $Apa ac30-native verify-closed --job $Job
& $Py -I -B -X utf8 $Apa ac30-native verify-reopen --job $Job
& $Py -I -B -X utf8 $Apa ac30-native verify-inclusion --job $Job
```

Для другого задания создайте новые копии по `apa.py ac30-native stage-layout --help`, затем `apa.py mcp-control --profile <новый профиль> --prepare-layout <новый каталог layout-mcp-*>`. Поддерживаемый вход включает от двух до пяти прямоугольных помещений общей глубины в ряд, одну входную дверь и двери в соседних перегородках. Окна и произвольные контуры отклоняются с диагностикой. Инструмент сохраняет граф зависимостей расчёта и проверяет собственную копию готового фрагмента.

## 4. Доказательства

Верните `job.json`, `preflight.json`, `attempted.json`, `saved.json`, `closed.json`, `reopened.json`, `inclusion.json`, хеш финальной PLN и квитанции MCP по ID вызовов. Сохраните SQLite-журнал и снимок проекта локально. При аварии передайте существующие файлы, точный этап и состояние модели. Повтор изменяющей команды при неизвестном результате требует сверки. Оригинальный донор и ранее принятые данные остаются средствами восстановления.

Контрольный отрицательный сценарий перед нативной записью: увеличьте `minPierMM` до 1000 только в копии входного JSON. Ожидайте `LAYOUT_MINIMUM_PIER` до построения графа при прежних положениях дверей. В основном проходе проверьте отказ `write` без локального допуска на отдельном ID. Оба отказа должны оставить геометрию и исходный файл без изменений.
