# APA 29 — изоляция GuardedSave от параллельных записей (SAFE-01)

**Дата:** 19.10.2026. **Статус:** SOURCE ПОДГОТОВЛЕН / OFFLINE CI ОЖИДАЕТ / INSTALLED NOT RUN / LIVE NOT RUN.

## Факты из LIVE-02 (PR №173)

В принятой пакетной операции 69→119 GUID и два экземпляра Hotlink за один CreateHotlinkInstances подтверждены после одного GuardedSave. Сразу после него исходная тестовая scratch PLN изменилась: её поздний SHA перестал совпадать с принятым `savedSHA256`. Неизменённая BPN позволила восстановить точные сохранённые байты и выполнить повторное открытие.

Это **не доказательство дефекта SaveProject и не доказательство, что виновен конкретный процесс**. Известно только, что между первоначальным сохранением и последующим контролем возникла дополнительная файловая запись. Не нужно повторять LIVE-02, пытаться вручную восстановить виновника или стирать чужую рабочую PLN.

## Что изменилось

- Новый `scripts/apa_ac29_save_isolation.py`. `ScratchWriteLease` резервирует **конкретный путь копии PLN** посредством атомарного создания `<scratch>.apa-write.lock`. Другой экземпляр APA, соблюдающий этот протокол, не сможет одновременно получить такую же бронь. При UNKNOWN бронь остаётся, не происходит тайм-аутов/автоматического сброса блокировки.
- Функция `preserve_guarded_save` немедленно после успешного нативного SaveProject (внутри `SceneWriter` verify-after) создаёт новый файл `guarded-save.snapshot` с точными сохранёнными байтами, без перезаписи уже существующего файла. Хеширует обе копии и исходные PLN/модуль до и после копирования. В `guarded-snapshot.json` фиксируются SHA256, происхождение и запрет повтора.
- Только batch-адаптер `apa_ac29_hotlink_batch_oneshot.py` получил этот opt-in. **GuardedSaveTransport, общая библиотека APA, PR #171 и native API не переписаны**. Имеющиеся проверки исходной модели, SceneWriter/SQLite и SaveProject сохранены.
- Если позднее первоначальную scratch PLN изменит Archicad, защищённый snapshot останется отдельным. Новый `--stage-snapshot-reopen` подготовит вторую копию **точных сохранённых байтов** и отдельное состояние только для чтения: подлинные `manifest.json`, `plan.json`, `saved.json`, `attempted.json`, SQLite и их хеши сохраняются. Команда не выполняет нативных операций и не изменяет исходное состояние.
- Фазы `--confirm-open-snapshot` → фактический GUI close → `--check-closed` → фактический GUI reopen → `--verify-reopen` удостоверяют **два реальных открытия снимка**, разделённые доказанным `no open project`. Это отличается от попытки автоматически принять сохранение по одному хешу.

## Проверка после LIVE и безопасная процедура

Эта работа **пока не выполнялась на Windows**; команда ниже — инструкция для следующего отдельного локального теста **на новой тестовой копии**, а не утверждение о результате.

1. Выбрать новую отдельную тестовую PLN с существующим Hotlink, отдельный source-module, свободный порт AC29. Не изменять пользовательские PLN/APX, штатный main и уже принятую LIVE-02.
2. Выполнить существующие `--stage`, `--plan`, `--execute` согласно PR №173 с одобренными тестовыми координатами и количеством. В `--execute` новая бронь и точный snapshot возникнут автоматически при подтверждённом SaveProject.
3. Сверить наличие `state/guarded-save.snapshot` и `state/guarded-snapshot.json`, статус `BYTE_EXACT_GUARDED_SAVE_SNAPSHOT_CAPTURED` и SHA с `saved.json`. Ни одного дополнительного SaveProject ради снимка **не требуется**.
4. Для стандартного пути без внешнего изменения пройти прежние GUI close → `--check-closed` → GUI reopen → `--verify-reopen`; отдельно сохранить созданный snapshot.
5. Если исходная scratch изменена сторонним процессом, **не откатывать и не переписывать её**, не переписывать SQLite, не выполнять batch второй раз. Создать новые пути:
   
       python scripts/apa_ac29_hotlink_batch_oneshot.py --stage-snapshot-reopen --state-dir "ИСКОННЫЙ_КАТАЛОГ_КВИТАНЦИЙ" --snapshot-pln "НОВАЯ_КОПИЯ_СОХРАНЕНИЯ.pln" --snapshot-state "НОВАЯ_ПАПКА_КВИТАНЦИЙ" --reopen-port 19727

6. Открыть **новую** копию снимка в выделенном Archicad 29, затем выполнить:

       python scripts/apa_ac29_hotlink_batch_oneshot.py --confirm-open-snapshot --state-dir "НОВАЯ_ПАПКА_КВИТАНЦИЙ"

   После успешного независимого чтения закрыть только эту копию **без нового сохранения**, затем:

       python scripts/apa_ac29_hotlink_batch_oneshot.py --check-closed --state-dir "НОВАЯ_ПАПКА_КВИТАНЦИЙ"

7. Повторно открыть ту же копию с диска, затем:

       python scripts/apa_ac29_hotlink_batch_oneshot.py --verify-reopen --state-dir "НОВАЯ_ПАПКА_КВИТАНЦИЙ"

   Приёмка требует точных GUID, BREP, связей, трансформаций, SHA и цепочки происхождения. Это **проверка сохранённого снимка**, а не утверждение, что поздняя изменённая scratch принята.

## Границы защиты

**Блокировка согласованная (cooperative)** — она останавливает только другие задания APA, которые используют `ScratchWriteLease`. Обычный Archicad, внешние приложения и ручная перезапись не обязаны её учитывать. Нельзя выдавать эту реализацию за системную Win32-блокировку, эксклюзивный доступ к PLN или гарантию отсутствия внешней записи. Фактический дефект LIVE-02 устраняется практически за счёт **немедленной побайтовой фиксации** оригинального GuardedSave и строгой последующей сверки с SHA.

Любое несоответствие исходных SHA, неожиданная запись во время snapshot-copy, существующий путь назначения, дубликат состояния или разрыв цепочки квитанций → STOP/UNKNOWN, запрет повторной нативной вставки. Снимки и журналы не стирать.
