# Прямое подключение APA к ChatGPT

APA использует уже закреплённый MCP SDK 2.3.0. Доступ через ChatGPT идёт по Secure MCP Tunnel. Для постоянного подключения запускайте APA в пользовательском сеансе Windows командой `Start-APA.cmd --mcp-profile <профиль>`. HTTP слушает только `127.0.0.1:18787/mcp`. Отдельный клиент OpenAI устанавливает исходящее соединение и передаёт запросы к этому адресу. Для локального клиента доступен также stdio через `apa mcp-control --profile <профиль>`. [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)

## Инструменты

- `apa_read` возвращает SHA манифеста, ревизию, перечень разрешённых целей, состояние задания и страницы его квитанций по ID. Доступные квитанции — план, инвентарь модели и вывод конкретной команды. Каждый файл сверяется с SHA из результата.
- `apa_execute` принимает типизированные действия `doctor`, `plan`, `native-read`, `preflight`, `write`, `check-closed` и `verify-reopen`. Клиент назначает новый `job_id` до вызова. Длительная операция возвращает ID и `QUEUED`, затем `apa_read` выдаёт квитанцию с кодом выхода, фазой и результатом. Повтор той же операции с тем же ID читает её прежнее состояние.
- `plan` принимает Semantic Brief или проект с вариантами. Модель, окна, запуск Windows-программ и файловые пути задаются локальным оператором. Профиль фиксирует манифест выпуска и подготовленные цели по SHA. На стороне ChatGPT приложение добавляется как частный сервер, связанный с нужным workspace. [Добавление пользовательского MCP](https://developers.openai.com/api/docs/guides/custom-mcp-server)

## Допуск к записи

Передайте `preflight` для конкретного имени цели. Оператор проверяет `approved-preflight.json`, план, PID/порт, SHA копии и границы изменения. Затем он локально оформляет разрешение для будущего ID вызова `write`.

```powershell
$Approval = (Get-FileHash -Algorithm SHA256 -LiteralPath $ApprovedPreflight).Hash.ToLowerInvariant()
& $Py -I -B -X utf8 $ApaScript mcp-control --profile $Profile --grant $WriteId $Target $Approval
```

Сохранение проходит через действующие SceneWriter, SQLite, APX и общий lock приёмника. Процесс, который вызывает нативную команду, удерживает lock до завершения. Повторное подключение и повтор вызова читают уже существующую квитанцию. После тайм-аута или прерывания с неизвестным нативным результатом сохраните рабочую копию и журналы. Следующий безопасный шаг — чтение и сверка. Для модального окна диагностический маршрут останавливается и сохраняет PID и сведения об окне.

Режим обслуживания Windows остаётся отдельной локальной операцией. Доступ к сетевому приложению и ключу клиента определяется правами Platform и workspace. Мост передаёт разрешённые данные в обычный ChatGPT только после создания и установки частного подключения.
