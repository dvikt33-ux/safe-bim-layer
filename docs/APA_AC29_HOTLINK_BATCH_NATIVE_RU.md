## Найденная проблема координат

Первоначальный Hotlink был установлен с origin.x=346.475 м, а мировой BREP его импортированных элементов начинается при xMin=646.474975586 м. Это означает, что геометрия исходного модуля сама имеет локальный минимум x≈300 м. Фактический зазор составил 315.999975586 м, а не задуманные 10 м. Из этих величин следует максимальный X исходной сцены ≈330.475 м.

При нулевом повороте и отсутствии зеркальности:

- world BREP = module local BREP + native Hotlink origin;
- requested origin.x = maximum occupied world X + gap − module local minimum X;
- проверка на исходном примере: 330.475+10−300=**40.475 м**, новый мировой минимум 340.475 м, зазор **10 м**.

Новая функция автоматически измеряет локальные BREP-границы **из уже размещённого экземпляра**: запрашивает его настоящий корень, нативный node GUID и импортированные дочерние элементы с hotlinkId, читает BREP, вычитает подтверждённый origin. Она не делает предположений о том, что исходный модуль начинается с нуля.

**Ограничения V1:** этаж 0, нулевые rotationAngle, mirrored=false, source floorDifference=0, ось тиражирования +X, зазор 0.1–100 м, число новых экземпляров 1–32 за операцию. Параметры skipNested, suspendFixAngle, ignoreTopFloorLinks, relinkWallOpenings и adjustLevelDiffs читаются из существующего нативного экземпляра и **копируются во все N новых**; их readback проверяется повторно. Изменение любого из этих признаков блокирует приёмку. Сложные уровни этажей, наклонные/зеркальные модули и неоднозначная геометрия блокируются. Перед каждым LIVE-вызовом проверяется отсутствие пересечений AABB с существующей 3D-геометрией.

## Что подключено в коде

- `scripts/apa_ac29_hotlink_batch_geometry.py`: независимый READ_ONLY расчёт по реальным BREP, воспроизведение опубликованной ошибки 316 м и корректный X-gap.
- `scripts/apa_ac29_hotlink_batch_verifier.py`: кодовый NativeVerifier для ровно **одной** `CreateHotlinkInstances` с N записями в нативном массиве. Проверка ответов, N новых корней, N×M новых дочерних элементов, принадлежности каждого `hotlinkId`, структуры типов, трансформации и мировой BREP.
- `scripts/apa_ac29_hotlink_batch_oneshot.py`: read-only native plan, новая PLN-копия, штатный `DynamicCommands → BIM Graph → SceneWriter/SQLite`, 1 батчевая CREATE-запись, 1 `GuardedSaveTransport` и независимая проверка после **фактического** закрытия и повторного открытия.
- 2 набора прицельных unit/contract-тестов в Windows Python 3.11/3.12, не повторяющие старые 37 тестов без изменения общего кода.

Нового APX и новой команды Tapir не требуется. Идентификатор уже созданного узла переиспользуется; новых узлов не создаётся. В main и исходные пользовательские PLN ничего не отправляется.

## Порядок локальной интеграции на Windows

Не запускать на пользовательском оригинале, BDD или в сессии с чужими несохранёнными изменениями.

1. Выбрать **сохранённую принятую тестовую PLN с одним уже размещённым Hotlink** (например, `hotlink-native-test.pln` из PR №171), подтверждённый неизменённый исходный модуль и **не существующий** путь новой копии PLN. Не переиспользовать директорию предыдущей попытки.

2. В ветке этого PR подготовить новую тестовую копию (пример GUID основан на принятой LIVE-квитанции, остальные пути заменяются на реальные локальные):

       python scripts/apa_ac29_hotlink_batch_oneshot.py --stage --source-pln "ПУТЬ_К_ПРИНЯТОЙ_ТЕСТОВОЙ_PLN" --module-pln "ПУТЬ_К_НЕИЗМЕННОМУ_МОДУЛЮ.pln" --scratch-pln "НОВАЯ_BATCH_КОПИЯ.pln" --state-dir "НОВЫЙ_КАТАЛОГ_КВИТАНЦИЙ" --node-guid e06d3a5b-9797-aff7-49e3-87741c205118 --prototype-guid 2a4d7d8f-06dc-4c79-97f1-34e7dc91b7ae --count 2 --gap 10 --port 19726

   Команда `--stage` только копирует сохранённый тестовый файл и фиксирует SHA256 обоих источников, нативных записей нет.

3. В отдельном AC29 build 5101/Tapir 1.5.10 вручную открыть **именно новую копию** на нужном порту (не закрывая несохранённые другие проекты). Затем:

       python scripts/apa_ac29_hotlink_batch_oneshot.py --plan --state-dir "НОВЫЙ_КАТАЛОГ_КВИТАНЦИЙ"

   Этот шаг делает только native READ: извлекает source-local/world BREP и вычисляет точки для N экземпляров. В `plan.json` записываются хеш набора GUID, нативной геометрии, контракта и точные координаты. Проверить ожидаемые мировые границы и 10-метровый зазор.

4. После подтверждения плана:

       python scripts/apa_ac29_hotlink_batch_oneshot.py --execute --state-dir "НОВЫЙ_КАТАЛОГ_КВИТАНЦИЙ"

   Перед нативной записью выполняется повторный read-only расчёт; несовпадение любого SHA/GUID/BREP/плана останавливает работу. Затем одна команда `CreateHotlinkInstances` создаёт два экземпляра одним массивом (для указанного примера), SceneWriter сохраняет SQLite-результат. Нативная проверка принимает только **полное** совпадение по корням, дочерним элементам, владельцам, типам и BREP. Только после этого отдельный `SaveProject`.

   При UNKNOWN, тайм-ауте, ошибке нативного ответа **никаких повторов** той же команды, ручного удаления строк SQLite или скрытого отката. Сначала независимая read-only-сверка состояния.

5. Закрыть **только эту копию** через GUI и убедиться, что AC29 действительно в состоянии «проект не открыт». Затем:

       python scripts/apa_ac29_hotlink_batch_oneshot.py --check-closed --state-dir "НОВЫЙ_КАТАЛОГ_КВИТАНЦИЙ"

   Программа должна получить отказ `GetProjectInfo` с кодом 4001 «no open project». Это обязательная отдельная квитанция. Нельзя считать ответ `CloseProject:success` доказательством закрытия: ранее он оказался ложноположительным.

6. Открыть сохранённую копию заново через интерфейс Archicad; затем:

       python scripts/apa_ac29_hotlink_batch_oneshot.py --verify-reopen --state-dir "НОВЫЙ_КАТАЛОГ_КВИТАНЦИЙ"

   Итоговый PASS требует полного восстановления GUID/BREP, нового N×M-поддерева, точных трансформаций, исходного неизменного хеша модуля и оригинала, и `LIVE_NATIVE_HOTLINK_BATCH_SAVED_REOPENED_PASS`.

## Критерий ГОТОВО и публикация

- CI нового source-пакета на Python 3.11/3.12 зелёный на точном SHA; отдельный draft PR, без merge в main.
- В реальном AC29 один и только один native `CreateHotlinkInstances` с N≥2; не создавать второй node.
- Каждый из N корней и его M потомков подтверждён, исходные BREP без изменений, геометрические зазоры в пределах допуска.
- Один `SaveProject`, фактический GUI close/read-only подтверждение и повторное открытие.
- Опубликована обезличенная машинная квитанция, исходные файлы по SHA неизменны; SQLite и исходные raw-логи сохранены локально.

LIVE-02 завершён для конкретных двух экземпляров и проверенного файла из указанной квитанции. После GuardedSave при параллельной работе изменился первоначальный рабочий PLN; защита SHA остановила его приёмку. Поздний файл сохранён отдельно. Принят его BPN-снимок, побайтово совпадающий с исходной квитанцией единственного GuardedSave, после отдельного реального close/check-closed/reopen на 19727. Нативных повторов или дополнительных SaveProject не было. Это не приёмка произвольного N, других проектов или иных функций APA.
