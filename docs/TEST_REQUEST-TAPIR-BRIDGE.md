# Независимая нативная проверка моста Tapir

Проверить сборку из контрольной точки интеграции. Программные тесты использовали имитацию ответов Archicad и реальные опубликованные схемы Tapir.

## 1. Два экземпляра и две копии PLN

1. Распакуйте Windows-комплект отдельно. Запустите `Start-APA.cmd` для установки комплектных зависимостей.
2. Для AC29 + Tapir 1.5.10 и AC30 + Tapir 2.0.0 откройте по отдельной разрешённой копии PLN. Зафиксируйте порты этих экземпляров. Для каждой копии подготовьте отдельный побайтовый резервный PLN и профиль `APA_TAPIR_READ_PROFILE_V1` по руководству. Сверьте SHA-256 тестовой модели, резерва и APX. [Руководство профиля](APA-TAPIR-BRIDGE.md)
3. Для каждого профиля выполните команды из каталога `APA-Windows`. Сохраните stdout каждого шага и журналы `*-tapir-evidence`. Сверьте фактический путь, продукт, сборку, версию Tapir и SHA-256 загруженного каталога. Ожидается 262 описанных контракта у 1.5.10 и 789 у 2.0.0.

```powershell
$apa = '.\.apa-runtime\Scripts\python.exe'
& $apa -m apa tapir status --profile $profile
& $apa -m apa tapir catalog --profile $profile --command GetStories --probe
& $apa -m apa tapir read --profile $profile --command GetStories
& $apa -m apa tapir read --profile $profile --command GetSelectedElements
& $apa -m apa tapir read --profile $profile --command GetElementsByType --parameters $wallParams
```

`$wallParams` указывает на локальный JSON `{"elementType":"Wall"}`. Выполните те же чтения через единый MCP `apa_tapir`, запущенный командой `python -m apa mcp-control --profile <профиль>`. Ожидаются `runtimeRegistered=true`, `TAPIR_READ_VERIFIED`, параметры, хеш контракта и возвращённые данные. Сравните этажи с настройками этажей открытой модели, GUID выбранных элементов с выборкой в тестовой модели, тип и GUID стен с нативным списком. Для AC30 также выполните `GetSuspendGroupsMode` и сравните значение с настройкой Archicad.

## 2. Расширение и отказ

1. Скопируйте список проверенных чтений выпуска Tapir 2.0.0 и добавьте `"GetArchicadLocation":"archicad-addon/Sources/ApplicationCommands.cpp"` после просмотра реализации в исходном коммите. Выполните `tapir import-catalog` с неизменным коммитом `bb71abf12f37273f47a9ea0f3daeabae0578225d`. Сохраните новый файл каталога и его SHA-256. В отдельном профиле этого же PLN укажите оба поля каталога. Перезапустите тот же MCP. Вызов `apa_tapir` с `operation=read` и `command=GetArchicadLocation` должен пройти. В составе MCP по-прежнему один универсальный инструмент чтения.
2. Через `tapir read` проверьте вымышленное имя, `SaveProject`, `CreateWalls` и `GetElementsByType` без параметров. Ожидается отказ до отправки выбранной команды. Для команды с `runtimeRegistered=false` ожидается отказ после проверки регистрации. Сверьте `dispatch.jsonl`. В нём остаются диагностические запросы о среде и регистрации.
3. Для проверок несовпадения используйте копии профиля с неверным ожидаемым номером версии, хешем каталога или тестовым путём. Для неправильного пути оставьте открытым исходный тестовый PLN, а в копии профиля укажите третью побайтовую копию в поле `project`. Пути `project` и `backup` должны оставаться разными. Ожидается `BLOCKED` и отсутствие целевой команды в `dispatch.jsonl`.
4. Сверьте SHA-256 обоих тестовых PLN, резервов и APX после чтения. При сбое передайте квитанции и журналы с точной причиной. Состояние защищённого проекта сверяется до какого-либо повторного запуска.

## 3. Сохранённые сценарии

1. На AC30 запустите совместимый `ac30-mcp --profile <профиль> --elements <список>`. В списке 2–12 известных GUID стен, плит или крыш с типами. Выполните `apa_ac30_read(status)` и `apa_ac30_read(quantities)`. Сверьте группы по типам, равенство пакетного и поэлементного результата либо диагностируемый переход на подтверждённый поэлементный результат.
2. На AC29 проверьте прежнюю кампанию SceneWriter из отдельной тестовой копии и прежнего профиля. Для записи используется только ранее утверждённый сценарий с локальной квитанцией допуска именно на эту операцию и модель. Зафиксируйте один исполненный job ID, нативное чтение GUID/BREP и состояние SQLite при повторной подаче того же ID. Если допуска к записи нет, завершите предконтроль и отрицательную проверку допуска.

Передайте фактические результаты по каждому экземпляру, ревизию поставки, SHA-256 профиля и каталога, перечень вызванных команд и квитанции. Для нативной записи нужны отдельные подтверждения сохранения и повторного открытия модели.
