# APA AC29 — сетка из 1–32 нативных групп: планирование и проверка

**Задание A-GRID-01.** Статус: SOURCE_IMPLEMENTED / OFFLINE_PASS / LIVE_NOT_RUN. Windows CI 3.11 и 3.12: по 33/33 PASS на каждой версии (8 новых + 13 SceneWriter + 12 исходного группового маршрутизатора), run 39163173305. Изменений локальных PLN/APX нет.
Основание: независимый LIVE/SQLite PASS для двух размещений в PR #164 и контракт CloneNativeGroupV1 в archicad-addon/Sources/NativeGroupCommands.inc.

## Цель и действительная архитектура

Поддержать 1–32 точных размещения существующей группы из двух стоек (по одному дочернему ColumnSegment), через ОДИН запрос к ранее установленной native-команде CloneNativeGroupV1, без разработки второго движка.

- Новый чистый планировщик scripts/apa_ac29_native_group_grid.py принимает явные columns, rows, stepX, stepY, startDx, startDy, все расстояния в метрах.
- Члены исходной группы уже должны иметь проверенные GUID, familySignature, этаж, sourceRef и прочитанное из нативного API членство. Никаких предполагаемых данных.
- Генерируется ровно существующий запрос apa-native-group-auto/1, который повторно проверяется GROUP.route и передаётся APA.prepare_auto_optimized_native_task. Результат имеет executionPermission=False; никакой записи при планировании.
- Исполнитель остаётся существующий DynamicCommands → BIM Graph → SQLite SceneWriter. В старом коде сохранены защиты от повторов, проверка BREP и независимый постконтроль.
- Расширенный VerifiedNativeGroupClone проверяет для N повторов ровно N групп, 2N стоек, 2N дочерних сегментов, всего 4N новых GUID и сохранность всех прежних.
- Допускаются горизонтальные смещения с dx или dy любой ненулевой направленности (dz=0) в пределах 10 000 м, при отсутствии совпадений. Занятость геометрии проверяет прежний полный BREP/AABB-анализ.

**Реальное ограничение C++:** максимум 32 положения и максимум 200 копируемых основных элементов. Внутри одного нативного запроса SDK выполняет 32 операции преобразования; ускорение по времени не доказано.

## Критерии ГОТОВО

1. Строгая сетка 8×4 выдаёт 32 смещения, 64 целевых стойки, одну native-команду в исходном APA BIM-графе, 0 полномочий на запись.
2. Без вызовов Archicad блокируются 33+ смещения, NaN/Inf, дубликаты и нулевые сдвиги, нарушение пределов, неподтверждённая исходная группа, иная история/неправильный тип.
3. Проверяющий модуль доказывает численность групп, стоек, дочерних сегментов и подлинность ответа для 1, 2, 32 повторов; неверное число GUID/чужая группа/неполная геометрия блокируются.
4. Предыдущий независимый LIVE PASS на 2 размещения остаётся без регрессий; проверки SceneWriter и Group.route проходят в Windows CI 3.11/3.12.
5. Отдельный одноразовый LIVE-тест 32 повторов требует новой разрешённой копии PLN и независимой SQLite-квитанции; никогда не переиспользовать исходное испытание #02.

**Приёмка сейчас:** только SOURCE и OFFLINE после CI. Не меняются BDD, main, оригинальный PLN, исходный APX или активный несохранённый scratch #02. Нет нового LIVE PASS и нет подтверждённого ускорения 100×.

## Образец плановой геометрии

8 колонок × 4 ряда; шаг 25 м по X, 8 м по Y; первая копия смещена на +25 м. Возникают 32 новых положения, 64 целевые основные стойки. Физическую свободную зону обязан независимо проверить BREP-префлайт.

Параметры: schema=APA_AC29_NATIVE_GROUP_GRID_V1; columns=8; rows=4; stepX=25; stepY=8; startDx=25; startDy=0.

Связанные PR: #164 — принятая двухпозиционная native операция и SQLite; настоящий PR — 1–32-позиционный планировщик и расширенная проверка на чтение.

**CI-вывод:** 8×4 → 32 native-группы и 64 основных стойки (ещё 64 дочерних сегмента, если фактическая native копия пройдёт); потенциальное увеличение общего счётчика GUID исходной 44-элементной модели до 172.
