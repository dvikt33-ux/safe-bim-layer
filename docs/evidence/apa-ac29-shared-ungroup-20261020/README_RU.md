# APA AC29: нативная разгруппировка подключена, установлена и принята

## Новая функция редактирования группы

`apa-native-group-ungroup/1` принимает конкретный Group GUID, полный состав участников и источник. Общий selector выбирает реальный существующий `UngroupNativeGroupV1`, проверяет регистрацию в текущем AC29 и выполняет его через тот же Router, registry `VerifiedNativeGroupUngroup` и SceneWriter/SQLite. Используется общий вызывающий сценарий групповых операций с отдельной авторизацией разгруппировки; нового исполнителя и APX нет.

Разрешено только освобождение членства плоской группы существующих Column. Все физические GUID, геометрия, материалы, принадлежащие сегменты и другие группы колонн должны сохраняться. Полный состав и корневая принадлежность читаются до записи. После операции все участники должны иметь нулевые group/rootGroup GUID, а все80 записей принадлежности сверяются с исходным состоянием с двумя явно разрешёнными изменениями. Физическое удаление элементов не разрешается.

## Установка и CI

Установлен код `9113a249e16dafaae78d9178b1234bf5097f9c7f`. С резервными копиями изменены существующие функции selector/runtime, registry и общий вызывающий сценарий; добавлены точный исходный контракт и адаптер разгруппировки. Все296 исходных контрактов,30 файловых и4semantic команды сохранены. Factory, пакеты зависимостей, APX и main не изменены. Команда подключается общим selector при соответствующем запросе.

Необходимые автоматические проверки нового адаптера и изменённого сценария прошли. Все9checks CI на исполнявшемся коде SUCCESS; точные ссылки в `ci-checks.json`. Старое ожидание registry расширено только конкретным проверенным command/effect. Регрессионные проверки остаются в CI; ранее принятые копирование, сетка8×4, конечная линия, оси и создание группы повторно не выполнялись.

Границы: плоские группы2..128 полностью прочитанных Column на этаже0, точная авторизация всех участников, неизменность физической модели. LIVE выполнен на группе из двух Column. Вложенные группы, другие типы элементов, перемещение группы и произвольная смена состава требуют следующих отдельных адаптеров. Булевое объединение тел этим не выполняется.

Доказательства: `receipt.json`, `independent-audit.json`, `deployment.json`, `ci-checks.json`, `artifact-sha256.json`. PLN/SQLite/полные дампы остаются локально.
