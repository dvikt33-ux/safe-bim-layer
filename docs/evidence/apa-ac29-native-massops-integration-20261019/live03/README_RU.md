# AC29: native группа → выбор команды → сетка 8×4 → save → реальный reopen

Дата: 19.10.2026. Источник задачи: PR #174, после принятого SAFE-01 в PR #178.

## Результат

**LIVE_NATIVE_GROUP_BATCH_SAVED_REOPENED_PASS**, затем независимый
**INDEPENDENT_NATIVE_SQLITE_SAVED_REOPENED_GROUP32_PASS**.

- Archicad 29 build 5101, Tapir 1.5.10; точный SDK runtime указан в preflight.json.
- Использована существующая изолированная копия, подготовленная в #174.
  Её исходная stage-квитанция и байты подтверждены до записи. Оригинальный PLN сохранён.
- Запрос `apa-native-mass-request/1` с явной сеткой 8×4, шагами 25×8 м,
  первым смещением (25,0,0) прошёл существующие APA Router → group selector →
  BIM Graph → Dynamic Mutation Scope → исходный SQLite SceneWriter.
- Выбрана **одна** `AddOn.TapirCommand.CloneNativeGroupV1`, не отдельные Create.
- 32 новые группы; 64 новые Column и 64 принадлежащих им ColumnSegment.
  Инвентарь: **44 → 172 GUID**. Каждый GUID и состав каждой группы опубликован.
- Исходная группа `40d5303f-18ca-4117-9de0-e06bfd8e64b9` и все 44 исходных GUID
  сохранились. Независимо совпали геометрия, привязки и полные материалы граней
  всех исходных элементов, включая элементы вне копируемой группы.
- Один native Clone (0.3005511 с) и один Save (2.5871763 с).
  Это длительности отдельных native-вызовов, не всего процесса испытания.
- Синхронный snapshot, реальное GUI-закрытие без второго Save, native 4001
  `no open project`, реальное GUI-открытие, повторная сверка всех 172 GUID/BREP,
  полного состава групп, атрибутов и материалов. Дополнительных model writes нет.
- В исходном SQLite две сцены и два шага PASS, quick_check=ok.

## Найденные и закрытые дефекты

1. Пинованный JSON-план возвращал списки вместо Python-кортежей. Сравнение теперь
   использует полное каноническое JSON-представление, без исключения полей.
2. Аналогичная проблема в независимой проверке сохранённого sourceProof.
3. После reopen dump-local номера пула материалов изменились. Верификатор
   разрешает их через **пул того же native dump** в полные записи материалов.
   Сохраняются GUID/индексы атрибутов, цвет, прозрачность, текстура и прочие поля;
   исключаются только `id` и `modelMaterialIndex` самого пула. Неизвестная ссылка
   блокирует приёмку. Старый proof восстанавливает свой pool из pre-clone dump,
   подтверждённого по точному source solid и полному 44-GUID BREP.
4. При выделении save-only функции выявлена отсутствовавшая локальная привязка
   исходного SceneWriter. Ошибка произошла до Save; исправлена и покрыта тестом.

Испытание содержало остановки. Клонирование **не повторялось**: уже PASS-сцена
была независимо сверена чтением, после чего выполнено отдельное единственное
сохранение. failed/attempted/lease не удалялись. Остановка NameError до Save
разрешена явным продолжением только после доказательства нулевого Save в trace
и SQLite. Публикуются hashes исходных квитанций и описание продолжения.
Это не доказательство непрерывного нового прогона `execute()` без остановок.

## Тесты и границы приёмки

- Windows Python 3.11: **121/121** целевых контрактных/регрессионных тестов PASS.
  Это офлайн тесты. LIVE-приёмка приведена отдельно выше.
- Статус GitHub Actions сообщается отдельно: локальный PASS не заменяет CI PASS.
- Подтверждён существующий native group из двух полных одноcегментных Column
  на этаже 0 и горизонтальное тиражирование 1..32 размещения; LIVE выполнено 32.
- Другие составы групп, создание новой группы, булево объединение, создание
  объектов осей и массовые изменения пользовательских рабочих PLN не приняты.
- LINEAR/TRANSLATIONS/AXIS_INTERSECTIONS поддержаны контрактом selector и тестами;
  этот LIVE доказывает GRID 8×4. Размеры/материалы из свободного текста не придуманы.
- Обновление установленного APA ещё не входит в эту квитанцию: проверен код
  интеграционной feature-ветки, использующий существующий Router/SceneWriter.
  Установленные 30 read-only sidecar и 4 semantic bridge не переустанавливались.
- Основная ветка и исходные APX/PLN не изменялись, merge не выполнялся.
