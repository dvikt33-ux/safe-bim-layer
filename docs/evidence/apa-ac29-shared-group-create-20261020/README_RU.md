# APA AC29: создание нативной группы через общую цепочку

## Новая работающая возможность

Запрос «сгруппировать эти колонны» с точными GUID и ссылкой на источник проходит общий `prepare_auto_optimized_native_task`, проверку текущего runtime, существующий Router, registry `VerifiedNativeGroupCreate`, SceneWriter и SQLite. Выбирается существующий SDK `CreateNativeGroupV1`; APX не меняется. Создание членства группы разрешено как MODIFY двух существующих физических участников. Право изменять их геометрию этим не предоставляется.

Проверяются действительные несгруппированные Column на исходном этаже, их параметры, принадлежащие ColumnSegment, полный BREP/материалы и членство остальных групп колонн. Состав новой группы подтверждается независимо через `GetNativeGroupMembersV1` и `GetNativeGroupRootsV1`. Вся физическая модель должна сохранить GUID и полную семантическую сигнатуру.

## Установка и CI

Функция фактически установлена в действующий APA из `51acd9db7f0a8da4cb5d22f01722abd5ae79f248`: изменены два существующих тела selector/runtime entrypoint и функция registry, добавлены адаптер, вызывающий сценарий и точный контракт. Прочий код ядра сохранён. Резервные копии сохранены локально. Все296 исходных контрактов,30 файловых и4semantic команды сохранены. Новый контракт подключается существующим selector по запросу группы; подготовленный каталог299, исходный общий factory298 сохранён.

Новые автоматические проверки покрывают выбор команды/точную MODIFY scope, readback состава, сохранность других групп и материалов, несоответствие ответа, уже сгруппированные элементы, защиту источников и no-replay. Регрессии выполняются CI. На `bcf56fb3` исправлено устаревшее ожидание состава registry: добавлена только конкретная новая пара command/effect; механизм проверки не ослаблен. Точный итог CI приведён в `ci-checks.json`.

Границы принятого контракта:2..128 существующих несгруппированных Column на этаже0 с полностью прочитанной геометрией и сегментами. LIVE приёмка выполнена на двух Column. Нельзя выдавать это за приёмку произвольных типов, вложенного перегруппирования, перемещения/разгруппирования или булевого объединения тел. Эти возможности подключаются следующими отдельными функциями через тот же Router/registry.

Это одна приёмка новой функции. Принятые ранее сетка8×4, индивидуальный LINEAR, конечная линия и выбранные оси не повторялись. Исходные PLN/APX/main сохраняются; merge не выполнялся.

Доказательства: `receipt.json`, `independent-audit.json`, `deployment.json`, `ci-checks.json`, `artifact-sha256.json`. Полные дампы, SQLite и PLN остаются локально. Реестр: `APA-P70.A11.S17`.
