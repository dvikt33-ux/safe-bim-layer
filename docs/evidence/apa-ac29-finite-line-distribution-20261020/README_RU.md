# APA AC29: распределение по конечной линии — установлено и принято

## Новая работающая возможность

`LINE_SEGMENT` принимает явные координаты начала и конца отрезка, число новых позиций и подтверждённую точку отсчёта прототипа. Размещает копии равномерно, включая оба конца. Поддерживает диагональное направление, обратное направление и дробный шаг; сохраняет исходный элемент. Никакие размеры или число экземпляров из текста не придумываются.

Включено в существующий `prepare_auto_optimized_native_task`: запрос → распознавание намерения → mass selector → capability discovery → один `MoveElements(copy=true)` → существующий registry `VerifiedNativeBatchCopy` → SceneWriter/SQLite → readback → GuardedSave/снимок → переоткрытие. Для существующей принятой группы selector выбирает `CloneNativeGroupV1`; LIVE этого нового режима для групп не заявлен. Нового Router, исполнителя и зависимостей нет.

## Установка и автоматическая регрессия

Установлены два изменённых Python модуля существующего APA, с резервными копиями и сверкой точных прежних байтов. Все 296 прежних контрактов, 30 файловых и 4 semantic команды сохранены; совокупный каталог 298. APX/исходный PLN/main не изменялись. Новые проверки контракта входят в CI Windows Python3.11/3.12. Обе проверки CI на коде `3527254a` SUCCESS; точные ссылки в `ci-checks.json`.

Границы: горизонтальное размещение на исходном этаже, 2..200 новых позиций, обязательные конечные SI координаты. Нулевые, совпадающие, нечисловые позиции, чужая точка отсчёта и вертикальное размещение отклоняются. Проверки переноса на другие типы и создание нативных объектов осей этим результатом не подменяются.

## Выявленное изменение старой рабочей копии

Перед первой попыткой планирования новая функция остановилась без нативных вызовов: прежний рабочий `native-column-copy.pln` уже имел SHA `1202f31be224f34f79468ae35114866d1f76ab3c9be409cc7d016d51a11280cf` вместо принятого `f9f172004cb6abaed832445b9373083f39bc5deb71b2e3fd6ff601477663269f`. Причина этого изменения не установлена. Рабочий файл не восстанавливался и не использовался как доказанный источник. Его отдельный ранее принятый guarded snapshot сохранил точный SHA f9f172… и использован явным безопасным режимом как донор новой копии. Остановленный trial сохранён, повторов нативного копирования в нём нет.

Принятые ранее сетка групп8×4 и индивидуальный LINEAR пакет не повторялись. Это приёмка новой функции конечного диагонального отрезка. Защищённый исходник `3a74d7cb…`, принятый gridPLN `b6b44dc1…` и донорский снимок `f9f17200…` сохранены.
