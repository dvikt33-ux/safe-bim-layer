Запрос массового копирования проходит существующий selector → DynamicCommands/Router → registry `VerifiedNativeBatchCopy` → SceneWriter/SQLite → один `MoveElements(copy=true)` → точный readback → GuardedSave со снимком → проверку после реального закрытия/открытия PLN.

Принятый сценарий: распределение двух копий настоящей одиночной Column по линии с шагом 25 м. Это уже выполненная LIVE-приёмка; повторное испытание не требуется. Grid 8×4 групп принят отдельно в PR179 и также не повторяется.

## Безопасность и границы результата

Полностью сохранены геометрия, материалы граней и связи всех 172 исходных GUID, все 32 принятые группы и 88 записей group roots. Исходный принятый PLN имеет SHA256 `b6b44dc1a811ec4e77864177f3cef57e701e1f63126c16bc64b6a5d82a89c478`; защищённый исходник — `3a74d7cb17e460378eacfa8f933aeae29a5ca39fbf2bc73633115c9fee728750`. Оба неизменны. SQLite: обе сцены/шага PASS; quick_check ok. GUID, владельцы сегментов, BREP, расположение и материалы сверены после переоткрытия.

Первый trial остановлен до нативной записи из-за того, что CREATE scope ошибочно трактовал GUID прототипа как изменяемый объект. Прототип теперь явно разрешён как сохранённая ссылка только для `MoveElements(copy=true)`. Исходные ограничения MODIFY и перемещения сохранены. Остановленный trial не перезапускался; 0 копирований/сохранений доказаны отдельно (`pre-native-trial01-stop.json`).

LIVE подтверждён для одиночной Column и указанного линейного пакета. Beam/Object предусмотрены узкими автоматическими контрактами, но их LIVE-приёмка здесь не заявляется: в использованной модели нет подходящего Beam, а Object имеют зависимости. Новые типы и новые операции принимаются отдельной содержательной операцией. Реальные PLN/полные дампы/SQLite в GitHub не загружены.
