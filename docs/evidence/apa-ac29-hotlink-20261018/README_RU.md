## Обнаруженная ошибка и продолжение без повторной записи

На исходном SHA команда создания узла вернула полный успешный ответ с новым GUID (`existing=false`), но `GetHotlinks` вернул пустое дерево. Проверка PR ошибочно ожидала, что неразмещённый узел уже находится в дереве размещённых узлов. SceneWriter сохранил `PARTIAL_OR_UNKNOWN_OUTCOME`, шаг — `UNKNOWN_OUTCOME`, и остановился. Этот факт сохранён в [экспорте SQLite](sqlite-journal.json).

Причина проверена в локальном исходнике Tapir: `GetHotlinksCommand::Execute` обходит `ACAPI_Hotlink_GetHotlinkNodeTree` от корневых размещённых узлов. Пример `archicad-addon/Examples/hotlink_instances.py` прямо использует GUID ответа создания для первого размещения, поскольку новый неразмещённый узел ещё отсутствует в дереве.

До продолжения независимо повторно прочитаны GUID/BREP и хеши всех трёх файлов: изменений не было. Реализовано узкое продолжение `--resume-unplaced-node`, привязанное к полному исходному native-ответу, хешу оригинальной SQLite-строки, точному проекту и неизменной модели. Защита существующего scope один раз дополнительно остановила подготовку **до dispatch** из-за отсутствующей квитанции исторической сверки. После её подключения отправлен только первый экземпляр исходного узла. Дополнительная проверка raw-журнала исправлена так, чтобы учитывать последующие read-only preflight-записи. Ни одна из этих остановок не привела к повтору узла или экземпляра.

После размещения `GetHotlinks` подтвердил тот же GUID и источник. 24 новых дочерних элемента указали `hotlinkId` созданного экземпляра. Сам экземпляр имеет нативный тип Hotlink, точный node GUID и заданную трансформацию. Затем выполнено единственное защищённое сохранение. Исходная UNKNOWN-строка **не переписана в PASS**: её подтверждает отдельная `node-reconciled.json`, отражённая в экспорте SQLite.

В исправленном обычном сценарии успешный ответ неразмещённого узла отмечается `HOTLINK_UNPLACED_NODE_RESPONSE_ONLY_PASS` с `independentReadbackVerified=false`. Полная приёмка узла откладывается до независимого чтения после первого размещения. Сохранение до этой проверки запрещено. В завершённой LIVE-сессии исходная команда узла была выполнена на начальном SHA, продолжение экземпляром и сохранение — после исправления; новые проверки нативного корня дополнительно выполнены read-only на повторно открытой модели. Полного второго создания узла на исправленном коде не выполнялось, чтобы сохранить требование одного узла и отсутствие replay.

## Реальное закрытие и открытие

Tapir `CloseProject` вернул success, но последующая проверка обнаружила прежний открытый проект. Формальный ответ не был принят за закрытие. Использовано меню **Файл → Закрыть проект**. В диалоге собственной тестовой копии выбрано «Не сохранять», чтобы проверить именно ранее сохранённые через GuardedSaveTransport байты. Дополнительного сохранения не было. После этого окно стало пустым, lock исчез, а API вернул код 4001 `Invalid program status (no open project)`.

Tapir `OpenProject` в состоянии без проекта также вернул код 4001. Файл повторно открыт штатным меню **Файл → Открыть → hotlink-native-test.pln**. `--verify-reopen` подтвердил итог в 19:57:33 UTC; последующая независимая read-only сверка исходных BREP, нативного корня, владельцев, зазора и хешей прошла в 20:01:53 UTC. Ошибки перехода проекта не затронули модель и не вызвали нативного replay.
