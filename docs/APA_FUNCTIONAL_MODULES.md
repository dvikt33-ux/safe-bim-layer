# APA functional module expansion

APA now prepares five additional native SDK query contracts and runs nine local analytical entries through the existing catalog, BIM Graph dependency bindings and main orchestrator. The current original Archicad runtime is unchanged. This package does not repeat the accepted Wall/Window scenario or start further native geometry tests.

## Working local modules

Six newly exposed analytical capabilities reuse installed NetworkX, Shapely, OR-Tools and IfcOpenShell: dependency impact/order, indexed polygon relations with holes, constrained integer assignment, IFC selection/property sets, IFC schema/EXPRESS validation, and IFC kernel geometry. Three existing APA utilities (NativeDump normalization, native BREP quantities, IFC exchange facts) gain catalog access and are not counted as new algorithms. An actual archived NativeDump and an existing Archicad IFC export were used; no new native model read/write or live acceptance is claimed. All nine entries produced schema-checked local results. The actual IFC passed schema validation; three selected walls yielded positive volumes and world-coordinate bounds. NetworkX detected a cycle without enumeration; Shapely preserved a hole and exact contact; CP-SAT returned the supplied constrained optimum. These facts do not prove normative or engineering suitability.

`native_command_router()` attaches the code-owned module manifest by default. `include_functional_modules=False` keeps a legacy isolated catalog when needed. Dependencies import only for the selected local operation. GPT searches unchanged Knowledge Graph summaries and requests only selected schemas. Explicit provider/domain distinguishes `local-python` analysis from `addon-json` native commands. Attachment is repeatable without duplicate entries and checks source/contract hashes; a catalog cannot import arbitrary code or reclassify an arbitrary native command as read-only. Existing SceneWriter/SQLite remain the only native mutation executor. Local diagnostics record input/result hashes and library versions without native intent or model writes.

The demonstrated common graph passes `NormalizeNativeDump.elements` directly into `NativeBodyQuantities.elements`; typed IFC selection also feeds geometry by result pointer. The existing graph compiler resolves dependencies and concrete result schemas. Native commands retain runtime probe, project identity, mutation scope, journal and UNKNOWN no-replay gates. A composed native/local plan does not grant native execution permission.

## SDK groups and reuse

Five thin read groups invoke the public Archicad29 SDK: tool defaults for twelve native types; polygon memo coordinates, contour ends and arcs; project working units; nested group roots; modern GDL library-part origin. Complex defaults expose native type/variation/story/layer headers only. Polygon memo is not resultant BREP, and missing complex memo serialization is explicit. No custom solid engine or stair/roof solver is added.

Existing DevKit `AddOnCommandTest.ProtectionInfoCommand` is registered with its original namespace/name in the same Tapir APX. Twelve existing candidate commands are retained in the full build. The duplicate DevKit column example is covered by existing `CreateColumns`. Twelve LibraryManagement examples remain source-only: their UI/implicit-selection/library/network side effects require explicit headless contracts; they are not copied into generic read dispatch. Current schema and existing source provenance are retained separately when upgrading the ProtectionInfo build contract.

Full Release APX compile/link passed with 280 Tapir registration expressions and one additional DevKit namespace handler. Build and source registration are not runtime registration. Binary identity/source stamping is checked separately before any future deployment. No experimental APX was installed and no PLN was changed. Five SDK adapters plus reused ProtectionInfo require a separately approved candidate registration test to obtain native CALLABLE/LIVE evidence.

## Coverage boundaries

377 prepared entries =368 native/official/source contracts +9 local analytical entries. Only337 native contracts belong to the previously verified current stack;31 native/source contracts require runtime support. This arithmetic never converts nine local functions into Archicad commands. Five new native schemas and six new analytical capabilities are functional deltas; three local utilities and twelve candidate commands are reuse, not new discoveries. The32 non-Tapir APX still have no independent documented JSON/MDCL contract. Their ledger maps supported subsets to public SDK/existing providers without claiming private vendor integration. Grid, profile, layer, selection, MEP, IFC and element information have partial alternatives; interactive schedule rows, RVT/Rhino/point cloud/energy/AI vendor contracts remain exact external gaps. Coverage JSON keeps all32 providers and all14 DevKit examples.

## Reproduce

Use the existing connected requirements and run `scripts/apa_functional_modules_smoke.py --native-dump input/native-dump.json --ifc input/model.ifc --output output/local-proof.json` on saved, authorized inputs. It performs no Archicad calls. Regenerate the manifest with `scripts/build_functional_module_manifest.py`. Build through existing `archicad-addon/Examples/build_model_dump.py` with an explicit compatible Tapir checkout and installed DevKit; the new overlay participates in existing registration/build identity. No second build controller, executor, indexer, knowledge engine or server is introduced.

Windows CI supplies full existing regressions; local checks cover only changed contracts and the actual saved-data scenario. A11.S03 remains PARTIAL. Next: a bounded approved runtime registration/read-only probe for the six built SDK/DevKit entries; preserve the existing deferred Roof Surface/Stair/MEP blockers, accepted model, normative/KG/search implementations, and A07 dependencies.
