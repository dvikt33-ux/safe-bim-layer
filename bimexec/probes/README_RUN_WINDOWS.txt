================================================================================
2. ЭТАП T0A — СТРОГО READ-ONLY
================================================================================
Ни одного mutating вызова. Только чтение. Безопасно на любом проекте,
но рекомендуется тот же MCP_TEST.pln.

Команда (одной строкой) — интерпретатор с пакетом archicad:
    "C:\Users\Admin\AppData\Roaming\uv\tools\archicad-mcp-server\Scripts\python.exe" probe_t0a.py --out capability_matrix.json --ports 19723,19724 --mcp-url http://127.0.0.1:8001/mcp --expect-project "C:\Users\Admin\Downloads\MCP_TEST.pln"

То же, если `python` уже указывает на нужное окружение:
    python probe_t0a.py --out capability_matrix.json --ports 19723,19724 --mcp-url http://127.0.0.1:8001/mcp --expect-project "C:\Users\Admin\Downloads\MCP_TEST.pln"

Пояснения к флагам:
    --out              куда записать capability matrix (JSON)
    --ports            кандидаты API-порта Archicad (перебор, read-only)
    --mcp-url          endpoint MCP (по инвентаризации: 8001)
    --expect-project   ожидаемый путь .pln; несовпадение = честное NO
                       (можно убрать, но тогда теряется проверка "тот ли проект")
    --backend-order    по умолчанию "tapir,mcp"; BIBIM в v1 не используется
    --port             точный порт, если перебор не нужен

Коды выхода:
    exit 0 — probe выполнен (это НЕ "go"; вердикт внутри отчёта/консоли)
    exit 2 — нет ни одного отвечающего бэкенда (fail closed: матрица пуста,
             ничего не считается подтверждённым)

Что забрать из T0A:
  * capability_matrix.json — целиком;
  * консольный вывод — целиком;
  * строку "element_id address (для T0B --element-id-address): ...";
  * блок "GUID candidates for T0B (стены):" — оттуда взять GUID стены для T0B.

================================================================================
3. ЭТАП T0B — КОНТРОЛИРУЕМЫЙ ROUND-TRIP МАРКЕРА (ПЕРВАЯ ЗАПИСЬ)
================================================================================
ЗАПУСКАТЬ ТОЛЬКО ПОСЛЕ РАЗРЕШЕНИЯ ПО РЕЗУЛЬТАТАМ T0A.

Геометрию НЕ создаёт. Пишет ТОЛЬКО значение свойства ОДНОГО элемента
с известным GUID и возвращает исходное значение.

ПРАВИЛО ДВУХ КЛЮЧЕЙ: запись выполняется ТОЛЬКО если переданы ОБА флага
    --allow-write  И  --i-understand-this-writes-to-archicad
Один флаг без второго — ошибка запуска (exit 1), запись НЕ выполняется.
Без обоих флагов — режим dry-run (только PRECHECK, без записи).

ОБЯЗАТЕЛЬНЫЕ флаги:
    --guid <GUID>                 GUID тестового элемента (из вывода T0A)
    --expect-project "<путь>"     тот же путь, что и в T0A

--------------------------------------------------------------------------------
3.1. Сначала PRECHECK без записи (рекомендуется):
--------------------------------------------------------------------------------
    python probe_t0b.py --guid <GUID> --expect-project "C:\PLN\MCP_TEST.pln" --carrier both --out t0b_receipt_dryrun.json --report t0b_report_dryrun.json --dry-run

Ожидаемо: "DRY-RUN OK: PRECHECK пройден, запись НЕ выполнялась." и exit 0.
Если здесь STOP — писать нельзя, сначала устранить причину.

--------------------------------------------------------------------------------
3.2. Носитель — user-defined property (РЕКОМЕНДУЕМЫЙ, основной прогон):
--------------------------------------------------------------------------------
    python probe_t0b.py --guid <GUID> --expect-project "C:\PLN\MCP_TEST.pln" --carrier property --out t0b_receipt_property.json --report t0b_report_property.json --allow-write --i-understand-this-writes-to-archicad

--------------------------------------------------------------------------------
3.3. Носитель — Element ID (второй прогон, тот же элемент):
--------------------------------------------------------------------------------
    python probe_t0b.py --guid <GUID> --expect-project "C:\PLN\MCP_TEST.pln" --carrier element_id --element-id-address General_ElementID --out t0b_receipt_eid.json --report t0b_report_eid.json --allow-write --i-understand-this-writes-to-archicad

Примечание по --element-id-address:
  * флаг необязателен; если его нет, probe перебирает 5 кандидатов адреса
    и берёт первый, который отдал непустое значение;
  * лучше передать явно то, что T0A написал в строке
    "element_id address (для T0B --element-id-address): ..."
    (например General_ElementID или builtin:General_ElementID);
  * ВАЖНО: Element ID — пользовательские данные. Probe сохраняет исходное
    значение и обязан вернуть его; но если оно вам дорого — прогоняйте
    только property-носитель.

--------------------------------------------------------------------------------
3.4. Оба носителя за один прогон:
--------------------------------------------------------------------------------
    python probe_t0b.py --guid <GUID> --expect-project "C:\PLN\MCP_TEST.pln" --carrier both --out t0b_receipt_both.json --report t0b_report_both.json --allow-write --i-understand-this-writes-to-archicad

--------------------------------------------------------------------------------
3.5. Последовательность шагов T0B (что именно проверяется):
--------------------------------------------------------------------------------
    PRECHECK       read-only: проект тот, GUID есть, details читаются,
                   в проекте нет наследия "BX:PROBE:"
    SAVED          исходное значение маркерного поля записано в receipt
    WRITTEN        записан BX:PROBE:<nonce>  (ОДНА попытка, повторов нет)
    READ_BACK      прочитано; строковое равенство (ловим "silent no-op")
    FIND_EXACT     поиск по точному маркеру → ровно один GUID == исходному
    FIND_PREFIX    поиск по префиксу BX:PROBE: → ровно один GUID == исходному
    RESTORED       записано исходное значение
    VERIFY_RESTORE прочитано; восстановление доказано
    FINAL_SWEEP    в проекте не осталось маркеров BX:PROBE:

Любой timeout, неоднозначный результат или "запись прошла, а read-back
не совпал" ⇒ UNKNOWN и немедленный STOP. ПОВТОРОВ НЕТ, по правилам BIMEXEC.

Коды выхода T0B:
    exit 0 — все шаги пройдены И восстановление доказано
    exit 1 — STOP (или не хватает одного из двух ключей записи)
    exit 2 — ошибка запуска/подключения

================================================================================
4. ФАЙЛЫ-АРТЕФАКТЫ (не удалять до разбора)
================================================================================
    capability_matrix.json     — результат T0A
    t0b_report_*.json          — результат T0B
    t0b_receipt_*.json         — receipt T0B. Если прогон упал, в нём ровно
                                 то значение маркера, которое надо удалить
                                 вручную (поле cleanup / value_to_remove).

ВНИМАНИЕ: receipt ДОЛЖЕН отсутствовать перед стартом. Если probe говорит
"receipt уже существует" — предыдущий прогон мог оставить маркер в модели:
проверьте поле cleanup, удалите маркер в Archicad, и только потом
переименуйте/удалите файл receipt и запускайте заново.
Файл *.lock рядом с receipt — признак живого прогона; не запускайте второй.

================================================================================
5. ЧТО ВЕРНУТЬ В РЕПОЗИТОРИЙ ПОСЛЕ T0A (до запуска T0B)
================================================================================
 1. capability_matrix.json целиком.
 2. Консольный вывод T0A целиком (включая блок GUID candidates).
 3. Код выхода T0A.
 4. Какой бэкенд фактически ответил (поле "backend" в capability_matrix.json).
 5. Живую версию Tapir add-on, если T0A её показал.

Критерий перехода к T0B (go/no-go) — см. T0_PLAN.md, раздел go/no-go:
  * project_identity = OK (проект тот, не Untitled, не Teamwork);
  * list_guids = OK;
  * wall_geometry_endpoints = OK (в ответе есть beg/endCoordinate);
  * хотя бы ОДИН носитель маркера читается (read_element_id или
    read_custom_property);
  * search_scan = OK (позитивный и негативный контроль пройдены).
Если что-то из этого NO — T0B не запускать, сначала разбираемся.

6. ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
================================================================================
"STOP: ни один бэкенд не отвечает" (T0A exit 2)
    — Archicad не запущен, или Tapir Add-On не загружен, или не установлен
      пакет `archicad`, или не тот порт. Проверьте Archicad, затем:
      python -c "import archicad; print(archicad.__file__)"
      и перебор портов: --ports 19723,19724,19725

"initialize failed: ... URLError ..." для MCP
    — MCP-сервер не поднят на 8001. T0A при этом продолжает работать на
      Tapir; MCP важен только как резервный источник capabilities.

"package 'archicad' is not installed"
    — Запускайте probe интерпретатором
      C:\Users\Admin\AppData\Roaming\uv\tools\archicad-mcp-server\Scripts\python.exe
      Проверка:
      "C:\Users\Admin\AppData\Roaming\uv\tools\archicad-mcp-server\Scripts\python.exe" -c "import archicad; print(archicad.__file__)"

"project_path != --expect-project"
    — открыт не тот файл. Откройте MCP_TEST.pln и повторите.

"в проекте уже есть элементы с префиксом BX:PROBE:"
    — наследие прерванного прогона. Удалите значения вручную в Archicad,
      затем запустите T0B заново (и удалите старый receipt).
